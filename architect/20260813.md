# 2026-08-13 Architecture Decisions

## 13:08 KST — SurvFace TPIR20 및 5-point FPIR 공통 후처리 v5

- 작성일: 2026-08-13 (KST)
- 상태: 구현됨, fixture 및 실제 EdgeFace/LFW PCA smoke 검증됨; SurvFace full v5 수치 검증은 미실행
- 이전 결정과의 관계: `architect/20260809.md`의 score 1회 계산·다중 operating point 적용과 완료 run 불변 원칙을 유지하면서, v4의 FPIR 10%/1% Rank-1 DIR 계약을 TPIR20 5-point v5 계약으로 보완한다. 기존 v4 파생 artifact는 덮어쓰지 않는다.

### 변경 배경

SurvFace 기존 연구와 직접 비교하려면 Rank-1 DIR만으로는 부족하고 `TPIR20@FPIR=10%`가 필요하다. 논문 해석을 위해서는 1%·5%·10%·20%·30% operating point, calibration threshold, held-out realized FPIR, Origin/압축/frozen/recalibrated 성능, Origin 대비 retention, threshold와 무관한 closed-set Rank-20 recall을 함께 보존해야 한다.

기존 retrieval ledger는 Top-20 identity와 score 목록을 계산했지만 compact summary는 Rank-1 correctness와 top-1 maximum score만 집계했다. `Top-20에 정답이 있음`과 `top-1 maximum score가 threshold를 통과함`을 결합하면 공식 TPIR20 의미와 달라질 수 있으므로 정답 identity 자체의 rank와 score를 명시적으로 계산해야 한다.

### 결정 내용

1. TPIR@rank-k는 mated probe의 정답 identity가 retained top-k에 존재하고, 그 정답 identity score가 calibration split에서 고정한 threshold 이상일 때만 성공으로 정의한다.
2. common paper contract의 `top_k`는 20으로 fail-closed 검증한다. compact summary에는 generic rank-k 필드와 명시적인 `origin_tpir20`, `compressed_tpir20` 별칭을 함께 기록한다.
3. operating point는 `(0.01, 0.05, 0.10, 0.20, 0.30)`으로 고정하고 동일 profile/search score를 재사용해 threshold만 다르게 적용한다.
4. Origin, compressed frozen-origin threshold, compressed recalibrated threshold를 long-form policy 행으로 보존한다. PQ ADC는 cosine과 score space가 다르므로 기존 결정대로 frozen-origin threshold를 금지하고 recalibrated 행만 허용한다.
5. retention은 `compressed_tpir20 / origin_tpir20`으로 정의한다. Origin TPIR20이 0이면 retention은 정의하지 않고 결측값으로 둔다.
6. 기존 `search_space_v4_multi_fpir`를 변경하거나 덮어쓰지 않는다. 새 파생 artifact는 `search_space_v5_tpir20_multi_fpir`, schema 5, artifact type `step4_search_space_tpir20_multi_fpir_v5`로 발행한다.
7. 공통 report는 `survface_tpir20_comparison.csv`와 `tpir20_method_comparison.csv`를 추가하고, 각 행에 threshold, realized FPIR, TPIR20, retention, closed-set Rank-20 recall, test target 충족 여부를 기록한다.
8. RFW-Official 1:1 verification은 TPIR20 1:N 표와 결합하지 않는다. RFW-Custom은 비공식 1:N supplementary 경계를 유지한다.

### 현재 구현과 목표 구조의 차이

- 구현됨: true-identity rank/score ledger, threshold별 TPIR 판정, Wilson CI, paired probe bootstrap delta CI, retention, closed-set Rank-20 recall, 5-point v5 producer, batch 전달, report/matrix fail-closed 검증과 논문용 3-stage 표.
- 검증됨: synthetic fixture에서 top-1 maximum은 threshold를 통과하지만 rank-2 true-identity score는 통과하지 않는 경우 TPIR 실패로 처리됨. 실제 EdgeFace/LFW completed run의 PCA 5개 profile에서 100개 v5 compact 행과 5-point target coverage가 생성됨.
- 검증 필요: SurvFace full completed run의 PCA/PQ 전체 v5 후처리 수치, 기존 SurvFace 공식 MATLAB/Euclidean 결과와 common cosine 결과의 protocol 일치성, SOTA 표에 넣을 최종 수치.

### 데이터·모듈 흐름

```text
immutable completed Step 4 run
  -> calibration/evaluation top-20 search once per profile and search mode
  -> query true identity rank + true identity score within top 20
  -> calibration non-mated maximum-score thresholds at 1/5/10/20/30% FPIR
  -> Origin / frozen compressed / recalibrated compressed TPIR20
  -> realized FPIR + Wilson CI + paired TPIR delta CI + retention
  -> search_space_v5_tpir20_multi_fpir compact artifact
  -> cross-dataset Origin/frozen/recalibrated paper tables
```

### 검증 기준

- 모든 common compact 행에서 `top_k=tpir_rank=20`이다.
- target FPIR 집합이 정확히 `{0.01, 0.05, 0.10, 0.20, 0.30}`이다.
- `TPIR20 count / mated denominator == TPIR20 rate`이고 rate가 Wilson 구간 안에 있다.
- compressed-minus-origin TPIR20이 두 rate 차이와 일치하고 paired-bootstrap 구간이 뒤집히지 않는다.
- Origin TPIR20이 양수인 행에서 retention이 compressed/origin 비율과 일치한다.
- PQ ADC에 frozen-origin threshold 행이 없다.
- notebook JSON과 모든 code cell이 restartable/output-free 상태로 컴파일된다.
- 완료 source run과 기존 v4 artifact의 bytes/SHA-256은 변경하지 않는다.

### 미해결 위험과 주장 제한

- common pipeline의 score는 cosine 또는 PQ ADC adaptation이다. 기존 SurvFace 논문의 공식 MATLAB/Euclidean 수치와 동일한 protocol 재현인지 별도 검증하기 전에는 같은 열의 절대 SOTA 비교값으로 단정하지 않는다.
- calibration target을 만족해도 held-out realized FPIR가 목표를 초과할 수 있다. 해당 operating point의 threshold-dependent 주장은 `target_met_on_test`와 calibration-transfer 상태를 함께 보고한다.
- CI는 probe-level 불확실성만 반영하며 identity cluster와 checkpoint training 불확실성을 포함하지 않는다.
- 실제 SurvFace full PCA/PQ v5 후처리는 아직 실행하지 않았으므로 논문 수치가 개선됐다고 주장하지 않는다.
