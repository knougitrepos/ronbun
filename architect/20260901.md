# 2026-09-01 Architecture 변경 기록

## 19:23 KST — 4모델 보고서 matrix의 model UID 기반 run 자동 선택

- 작성일: 2026-09-01 (KST)
- 상태: 구현됨; 자동 선택 단위 검증 및 실제 run 선택 검증됨, 실제 4×3 통합은 SDC 계약 불일치로 미검증
- 이전 결정과의 관계: `architect/20260830.md`의 단일 model UID campaign 자동 선택을 4모델 matrix 입력 편의로 확장한다. `architect/20260809.md`의 strict 12-run loader와 fail-closed 과학 계약은 유지한다.

### 변경 배경과 결정

- 기존 `MODEL_RUN_MATRIX`는 ArcFace·AdaFace·MagFace·EdgeFace 각각의 LFW·SurvFace·RFW-Custom run directory 12개를 사용자가 직접 찾아 입력해야 했다.
- 직접 실행 설정에 `MODEL_RUN_MATRIX_MODEL_UIDS`를 추가한다. 사용자는 네 model family별 checkpoint UID만 지정한다.
- 각 UID는 기존 `select_model_uid_report_cohort`를 통해 최신의 완전하고 내부적으로 동질적인 3-dataset campaign으로 해석한다. 데이터셋별 최신 run을 독립적으로 혼합하지 않는다.
- 자동 선택 결과도 기존 `load_cross_model_open_set_matrix`에 명시적 12경로로 전달해 COMPLETED, lineage, SHA-256, FPIR/CI/search-mode 계약을 그대로 검증한다.
- 기존 `MODEL_RUN_MATRIX` 수동 경로 방식은 override로 유지하되 UID 자동 선택과 동시에 설정하면 모호성을 막기 위해 실패한다.
- selection manifest에는 요청 UID와 해석된 campaign, `model_uid_complete_campaign_auto_selection` 선택 방식을 기록한다.

### 데이터·모듈 흐름과 영향 범위

```text
4 model UIDs
  -> completed Step 4 candidate inventory
  -> model별 complete homogeneous campaign 선택
  -> 4 models x 3 datasets 명시적 run 경로표
  -> 기존 strict cross-model matrix loader
  -> validation-only 또는 four_model_three_dataset artifact
```

- canonical selector: `research/evaluation/report_selection.py`
- public API: `research/evaluation/__init__.py`
- notebook UI: `notebooks/common/reports/00_cross_dataset_results.ipynb`
- regression tests: `tests/research/test_report_selection.py`, `tests/research/test_notebook_layout.py`, `tests/research/test_cross_model_matrix.py`
- completed run, 기존 result artifact, DB와 embedding은 수정하지 않는다.

### 검증 결과와 재실행 범위

- model UID matrix 선택기의 정상 12칸 구성, 누락 family, UID prefix 불일치 회귀 테스트를 추가했다.
- 자동 선택기는 현재 저장소에서 ArcFace `20260829-R001`, AdaFace `20260830-R001`, MagFace `20260831-R001`, EdgeFace `20260901-R001`의 총 12개 completed run을 정확히 선택했다.
- compact CSV의 `%.12g` 직렬화에서 발생 가능한 TPIR20 delta 왕복오차를 producer와 동일한 `2e-12`로 검증하도록 맞췄다. 원본 metric이나 artifact 값은 변경하지 않는다.
- embedding 추출이나 데이터셋 실험 재실행은 필요 없다. 통합 보고서 실행만 대상이다.

### 미해결 위험과 승인 기준

- 현재 ArcFace 3개 run은 PQ SDC `((128, 8),)`이고 AdaFace·MagFace·EdgeFace는 SDC가 비활성화되어 있다. 기존 동질 SDC 계약에 따라 strict matrix loader가 혼합을 거부하므로 실제 4×3 artifact는 아직 생성하지 않았다.
- 이 차이를 해결하려면 ArcFace를 SDC 비활성 계약으로 재실험하거나, 공통 search-mode 교집합에서 SDC를 제외하는 별도 비교 정책을 명시적으로 승인·구현해야 한다. 이번 변경에서는 해당 과학 계약을 임의로 완화하지 않는다.
- 최종 승인은 12개 선택 행, 정확한 4×3 key 집합, source lineage/SHA 검증, 동질 SDC 계약 및 `results/paper/common/four_model_three_dataset/<matrix_uid>` manifest 일치를 요구한다.

## 19:41 KST — Cross-model SDC all-or-none 공통조건 정책

- 작성일: 2026-09-01 (KST)
- 상태: 검증됨; 합성 artifact 회귀 및 실제 12-run validation-only 검증 완료
- 이전 결정과의 관계: 위 19:23 KST 절의 미해결 SDC 계약을 사용자가 승인한 공통조건 정책으로 해결한다. 개별 completed run의 SDC 설정과 artifact는 변경하지 않는다.

### 변경 배경과 결정

- ArcFace는 PQ-m128 SDC를 포함하지만 AdaFace·MagFace·EdgeFace는 SDC가 비활성화되어, 기존 matrix loader가 비-SDC 공통 결과까지 모두 거부했다.
- cross-model matrix의 SDC 비교는 `all_model_dataset_sources_required`로 정의한다.
- 4모델 × 3데이터셋의 12개 source가 모두 SDC를 보유하고 동일 설정을 사용할 때만 `pq_sdc_exhaustive` 행을 포함한다.
- 한 source라도 SDC가 없으면 모든 source의 SDC 행을 제외한다. PCA 및 PQ reconstruction·one-sided·ADC 행은 기존 검증과 metric 정의를 유지한 채 산출한다.
- SDC 제외는 보고서 결합 단계의 비교 가능 조건 투영이며, source run·compact artifact를 수정하거나 SDC가 없었다고 재기록하지 않는다.

### 데이터·모듈 흐름과 영향 범위

```text
12 verified source summaries
  -> source별 SDC 설정과 model별 3-dataset coverage 집계
  -> 12/12 + 동일 설정: SDC 포함
  -> 그 외: 모든 pq_sdc_exhaustive 행 제외
  -> 공통 retrieval/joined matrix + coverage manifest
```

- canonical policy/loader/writer: `research/experiments/cross_model_matrix.py`
- notebook 표시와 export status: `notebooks/common/reports/00_cross_dataset_results.ipynb`
- regression tests: `tests/research/test_cross_model_matrix.py`, `tests/research/test_notebook_layout.py`
- matrix schema/artifact는 v4로 갱신하고, `matrix_uid`는 source content와 SDC 비교 계약을 함께 해시한다.

### manifest와 검증 기준

- `sdc_comparison_contract`에 policy, 포함 여부, 이유, 12-source coverage, model별 coverage, 완전한 model 목록과 제외 search mode를 기록한다.
- 모든 source가 SDC인 합성 matrix는 SDC를 포함하고, 전부 비활성인 matrix는 비-SDC 공통 행만 포함한다.
- 한 모델의 세 dataset에 SDC가 없는 혼합 합성 matrix는 전체 SDC를 제외하며 다른 search mode의 행 수와 lineage를 보존한다.
- 실제 현재 matrix의 승인 기준은 SDC coverage `3/12`, `sdc_included=false`, 제외 mode `{pq_sdc_exhaustive}`, 그리고 기존 strict lineage/statistical 검증 통과이다.

### 실제 12-run validation-only 결과

- model UID 자동 선택으로 4모델 × 3데이터셋의 completed run 12개가 선택됐다.
- matrix schema는 v4, matrix UID는 `open-set-matrix-e01a05d216b293223df3`이다.
- SDC coverage는 ArcFace 3, AdaFace 0, MagFace 0, EdgeFace 0으로 총 `3/12`이며 `sdc_included=false`와 `pq_sdc_rows=0`을 확인했다.
- 공통 결과는 compression 120행, retrieval 2,700행, joined 2,700행이다.
- 포함 search mode는 PCA direct/reconstruction과 PQ reconstruction/one-sided/ADC이며 SDC만 제외됐다.
- 검증은 메모리에서 읽기 전용으로 수행했으며 matrix artifact 파일은 작성하지 않았다.

### 재실행 범위와 위험

- embedding, PCA/PQ fitting, retrieval 실험 재실행은 필요 없다. 기존 compact artifact를 읽는 cross-model report만 다시 실행한다.
- SDC가 12개 모두 존재하더라도 설정이 서로 다르면 직접 비교할 수 없으므로 fail-closed로 거부한다.
- 공통조건 투영은 SDC 행만 제거한다. 다른 search mode의 누락이나 계약 불일치는 계속 전체 matrix 실패로 처리한다.

## 20:06 KST — Cross-model 통합 실행 조절 변수

- 작성일: 2026-09-01 (KST)
- 상태: 검증됨
- 변경 배경: 보고서 노트북 상단에서 단일 모델 보고와 4모델 × 3데이터셋 통합 matrix 실행 여부를 명시적으로 선택할 수 없었다.

### 결정과 동작

- `notebooks/common/reports/00_cross_dataset_results.ipynb`의 사용자 설정 영역에 `RUN_CROSS_MODEL_MATRIX` boolean을 추가한다.
- `True`이면 model UID 기반 12-run 자동 선택, strict matrix 검증, SDC all-or-none 투영과 선택적인 matrix 파일 작성을 수행한다.
- `False`이면 cross-model UID 자동 선택과 matrix loader·writer를 모두 건너뛰고 기존 단일 모델 LFW·SurvFace·RFW-Custom 및 supplementary 보고만 처리한다.
- 비활성 상태는 최종 `export_result.cross_model_matrix.status="disabled"`로 `not_configured`와 구분한다.
- `RUN_CROSS_MODEL_MATRIX=False`와 `REQUIRE_COMPLETE_MODEL_MATRIX=True`의 모순된 조합은 fail-closed로 거부한다.
- 배치 parameter 주입에서 새 변수가 없으면 기존 `MODEL_RUN_MATRIX` 또는 UID matrix 설정 존재 여부로 호환 기본값을 결정한다.

### 검증 결과와 재실행 범위

- 동일한 실제 completed run 환경에서 `False`는 matrix 선택 0행·경로 0개·loader 미호출·retrieval 0행을 확인했다.
- `True`는 12개 run 자동 선택, 12개 경로, matrix 로드와 SDC 제외 후 retrieval 2,700행을 확인했다.
- notebook JSON/AST, output-free 상태와 notebook layout 회귀 테스트를 검증한다.
- run/result artifact와 실험 metric은 변경하지 않으며 보고서 노트북만 다시 실행하면 된다.
