# 2026-11-15 KST · UCFace 일반 baseline과 진단 조건의 분리

상태: 방향 교정 구현·관련 테스트 및 실제 checkpoint/전달 경로 검증 완료. UCFace 동일 성능 재현과 정식 학습 재개는 미실행이다.

## 배경과 이전 결정

사용자의 1차 목표는 UCFace Table I의 일반 ArcFace/CosFace/MagFace/AdaFace 모델을 준비하고 압축 전 성능을 비교하는 것이다. 20261114의 기본 선택 목록에 `arcface_continuous_margin`을 포함한 결정은 이 목표와 맞지 않아 폐기한다. 해당 수식은 기본 학습에서 제외하고, 선택형 진단 API에만 남긴다. 기존 checkpoint·전처리·결과 불변, 20261106의 안전 중단/명시적 재개, producer/consumer 독립 경계는 유지한다.

## 근거와 결정

- 사용자가 이번 대화에 제공한 제1저자 이메일은 대부분의 baseline에 FaceX-Zoo를 참고했고 VGGFace2 parent를 사용했다고 설명한다. 원본 실험 파일을 확인한 답변이 아닌 기억에 근거한 답변이다. 상세 checkpoint·SCFace 인물 명단·평가 코드가 제공된 것은 아니다.
- 이메일의 MobileFaceNet 512D와 출판본이 충돌한다. 본문 IV-A.3, 인쇄면 7181은 주요 실험 전체 1024D를 명시하고 부록 Table XVII는 별도의 MobileFaceNet 512D 실험을 제시한다. Table I 비교에는 1024D를 유지한다. parent를 이 이유로 다시 만들지 않는다.
- 원래 ArcFace의 `margin_am=0`을 기본 목록에서 유지한다. 기존 target-only FP32/zero-radicand 수치 보호는 이전 로컬 구현 선택으로 남으며 이번에 학습 수식·Trainer·checkpoint fingerprint 대상 파일을 변경하지 않는다.
- SurvFace의 현재 FR 4,255명/176,205장은 논문 5,319명/220,888장과 다르다. 기존 비등록 보정 인물을 포함한 전체 FR 모델은 별도 protocol/출력 경로가 필요하며 기존 FR 제외 calibration 계약에 그대로 연결하지 않는다. SCFace 인물 명단, 저해상도 정렬의 구체적 추출기/실패 처리도 저자 구현으로 확인되지 않았다.

## 구현과 데이터 흐름

FaceX `ucface_reference.py`가 논문 대비 인원·차원·미확인 조건을 계산해 표시한다. `selected_campaign.py`의 기본 목록은 일반 loss 12개이며, v2 선택 파일에 `purpose`, `reproduction_scope`를 기록한다. `local_protocol_baseline`에는 continuous-margin을 허용하지 않는다. v1 파일은 보존·열람만 허용하고 새 실행은 거부한다. `process_runner.py`와 자식 `run_campaign.py`가 모두 실행 목적을 확인해 이전 커널의 v1 요청도 거부한다.

03·04 기본값은 `CAMPAIGN="ucface_review"`, `EXECUTE=False`다. 검토 모드는 모델 상태를 읽지만 학습/export를 수행하지 않으며, True로 바꾸어도 미확인 재현을 로컬 실험으로 대체 실행하지 않는다. 명시적 `selected` 경로는 기존 연구 조건의 재개용이다. 현재 선택 파일은 `F:/models/facex/selected/ucface_recipes_v1/plans/selection_v2_local_protocol.json`이며 root를 유지해 동일 조건의 기존 checkpoint를 재사용한다.

ronbun `facex_inventory.py`는 v2의 목적·출처·완료 상태·실제 export head 설정과 인물 수를 검사한다. 목적을 바꾸거나 continuous-margin을 baseline으로 섞으면 거부한다. v1은 명시적 `legacy_local_control`로만 읽는다. 생성 YAML의 `model_scope`는 최종 report contract에도 포함된다. `study.stage="baseline"`은 ronbun의 실험 단계이며 UCFace 재현 인증을 뜻하지 않는다.

새 inventory 설정은 `INVENTORY_ORIGIN_ONLY=True`로 각 데이터셋의 Origin만 먼저 평가한다. PCA/PQ 비교는 Origin 결과 검토 후 False와 새 YAML 경로로 생성한다. 기존 YAML·ModelSpec·완료 보고서를 변경하지 않는다. SurvFace의 독립 보정 threshold 성능과 test ROC 기반 논문 비교는 구분한다. DB schema·기존 calibration identity 역할은 변경하지 않았다.

## 검증과 재실행 범위

선택한 12개 기존 연구 후보는 완료 9개, TinyFace CosFace 재개 1개, TinyFace MagFace/AdaFace 신규 2개다. 이는 논문 동일 성능 판정이 아니다. 중단 checkpoint의 모델/head/optimizer/scheduler/RNG를 CPU에서 복원했고 epoch 21, next-batch index 42를 확인했다. continuous-margin 모델은 미시작이다.

관련 41개 테스트 통과. 03·04 코드 셀 전체를 계획 모드로 실행하고, 검토 모드의 True 실행이 자식 학습 전에 차단되는 것을 확인했다. 실제 기존 SCFace ArcFace export 1개로 v2 inventory → 등록 → YAML → 기존 handoff 검증을 수행했다. 새 정식 학습·전체 임베딩·PCA/PQ·보정 성능 실험은 실행하지 않았다. 상세 근거는 `publish/UCFace_baseline_방향교정_20261115_v1.md`와 외부 `ucface_reproduction_review_20261115` 검증 산출물에 기록한다.

사용 시 디스크의 수정된 노트북을 다시 열고 커널을 재시작한다. 기존 parent/전처리를 다시 실행할 필요는 없으며, 연구 분할·정렬을 변경하는 별도 재현 캠페인은 해당 입력과 모델만 새로 생성해야 한다. 저자의 원본 구현이 없는 상태에서 동일 성능·완전 복제를 보장할 수 없고, 일반 baseline 학습 조건의 로컬 재구현과 구분해야 한다.
