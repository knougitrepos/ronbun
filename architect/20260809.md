# 2026-08-09 Step 7 architecture decisions

## 21:30 KST — EdgeFace 추가 및 RFW 진단 평가 분리

- 작성일: 2026-08-09 (KST)
- 상태: 구현 중
- 작업 브랜치: `step7`

### 변경 배경

기존 정식 비교는 ArcFace, AdaFace, MagFace 체크포인트에 한정되어 있었다.
세 체크포인트는 학습 데이터와 전처리가 완전히 통제된 loss ablation이 아니므로,
모델 계열을 넘어 반복되는 압축 경향을 확인하려면 다른 경량 구조와 학습 소스를
가진 외부 체크포인트가 필요하다. 사용자가 공식 EdgeFace-XS gamma=0.6 가중치를
`models/edgeface/edgeface_xs_gamma_06.pt`에 배치했다. 또한 RFW는 추가 데이터셋으로
사용하되 BalancedFace는 이번 단계에서 유예한다.

### 결정 내용

1. EdgeFace-XS gamma=0.6을 네 번째 checkpoint-level 비교 대상으로 추가한다.
   - family: `edgeface`
   - architecture: `edgeface_xs_gamma_06`
   - training dataset: `webface12m`
   - input: RGB 112x112, `(x - 127.5) / 127.5`
   - strict loader: official `edgenext_x_small` + recursive low-rank linear
     replacement(gamma=0.6)
   - target layer: `model.stages.3.blocks.2.convs.2`
2. MagFace 기본 체크포인트 경로를 의미가 명확한
   `models/magface/magface_ms1mv2.pth`로 변경한다. 체크포인트 내용과 lineage는
   SHA-256으로 구분하며 파일명 자체를 새로운 모델로 해석하지 않는다.
3. RFW는 공식 4-group 10-fold 1:1 verification 진단으로만 사용한다.
   - RFW를 open-set DIR/FPIR 평가로 재명명하지 않는다.
   - RFW 영상/쌍에서 PCA 또는 PQ codec을 fit하지 않는다.
   - LFW 또는 SurvFace development split에서 fit한 frozen codec을 RFW에 적용하는
     cross-dataset transfer만 허용한다.
   - 각 held-out fold의 threshold는 같은 그룹의 나머지 9개 fold에서 선택한다.
4. BalancedFace의 source inventory는 보존하되 Step 7 실행 입력, codec fit,
   threshold calibration에서 제외하고 `deferred_by_step7_scope`로 기록한다.
5. LFW 프로토콜은 현재 코드 구성 그대로 유지한다. query를 고위험/저위험으로
   나누는 uncertainty/defer 실험은 추가하지 않는다.
6. 기존의 두 실행 인터페이스를 모두 유지한다.
   - all-in-one: `notebooks/common/orchestration/00_batch_experiment_runner.ipynb`,
     `notebooks/common/reports/00_cross_dataset_results.ipynb`
   - step-by-step: `notebooks/lfw/**`, `notebooks/survface/**`
   공통 Python 모듈을 canonical 구현으로 사용하되 어느 한 인터페이스를 제거하거나
   합치지 않는다. `ARTIFACT_STORAGE_MODE`, 실행 승인, run 재사용/새 run 선택처럼
   재현성과 비용에 영향을 주는 설정 변수는 유지한다. 정말 제거해야 할 경우 해당
   노트북과 architecture 기록에 삭제 이유, 대체 경로, 재실행 영향을 먼저 남긴다.

### 현재 구현과 목표 구조의 차이

- 구현됨: EdgeFace family/adapter/backbone/strict loader/profile/runner alias,
  MagFace 경로 변경, RFW pair-scoring 평가 함수, BalancedFace 유예 계약.
- 검증 필요: 실제 EdgeFace 체크포인트 smoke test와 Grad-CAM target의 gradient,
  전체 회귀 테스트, LFW/SurvFace full experiment.
- 미구현: RFW tar/BIN에서 112x112 입력을 materialize하고 네 모델의 전체 임베딩을
  추출하는 장시간 실행 단계. 따라서 이번 변경만으로 RFW 수치 결과가 생성되지는
  않는다.

### 데이터 및 모듈 흐름

```text
EdgeFace checkpoint
  -> strict official loader
  -> common PyTorch adapter
  -> unchanged LFW/SurvFace Step 4
  -> origin/PCA/PQ metrics

RFW official pair manifest
  + origin embeddings or externally fitted frozen-codec embeddings
  -> cosine pair scores
  -> group-wise 9-fold threshold selection
  -> held-out accuracy/TAR/FAR and group gap
```

### 재실행 범위

기존 ArcFace/AdaFace/MagFace 완료 run은 immutable하게 유지한다. EdgeFace는 새
`model_uid`로 LFW와 SurvFace를 각각 새 full run으로 실행해야 한다. RFW 결과는
별도 supplementary diagnostic artifact로 만들며 기존 LFW/SurvFace open-set 표에
동일 metric인 것처럼 합치지 않는다.

### 검증 기준

- EdgeFace 공식 체크포인트가 missing/unexpected key 없이 strict load된다.
- uint8 RGB 입력에서 raw 512D, raw norm, unit-normalized 512D가 유한하다.
- 선언한 Grad-CAM target layer가 존재하고 backward gradient를 받는다.
- 공통 runner가 `edge` 별칭을 EdgeFace profile과 정확한 로컬 경로로 resolve한다.
- RFW 평가에서 held-out fold가 threshold 선택에 포함되지 않는다.
- RFW summary가 `open_set_protocol=false`, `codec_fit_on_rfw=false`를 기록한다.
- LFW의 기존 protocol/config는 바뀌지 않는다.
- all-in-one 및 step-by-step 인터페이스와 사용자 설정 변수의 존재가 유지된다.

### 미해결 위험

- WebFace12M과 RFW의 identity non-overlap 증거가 없으므로 EdgeFace의 RFW 결과도
  headline 일반화 근거가 아니라 보조 진단으로 제한한다.
- 모델들의 architecture, training data, preprocessing가 다르므로 네 모델 비교는
  loss function의 인과 효과를 증명하지 않는다.
- `timm==0.9.16`을 CUDA 11.8/GTX 1080 Ti 환경에서 고정했지만 실제 full run의
  VRAM/throughput은 첫 EdgeFace run에서 기록해야 한다.
- Frozen codec transfer에서는 codec source(LFW 또는 SurvFace)를 결과 행과
  manifest에 명시해야 하며 서로 섞어 하나의 RFW 결과로 평균내지 않는다.
