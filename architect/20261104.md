## 배경과 결정

사용자는 검증된 원본·전처리 이미지 및 목록을 임의로 수정하지 않는다는 전제를 명시하고,
최초 검증 완료 기록 재사용과 강제 재검증 변수를 요청했다. 20261025의 매 실행 이미지
바이트 hash 정책을 **사용자가 선택한 immutable_verified_reuse 모드에 한하여 대체**한다.
20261101의 학습 조건, 20261102의 미완료 전처리 복구, 데이터 분할과 저장소 경계는 유지한다.

- 노트북 00–04: DATA_INTEGRITY_MODE="immutable_verified_reuse", FORCE_DATA_REVERIFY=False.
  변수는 공통 Python 설정 data_integrity.mode/force_reverify로 전달된다.
- 최초 사용에는 전체 mapping/hash/decode를 검사한다. 기존 완전 일치 v1 decode receipt도
  전체 검증 완료 근거로 사용할 수 있다. 원본/전처리 이미지와 report는 수정하지 않는다.
- 재사용 시 report, source list, prepared list, manifest의 hash와 전처리 정책·기존 검증
  코드·라이브러리 계약을 확인한다. 이미지별 path walk/hash/decode는 수행하지 않는다.
- verification_cache/immutable_v1/<contract>.json에 완료 수, 상태, 근거, 자체 hash를 저장한다.
  강제 검사 중/실패 상태는 과거 성공의 재사용을 막는다. 이전 기록은 history에 보존한다.
- FORCE_DATA_REVERIFY=True는 전체 hash+decode를 수행하며 데이터의 기존 hash를 갱신하는
  옵션이 아니다. 입력이 달라졌다면 새 전처리 버전이 필요하다. 검사 후 False로 되돌린다.
- 완료된 전처리의 CLI --resume에도 같은 정책을 적용한다. 미완료 전처리는 기존 복구 절차를 따른다.
- 엄격한 기존 full/content_verified_reuse 모드와 기존 기본 Python 설정 의미는 보존한다.

## 코드 및 checkpoint 호환성

FaceX-Zoo의 새 modules/dataset_verification.py가 공통 검증 정책을 담당한다.
실제 전처리 변환·기존 검증 코드 alignment.py/integrity_cache.py는 변경하지 않아 전처리
정책과 과거 전체 검증 증거의 fingerprint가 유지된다. notebook_workflow의 학습/export 및
01의 bind, prepare_alignment.py의 완료 데이터 재사용 분기가 새 정책을 호출한다.

코드 hash 변경만으로 현재 중단 checkpoint를 폐기하지 않도록
configs/verification_resume_compatibility.json에 정확한 변경 전/후 전체 source map을 고정했다.
checkpoint_compatibility.py 및 checkpoint_manager는 그 조합만 승인하고, 그 외 설정은
전체 동일성을 요구한다. 모델·학습·데이터 조건 변경, 미등록 코드 변경, 역방향 전이는 거부한다.
새 checkpoint의 resume_source에 이전 checkpoint hash와 source 전환을 기록한다.
원본 checkpoint/config hash는 재작성하지 않는다. 현재 02에는 검증한 복구 파일을 명시했다.
