# 2026-08-26 Architecture 기록

## PQ query/gallery 조건 분해와 open-set operating-point v6 보고 계약

- 작성일: 2026-08-26 (KST)
- 상태: `구현됨` (코드·합성 회귀 `검증됨`, 실제 4모델×데이터셋 결과 `미실행`)
- 기준 브랜치·커밋: `step9`, `b9bfcc1acb1086b7380052da46df32545640fea1` 위 작업 트리
- 이전 결정과의 관계:
  - `architect/20260819.md`의 Step9 saliency-threshold v2 계약과 score-space 분리 원칙을 유지한다.
  - 기존 `search_space_v5_tpir20_multi_fpir`는 완료 artifact로 보존하고 새 비교는
    `search_space_v6_query_gallery_conditions`에서 생성한다.
  - 기존 `pq_reconstruction_cosine` 대 `pq_adc_exhaustive` 비교를 폐기하지 않고,
    one-sided cosine과 SDC를 추가하여 query precision과 distance-function 요인을 분해한다.

### 변경 배경

기존 PQ 비교는 양쪽 query/gallery를 PQ encode-decode한 cosine 검색과 원본 float32 query를
PQ-code gallery에 적용한 ADC를 비교했다. 따라서 관찰된 차이를 query 보존 효과와
cosine 대 squared-L2 score-space 차이 중 어느 하나로 귀속할 수 없었다. 또한 ADC에는
origin cosine threshold가 적용될 수 없다는 기존 계약을 SDC까지 일반화할 필요가 있었다.

### 결정 내용

1. PQ 검색 조건을 다음 네 가지로 고정한다.
   - `pq_reconstruction_cosine`: PQ 복원 query / PQ 복원 gallery / cosine
   - `pq_one_sided_cosine`: 원본 float32 query / PQ 복원 gallery / cosine
   - `pq_adc_exhaustive`: 원본 float32 query / PQ code gallery / asymmetric squared L2
   - `pq_sdc_exhaustive`: PQ code query / PQ code gallery / symmetric squared L2
2. 모든 retrieval 행과 compact summary에 `query_representation`,
   `gallery_representation`, `distance_function`, `compressed_score_space`,
   `score_spaces_comparable`, `frozen_origin_threshold_applicable`를 기록한다.
3. cosine 조건만 `frozen_origin`과 `recalibrated_compressed`를 모두 산출한다. ADC와 SDC는
   cosine과 다른 score space이므로 `recalibrated_compressed`만 허용한다.
4. SDC는 새 검색 알고리즘 기여가 아니라 양쪽 PQ-code 조건의 보조 ablation으로 둔다.
   Faiss 8-bit native SDC를 우선하고, 더 작은 bit width의 smoke/legacy 검증에는 동일 Faiss
   SDC table을 사용하는 bounded NumPy 경로를 둔다.
5. 파생 artifact 계약을 v6로 올리고 기존 완료 v5 artifact를 덮어쓰지 않는다. v6는
   FPIR 1/5/10/20/30%, TPIR20, closed-set Rank-20 recall, Wilson CI, paired delta CI,
   realized FPIR, target-met 여부, payload/codebook/amortized storage를 함께 보고한다.
6. 공통 보고서는 Origin, frozen/recalibrated compressed 행을 명시적으로 만들고
   `pq_query_gallery_operating_points.csv`를 별도 출력한다. `target_met_on_test=False` 행은
   목표 FPIR operating-point 결과로 인용하지 않는다.
7. `00_batch_experiment_runner.ipynb`와 `00_cross_dataset_results.ipynb`는 얇은 진입점으로
   유지한다. 실행·쓰기·덮어쓰기는 기본 비활성화하며 실제 계산과 검증은 공통 `.py`에 둔다.
8. TinyFace 표준 closed-set distractor protocol은 현재 open-set 표에 섞지 않는다.
   추가하려면 `TinyFace-Custom`의 non-mated probe와 calibration/test protocol UID를 먼저
   별도 고정해야 한다.

### 데이터·모듈 흐름

```text
완료 run의 prepared origin embeddings + explicit PQ budget
  -> 공통 PQ fit / query-gallery condition별 exhaustive search
  -> score-space별 calibration threshold
  -> per-query retrieval ledger
  -> v6 compact summary
     (realized FPIR / TPIR20 / Rank20 / CI / storage / condition metadata)
  -> 명시적 4-model x 3-dataset matrix
  -> Origin + reconstruction + one-sided + ADC (+ SDC) 보고표
```

### 미해결 위험

  난이도로 해석하지 않는다.

## 18:40 KST — TinyFace 공식 closed-set 1:N supplementary 경로 추가

- 작성일: 2026-08-26 (KST)
- 상태: `구현됨` (실제 설치본 protocol/count 검증 및 합성 평가 회귀 `검증됨`, 4모델 full GPU 결과 `미실행`)
- 기준 브랜치·커밋: `step10`, `54f3ef4aec45525505abda2d41396944a8a403a5` 위 작업 트리
- 이전 결정과의 관계:
  - 같은 문서의 PQ v6 결정 8항인 “TinyFace를 open-set 표에 섞지 않는다”는 원칙을 유지한다.
  - `TinyFace-Custom` open-set protocol을 새로 만들지 않고, 배포본이 제공하는 공식
    closed-set 1:N distractor protocol을 별도 supplementary 평가로 추가한다.
  - 기존 4 checkpoints × 3 open-set datasets 행렬은 변경하지 않는다.

### 변경 배경

`data/raw/tinyface`에 공식 TinyFace 배포본이 추가되었다. 설치본은 Training 7,804장,
Gallery_Match 4,443장, Gallery_Distractor 153,428장, Probe 3,728장으로 총 169,403장이며,
공식 MAT 파일은 probe와 match-gallery identity 관계를 제공한다. 이 protocol에는 non-mated
probe와 calibration split이 없으므로 FPIR/TPIR 또는 score-space threshold calibration을
정의하면 공식 TinyFace 결과가 아니게 된다.

### 결정 내용

1. TinyFace 공식 task를 `tinyface_official_closed_set_v1`로 고정한다. Gallery는
   `Gallery_Match + Gallery_Distractor`, query는 `Probe`, compressor fit은 `Training_Set`
   전용이다.
2. 공식 저해상도 face crop에는 detector를 다시 적용하지 않는다. 모든 이미지에
   `official_face_crop_resize` 한 번(PIL bilinear, 선택 checkpoint의 입력 크기 112×112)을
   적용하고 full coverage를 요구한다.
3. distractor마다 고유 identity namespace를 부여한다. 모든 distractor를 한 identity로
   합치는 오류를 금지한다.
4. 공식 지표는 mAP와 Rank-1/5/10/20이며 Rank 비율은 probe-level Wilson 95% CI,
   압축-minus-Origin 차이는 동일 query paired bootstrap 95% CI로 기록한다.
5. 조건은 Origin, PCA direct/reconstruction, PQ reconstruction cosine, one-sided cosine,
   ADC, 선택적 SDC를 기록한다. query/gallery representation, distance function, gallery
   payload/codebook/amortized storage를 조건별로 보존한다.
6. ADC/SDC의 공식 순위는 centroid 복원과 동치인 squared-L2 score로 전체 distractor gallery를
   스트리밍 평가하고, native compressed top-20 결과와 일치 여부를 fail-close 검증한다.
   score block은 선택된 CUDA device에서 계산하고 rank/AP ledger만 CPU로 회수하여 GTX 1080 Ti
   11GB 범위에서 전체 score matrix를 만들지 않는다.
7. quick은 test identity와 distractor를 결정적으로 부분 선택하고 paper eligibility를 끈다.
   full만 공식-result eligibility를 가질 수 있다.
8. 완료 TinyFace run은 명시적 경로와 manifest/SHA-256으로만 보고서에 선택한다. 자동 latest
   선택과 기존 완료 artifact 덮어쓰기를 금지한다.

### 데이터·모듈 흐름

```text
data/raw/tinyface
  -> official MAT + directory/count validation
  -> development / match-gallery / distractor-gallery / registered-probe manifest
  -> single recorded resize to checkpoint input
  -> normalized 512D embeddings
  -> Training_Set-only PCA/PQ fit
  -> condition-specific exact official ranking
  -> mAP + Rank-1/5/10/20 + CI + storage + latency artifact
  -> cross-dataset report의 separate TinyFace supplementary table
```

## 21:16 KST — 4-dataset orchestration 계약 통합 및 FULL 기본값 고정

- 작성일: 2026-08-26 (KST)
- 상태: `구현됨` (정적 notebook 검증과 단위 회귀 `검증됨`, 실제 full GPU 재실행 `미실행`)
- 이전 결정과의 관계:
  - 18:40 KST의 TinyFace 공식 closed-set supplementary 경로는 유지한다.
  - 당시 구현의 notebook-level 별도 TinyFace 플래그와 별도 quick fraction은 외부 실행 계약을
    둘로 나누므로 폐기한다.
  - protocol 및 metric 의미는 통합하지 않고, 외부 선택·계획·preflight·실행·완료-run 재사용
    인터페이스만 통합한다.

### 변경 배경

공통 실행 노트북에 LFW/SurvFace/RFW-Custom용 `QUICK_DATA_FRACTIONS`와 TinyFace 전용
`RUN_TINYFACE_OFFICIAL`, `TINYFACE_QUICK_FRACTION`, `TINYFACE_COMPLETED_RUN_OVERRIDE`가
동시에 존재했다. 이 구조에서는 동일한 실행 tier와 완료-run 선택 정책이 데이터셋별로 다르게
보이며, 설정 누락 또는 full/quick 혼합을 유발할 수 있었다.

### 결정 내용

1. 외부 orchestration dataset 계약을
   `("lfw", "survface", "rfw_custom", "tinyface")` 하나로 고정한다.
2. 기본 실행 tier는 Python의 `DEFAULT_RUN_TIER="full"`, YAML의
   `execution.default_tier: full`, notebook의 `RUN_TIER="full"`에서 일치시킨다. full은 모든
   선택 데이터셋에서 반드시 data fraction 1.0을 사용한다.
3. `QUICK_DATA_FRACTIONS`는 네 데이터셋의 키를 정확히 모두 요구한다. TinyFace quick 0.10은
   같은 공통 mapping에서 파생하며 별도 사용자 설정을 두지 않는다.
4. `COMPLETED_RUN_OVERRIDES`도 네 데이터셋을 같은 mapping으로 받으며, 선택되지 않은 dataset
   key가 있으면 fail-close한다.
5. notebook은 `build/inspect/run_or_reuse_integrated_*` 인터페이스만 호출한다. 내부 dispatcher가
   세 open-set 데이터셋은 canonical Step 4 runner로, TinyFace는 공식 closed-set runner로 보낸다.
6. SDC 선택은 `INCLUDE_PQ_SDC` 하나로 통합한다. protocol상 적용 불가능한 후처리는 dispatcher
   이후 명시적으로 `not_applicable`로 기록한다.
7. 최종 report 호출은 네 데이터셋을 단일 `selected_runs` mapping으로 받는다. report 내부에서만
   TinyFace를 supplementary 표로 분리하며 open-set `DATASETS`와 4x3 matrix에는 포함하지 않는다.

### 데이터·모듈 흐름

```text
DATASET_IDS + RUN_TIER(full default) + QUICK_DATA_FRACTIONS + COMPLETED_RUN_OVERRIDES
  -> integrated plan builder
  -> common preflight mapping
  -> protocol-aware dispatcher
       lfw/survface/rfw_custom -> open-set Step 4
       tinyface               -> official closed-set 1:N
  -> one EXECUTION_RESULTS mapping
  -> protocol-specific postprocessing
  -> one selected_runs report input
       open-set main tables + TinyFace supplementary table
```
