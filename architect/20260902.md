# 2026-09-02 Architecture 변경 기록

## 06:28 KST — CR-FIQA 조건부 threshold calibration 파이프라인

- 작성일: 2026-09-02 (KST)
- 상태: 구현됨; 단위·회귀 테스트, CR-FIQA S/L GPU smoke, 기본 노트북 top-to-bottom 실행 검증됨. 전체 SurvFace FIQA score 생성과 최종 Global/FIQA 비교 실험은 미실행이다.
- 이전 결정과의 관계: `architect/20260829.md`와 `architect/20260830.md`의 PQ ADC score-space별 calibration 및 saliency 분석 계약을 유지한다. `notebooks/common/orchestration/00_batch_experiment_runner.ipynb`와 `notebooks/common/reports/00_cross_dataset_results.ipynb`는 변경하지 않고, 새 파이프라인의 compact artifact가 실제 생성·검증된 뒤 보고 노트북에 연결한다.

### 변경 배경

- 연구 질문은 새 FIQA 모델 학습이 아니라 동일한 압축 검색 조건에서 `Global`, `FIQA-conditioned`, 향후 `FIQA+Saliency` threshold calibration을 비교하는 것이다.
- 로컬 `models/fiqa`에 공식 CR-FIQA(S)와 CR-FIQA(L) pretrained checkpoint가 준비됐다.
- 완료된 ArcFace/SurvFace Step-4 run은 PQ m128 ADC test retrieval core와 frozen codec을 보존하지만, threshold 산출에 사용한 calibration query별 compressed score는 저장하지 않았다.
- 현재 SurvFace Grad-CAM scalar feature는 test probe에는 존재하지만 calibration query에는 없다. 이 상태에서 FIQA+Saliency threshold를 fit하면 test leakage가 되므로 자동 차단이 필요하다.

### 결정 내용

1. CR-FIQA(S)를 주 분석으로 사용하고 CR-FIQA(L)는 동일 protocol의 민감도 분석으로만 사용한다. 두 모델 모두 raw scalar quality를 사용하며 sigmoid, clipping, min-max normalization을 추가하지 않는다.
2. 첫 실행의 기본 범위는 ArcFace/SurvFace/PQ `pq_512_m128_b8`/`pq_adc_exhaustive`로 고정한다. 파이프라인은 명시적으로 선택한 다른 completed SurvFace model run도 같은 계약으로 받을 수 있어 이후 AdaFace 민감도 반복이 가능하다. ADC 점수공간 `negative_squared_l2_adc`에서 threshold를 다시 산출하며 origin cosine threshold를 재사용하지 않는다.
3. calibration을 `identity_id` SHA-256으로 fit/safety에 결정론적으로 분할해 동일 identity의 query가 양쪽에 나뉘지 않게 한다. FIQA Low/High cutpoint는 fit subset에서만 정한다.
4. 각 FIQA group의 non-mated threshold는 표본수 기반으로 global fit threshold와 부분 풀링하되, `>=` comparator에서 raw group quantile보다 낮아지지 않는 one-sided conservative shrinkage를 사용한다. 표본이 부족하면 global threshold로 fallback하고 held-out safety threshold는 추가 상한으로 적용한다.
5. 비교 방법은 `global_empirical`, 동일 fit/safety 계약의 `global_safe`, `fiqa_2bin_conservative_shrunk_safe` 세 가지다. test에는 고정된 threshold만 적용한다.
6. Saliency 1차 목적은 원본 FR 모델의 공간적 인식 근거와 압축에 따른 embedding distortion, score/rank 변화 및 threshold crossing의 연관 분석으로 유지한다. 압축 전후 heatmap 자체가 변했다고 해석하지 않는다.
7. Saliency 2차 목적은 FIQA 이후 incremental information 검증이다. 사전 지정 feature는 `outside_face_attention`, `saliency_entropy`이며, high/low masking은 intervention/faithfulness 검증, random masking은 negative control로만 사용한다.
8. calibration/test 모두 동일 label-free target의 saliency coverage가 95% 이상이어야 FIQA+Saliency 단계로 진행한다. 현재 calibration coverage가 0이므로 해당 단계는 `blocked`이며 구현 결과나 개선으로 주장하지 않는다.
9. FIQA와 retrieval score는 dataset ID, aligned-bundle manifest SHA-256, query별 aligned-content SHA-256을 모두 대조한 뒤에만 결합한다. retrieval row의 `top_k=20`과 `compressed_score_space=negative_squared_l2_adc`도 source manifest와 대조해 잘못된 core를 Rank-20/ADC로 재표기하지 않는다. comparison UID는 검증된 두 source manifest의 canonical hash를 포함한다.
10. fit/safety는 query가 아니라 `identity_id` 단위로 분할하며 calibration/test sample과 identity 집합이 모두 분리됐는지 검사한다. comparison artifact에는 실제 `rank_k=20`을 명시한다.

### 데이터·모듈 흐름

```text
aligned SurvFace RGB 112x112
  -> pretrained CR-FIQA(S) raw scalar
  -> immutable FIQA score artifact

completed ArcFace/SurvFace Step-4 run
  -> prepared origin embeddings + frozen PQ m128 codec
  -> calibration ADC search replay only
  -> persisted test ADC core reuse
  -> five legacy thresholds reproduced within 1e-12
  -> immutable condition score artifact

FIQA scores + calibration/test ADC scores
  -> calibration-only Low/High cutpoint
  -> global empirical / global safe / FIQA shrunk safe
  -> frozen test FPIR, Wilson CI, TPIR@Rank-20, paired bootstrap
  -> compact calibration comparison artifact

existing test saliency diagnostics
  -> primary compression/retrieval association analysis retained
  -> calibration saliency coverage gate
  -> blocked until leakage-safe calibration saliency exists
```

### 검증 결과

- CR-FIQA(S) IResNet-50과 CR-FIQA(L) IResNet-100 checkpoint를 현재 PyTorch `2.7.1+cu118`/GTX 1080 Ti에서 strict-load했다. 실제 production batch 64에서 두 모델 모두 64/64 finite score를 반환했으며 peak allocated memory는 S 1,214,481,920 bytes, L 1,300,907,520 bytes였다.
- 등록된 checkpoint byte size와 SHA-256이 로컬 파일과 일치한다.
- FIQA 전처리는 aligned uint8 NHWC RGB 112x112를 float32 NCHW `pixel/127.5-1.0`으로 변환하며 read-only memmap을 안전하게 copy한다.
- 전체 FIQA 추론은 8,192장 단위 shard를 원자적으로 기록한다. 합성 interruption 뒤 완료 shard를 건너뛰고 남은 shard만 계산해 최종 artifact를 조립하는 resume 회귀를 확인했다.
- 완료 run의 `freeze_manifest.json`과 selected-manifest SHA-256, run/dataset/model/extraction lineage를 대조하도록 replay preflight를 강화했다.
- 실제 completed run의 prepared population으로 calibration protocol 재구성 경로를 점검했다. seed 8972에서 query 160,408개(registered 61,583, known-unknown 98,825), gallery template 3,000개/60,480 images로 원 실행 진단과 일치했다. 전체 ADC score replay 자체는 아직 실행하지 않았다.
- row-level Rank-20/ADC lineage, sparse-group safety fallback, conditional calibration 및 artifact round-trip, saliency test-only 차단, 기존 gallery-size/rejection 회귀를 포함한 테스트 31개가 통과했다.
- 새 노트북은 장시간 실행·쓰기 플래그가 기본 False이며, checkpoint/hash preflight와 기존 saliency summary를 포함한 기본 top-to-bottom 실행에서 error 0을 확인했다. 소스 노트북은 execution count와 output을 남기지 않는다.

### 최종 승인 기준과 미해결 위험

- FIQA score row가 aligned bundle과 1:1이며 checkpoint/bundle SHA lineage가 일치해야 한다.
- replay한 다섯 global threshold가 completed Step-4 artifact와 `1e-12` 이내에서 일치해야 한다.
- 실제 결론은 target FPIR별 realized FPIR, Wilson 95% CI, TPIR@Rank-20, `target_met_on_test`, paired bootstrap 차이를 함께 사용한다. 미세한 point estimate 개선만으로 채택하지 않는다.
- shrinkage strength, safety fraction과 2-bin 선택은 사전 지정값이다. `safe`는 held-out empirical 보수화이며 formal FPIR guarantee가 아니다. 결과를 본 뒤 조정하면 별도 exploratory/sensitivity 분석으로 분리해야 한다.
- CR-FIQA checkpoint license는 CC BY-NC 4.0이므로 checkpoint 자체를 저장소나 논문 부록에 재배포하지 않는다. 사용자가 공식 출처에서 직접 받은 provenance는 최종 논문 기록에서 재확인한다.
- FIQA+Saliency는 calibration saliency 확보 전까지 차단된다. test-only saliency로 feature 선택, threshold fitting 또는 fallback 정책을 만들지 않는다.
