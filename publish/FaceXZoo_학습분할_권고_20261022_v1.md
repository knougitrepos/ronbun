대상 저장소는 `C:/ronbun`의 `step14` (`e1997a1c78c48627084202d5b691f203fb157266`)와 `F:/FaceX-Zoo`의 `adjust1` (`b7cc6f4772ae09591e0d5b759ca41ec9088ba40b`)이다. ronbun에는 진행 중인 변경이 있으므로 commit만으로 현재 작업 트리 전체를 재현할 수 없다. 수량은 아래 manifest와 명시한 결정 규칙에서 직접 재계산했다. 기존 완료 run, 원본 이미지, FaceX-Zoo 학습 목록은 수정하지 않았다.

## 권고와 적용 범위

주 실험은 **SurvFace의 공식 test를 유지하면서, 공식 training 안의 1,064명을 downstream fine-tune 전에 비등록자 calibration 용도로 남기는 구성**을 권고한다. 나머지 4,255명은 FR fine-tune에 사용하고, 그 안에서 calibration gallery 3,000명과 PQ-development 1,255명을 분리한다. 이 구성은 FR 학습량을 대부분 유지하고, 임계값을 실제로 학습하는 비등록자 fit/safety를 downstream FR 학습에서 분리한다.

이는 성능 실험으로 입증한 최적 비율이 아니다. 현재 데이터 규모, 3,000명 gallery 일치, 기존 분할 재현성, 학습 비용을 고려한 기본 설계다. 같은 MobileFaceNet 1024D 구조를 사용하더라도 SurvFace 학습 인원은 UCFace의 5,319명과 다르므로 **UCFace Table I과 동일한 구조를 사용한 별도 calibration 실험**이라고 명시해야 한다.

TinyFace와 SCFace는 기존 rank 평가를 보조 실험으로 유지하는 편이 적절하다. 순위를 그대로 둔 채 임계값만 바꾸는 Continuous-FIQA는 rank-1뿐 아니라 rank-20도 높이지 않는다. 이 두 데이터셋에서 Continuous-FIQA 효과를 주장하려면 비등록자 probe와 FPIR을 정의한 별도 open-set 프로토콜이 필요하며, 이를 기존 Table I 결과와 동일한 평가라고 부를 수 없다.

UCFace 본문 IV-A와 Table I은 MobileFaceNet 1024D, CosFace/ArcFace/MagFace/AdaFace, TinyFace·SCFace의 rank-1, SurvFace의 TPIR@20·FPIR을 구분한다. 본 논문은 IEEE TIFS 2024 정식 출판물이다. 본 권고에서 변경하는 것은 downstream 데이터 역할이며, 저자가 제시한 새로운 분할인 것처럼 표현하지 않는다. [UCFace 논문](https://doi.org/10.1109/TIFS.2024.3426973), [저자 논문 사본](https://openreview.net/pdf?id=k8BijWnOHZ).

## SurvFace 분할을 재현하는 규칙

1. `C:/ronbun/data/interim/survface/training_manifest.csv`의 기존 identity 분할을 고정한다. `development`: 4,255명 / 176,205장, `calibration`: 1,064명 / 44,683장이다. 인물 단위 분리이며 이미지 단위 무작위 분할이 아니다.
2. FaceX-Zoo train list에는 **development의 4,255명만** 넣는다. 공식 test와 1,064명 calibration의 어느 이미지도 FR fine-tune, checkpoint 선택, augmentation 선택에 사용하지 않는다. 매 모델·학습 seed에 같은 데이터 분할을 사용한다.
3. development의 identity 문자열을 `research.protocols.open_set._stable_key`와 namespace `survface:training-matched-calibration:gallery-identity`, seed `8972`로 정렬하여 앞 3,000명을 calibration gallery 인물로 고정한다. 각 인물의 이미지 절반(`floor(n/2)`)이 gallery에 들어간다. 기존 함수의 이미지 정렬 namespace를 그대로 사용하면 gallery 61,433장, 나머지 등록자 진단 probe 62,545장이 된다.
4. gallery에 들어가지 않은 development 인물 1,255명 / 52,227장을 PQ-development로 고정한다. 여기서 Origin용 PCA/PQ 또는 순수 PQ codebook을 모델별로 학습한다. gallery, 비등록자 fit/safety, final test 이미지로 codebook을 다시 선택하거나 학습하지 않는다.
5. calibration 1,064명의 `identity_id`에 `deterministic_calibration_partition(seed=8972, safety_fraction=0.30)`을 적용한다. 실제 규칙은 SHA-256의 앞 8바이트로 만든 `[0,1)` 값이 0.30 미만이면 safety이다. canonical 문자열(`survface:train:<native_id>`)을 사용해야 한다. 결과는 fit 744명 / 33,754장, safety 320명 / 10,929장이다.
6. 비등록자 fit의 검색 score·FIQA로 조건부 threshold를 학습하고 safety의 비등록자 residual로 안전 여유를 정한다. 동일 gallery·같은 fit/safety로 Global baseline도 구성한다. score space별로 각각 보정하고, 압축 후 점수에 cosine threshold를 재사용하지 않는다.
7. 모델·codebook·FIQA 선택·threshold·safety offset을 고정한 뒤 공식 test를 평가한다. test에서 best threshold, best seed, best 압축 설정을 고르면 held-out 평가가 아니다.

이 설계에서는 gallery와 등록자 calibration probe가 **FR 학습에서 본 인물**이다. 따라서 “모든 calibration 인물이 FR 학습에 노출되지 않았다”는 조건은 충족하지 않는다. 정확한 설명은 **비등록자 threshold fit/safety 인물이 SurvFace downstream fine-tune에서 분리되었다**이다. VGGFace2 등 부모 모델의 학습 인물까지 전혀 겹치지 않는지는 별도의 cross-dataset 인물 감사 없이는 확정할 수 없다.

FR 학습에 노출된 등록자 진단 probe의 TPIR로 방법을 반복 선택하면 일반화 추정이 낙관적으로 될 수 있다. 현재 Continuous-FIQA는 이 등록자 데이터를 직접 학습하는 목적함수가 아니므로, 이 probe는 진단에만 쓰고 최종 개선 주장은 공식 test로 제한한다. hyperparameter 선택이 필요하면 fit 내부에서 identity 단위 교차검증하거나, 별도 development를 명시한다. safety를 선택용 validation으로 반복 사용하지 않는다.

gallery 인원은 공식 test와 같은 3,000명이지만 이미지 수와 도메인 분포가 완전히 같지는 않다. calibration gallery 61,433장과 final gallery 60,294장의 차이, 학습 인물 gallery와 미학습 test 인물 gallery의 차이, test의 native identity가 복구되지 않는 distractor가 있다는 점을 결과 한계로 남긴다. 이는 empirical FPIR 제어이며 수학적 보장이 아니다.

TinyFace를 2,056명 학습 / 514명 calibration으로, SCFace를 40명 / 10명으로 나누는 등의 비율은 만들 수 있다. 그러나 이 숫자는 방법론상 필수 조건이 아니며 현재 권고 기본안도 아니다. TinyFace·SCFace의 기존 rank 평가에 임계값 효과가 생기지 않고, 특히 SCFace 10명의 반복 이미지를 대규모 독립 비등록자 표본처럼 해석할 수 없기 때문이다. 별도 rejection 실험을 요청하면 평가 역할과 인물 목록을 먼저 확정해야 한다.

## Continuous-FIQA가 실제로 개선하려는 값

현 `research/calibration/continuous.py`는 비등록자 fit에서 **smoothed pinball + ridge**로 조건부 score quantile을 학습하고, 비등록자 safety에서 일방향 residual offset을 정한다. 코드에 `fit_features_source=fit_non_mated_only`, `formal_fpir_guarantee=False`, `threshold_fit_on_test=False`가 명시되어 있다.

따라서 현재 구현은 **TPIR@20 자체를 직접 최대화하는 학습이 아니다**. FIQA에 따라 threshold를 조절한 결과, 목표 FPIR 부근에서 genuine score가 더 많이 통과하여 TPIR@20이 개선되는지를 검증한다. rank는 바뀌지 않는다.

`TPIR@20 = P(genuine identity가 Top-20 안에 있음 AND genuine score >= tau(q) | 등록자 probe)`이다. Top-1의 다른 사람 score가 threshold를 통과한 것만으로 성공 처리하면 안 된다. FPIR은 비등록자 probe에서 gallery 후보 중 하나 이상이 threshold를 넘는 비율이다. [SurvFace 공식 평가 프로토콜](https://qmul-survface.github.io/protocols.html).

Global은 비교 baseline이다. 주요 결과는 같은 checkpoint·score space·압축 프로파일·test cohort에서 `Continuous-FIQA − Global`의 **TPIR@20 차이와 realized FPIR**이다. 양쪽의 target 충족 여부, 원래 rank-20 도달률, genuine score 미달 실패, paired 불확실성도 함께 남긴다. 학습 seed를 여러 번 돌려도 같은 test 인물을 공유하므로 이를 서로 독립인 test 표본처럼 합산하지 않는다. 학습 split seed와 모델 초기화 seed는 구분한다.

## LFW·RFW의 “실험용으로만 사용”

이 보고서는 사용자의 표현을 **FR 모델의 fine-tune에는 사용하지 않되, 평가 프로토콜이 허용하는 내부 calibration에는 사용**하는 뜻으로 해석했다. outer fold의 test 쌍·인물은 해당 fold의 fit/safety/PQ 학습에 사용하지 않는다. 하나의 샘플이 다른 outer fold에서 개발 역할을 맡는 것은 교차검증 구조이며, 최종 모델 선택에 전체 test 결과를 반복 사용하는 것과 구분한다.

만약 “실험용”이 LFW/RFW에서는 어떠한 threshold/PQ 학습도 하지 않는다는 뜻이라면, 외부 데이터에서 학습한 모델·codebook·threshold를 고정한 **전이 평가**가 필요하다. 그 경우 target FMR이 LFW/RFW에서도 유지된다고 가정할 수 없다.

LFW의 기존 공통 PQ-development는 모든 pair에 등장하지 않는 1,468명 / 1,549장이었으나, `people.csv`의 outer test 인물 fold에는 그중 108–166명이 포함되어 있었다. 따라서 공식 people-fold 인물 분리까지 요구하는 새 실험은 **outer fold별로 해당 people-fold를 PQ-development에서 제외**해야 한다. 단순히 “6,000 pair에 없는 이미지”라는 조건만으로 충분하다고 기록하지 않는다. 이번 코드 교정의 실제 반영 여부는 현 workflow와 테스트 결과를 별도로 확인해야 하며, 과거 완료 run을 소급 수정하지 않는다.

LFW·RFW의 fit/safety 수는 전체 5,400쌍과 다르다. 서로 다른 역할의 두 인물을 잇는 impostor 쌍은 제외되고 RFW는 outer test 인물 purge도 필요하기 때문이다. 위 범위는 `publish/support/protocol_audit_20261022_v1`의 200개 LFW 분할과 800개 RFW 가상 분할 감사에 근거한다. 후자는 workflow 완료 결과가 아니다.

한 outer test fold의 impostor는 300쌍이므로 관측 FMR은 1/300 단위로 변한다. safety impostor 86–276쌍 등의 작은 표본에서 극저 FMR 보장이나 정밀한 우월성을 주장할 수 없다. 10-fold를 보고하되 분모·false accept 수·불확실성과 인물/쌍의 반복 의존성을 함께 표시한다. RFW의 기존 custom 1:N 경로를 공식 1:1 pair Continuous-FIQA 구현으로 간주하지 않는다.

## 현재 코드가 이미 해주는 일과 추가 적용이 필요한 일

**현재 FaceX-Zoo는 위 4,255/1,064 권고 분할을 적용하지 않는다.** `fine-tune/modules/finetune_protocol.py`의 `PAPER_SPLITS`와 `prepare_protocol`/`verify_protocol`은 SurvFace 5,319명 / 220,888장 전체를 요구하며, 클래스 수 변경이나 validation 목록을 거부한다. `prepare_selected_protocols`도 FIQA 데이터를 FR train에서 별도로 남기지 않는 계약이다. 현재 ronbun의 1,064명 / 44,683장은 기존 FaceX-Zoo 전체 training에 포함된다.

또한 `research/protocols/open_set.py::build_survface_matched_calibration_protocol`은 `protocol_role=training`을 모두 모아 gallery를 뽑는다. 기존 `development`와 `calibration`을 후보 단계에서 구분하지 않는다. 따라서 FaceX-Zoo train list만 바꾸고 이 함수를 그대로 호출하면 이번 권고 역할 배치를 보장할 수 없다.

적용 시 최소한 다음 연결이 필요하다. 이 목록은 **후속 구현 조건**이며 이번 분할 보고서에서 적용했다는 뜻이 아니다.

1. FaceX-Zoo에는 기존 UCFace 전체 training 프로토콜과 별도의 protocol namespace를 만든다. 새 train manifest/list, 4,255 class head, split-policy ID와 역할별 hash를 기록하고 기존 완료 checkpoint를 덮어쓰지 않는다.
2. ronbun에는 gallery 후보를 `development`, 비등록자 후보를 `calibration`으로 제한하는 명시적인 protocol policy/helper가 필요하다. 두 집합의 identity disjointness를 검사하고, 선택되지 않은 development 1,255명을 비등록자 probe로 자동 편입하지 않는다.
3. `research/experiments/fiqa_threshold_calibration.py`의 SurvFace calibration 생성과 `research/experiments/survface_compression.py::survface_watchlist_fit_image_paths` 양쪽에서 같은 역할 manifest를 사용한다. 현재 압축기는 training-derived gallery 이미지로 학습하므로 새 권고의 별도 PQ-development와 다르다.
4. export에 사용한 training identity hash와 calibration의 제외 ID 목록을 교차 검증한다. ModelSpec의 차원만 1024로 바뀌었다고 분할까지 올바른 것은 아니다. parent checkpoint·전처리·FR seed·PQ seed·split seed·score space도 기록한다.
5. test를 그대로 유지했는지 identity·이미지·파일 hash로 검증하고 새 namespace에서 embeddings → PQ → calibration → test를 실행한다. 학습 split이 바뀐 기존 5,319명 모델의 embeddings와 보정 artifact는 재사용하지 않는다.

실행 시작 조건은 SCFace 데이터 확보, 모델 export 완료, 입력의 실제 모델 UID·차원·전처리 일치, 데이터 역할 검증이다. 현재 이 보고서 자체는 모델 학습·내보내기·임베딩·최종 평가의 완료 증거가 아니다.
