## 배경과 유지한 결정

20261023.md의 저장소 독립성, 1024D FR, 데이터 역할, 점수 공간과 평가 지표를 유지한다.
교차분석과 현재 소스에서 모델 선택, 입력 재사용, 코드 출처, 노트북 설정 전달 결함을 확인했다.
FaceX-Zoo는 모델 생산, ronbun은 파일로 전달받은 모델의 활용 실험을 담당한다.
두 저장소의 Git 이력·실행 환경을 합치거나 상대 저장소 Python을 runtime import하지 않는다.
현행 분할을 최적 비율 또는 UCFace와 성능이 같은 조건으로 주장하지 않는다.

## 구현 변경과 데이터 흐름

- ronbun은 선택한 평가 데이터셋마다 적용할 모델이 있는지 먼저 확인한다. 불필요한 모델은
  이번 작업에서 제외하되, LFW/RFW만 선택해도 각 모델의 외부 development 입력을 준비한다.
- 입력 cache 재사용은 현재 원본 바이트와 완료 ledger를 전수 대조한다. 의도적인 원본 교체는
  새 output_root에서 수행하고 기존 완료 cache는 보존한다. 고정 artifact 읽기는 원본 파일의
  현재 존재 여부와 분리하며, artifact manifest/hash를 검증한다.
- source_fingerprints.py는 local Python import 의존성을 재귀 추적하고 상대 경로별 SHA-256을
  기록한다. 동적으로 선택하는 FaceX loader도 명시적으로 포함한다. AST 해석 캐시는 정확한
  소스 바이트로 구분하여 같은 프로세스 안의 파일 변경을 숨기지 않는다. package initializer를
  포함하므로 실행에 직접 쓰지 않은 코드 변경에도 보수적으로 새 UID가 생길 수 있다.
- CR-FIQA 결과는 population·전처리·품질 checkpoint·코드가 같은 경우 quality/에서 공유한다.
  FR embedding/raw_norm/codec은 모델별로 유지한다. quality cache의 파일 hash와 이미지 바이트
  hash를 검증하고 완료 입력만 공유 cache로 게시한다. TinyFace/SCFace rank 및 codec 준비만
  수행하는 입력은 품질 추론을 생략한다. manifest의 source=not_required와 None 반환으로
  품질이 계산되지 않았음을 명시한다. raw_norm을 선택한 실험은 모델 간 품질을 공유하지 않는다.
- RFW tar 입력은 archive 순서로 stream을 읽고 TarInfo로 추출한다. 이름 목록 선형 탐색과
  최초 전체 member 탐색을 없앤다. 역방향 요청에는 명시적으로 새 stream을 연다.
- FaceX 03/04는 00의 저장된 HEADS·HEAD_PARAMETERS를 유지한다. 새 campaign의 부모 준비와
  학습을 생략할 수 있다는 과거 안내를 수정한다. ronbun legacy 56개를 보존하고 현재 4개 순차
  노트북 안내와 구분한다.

## 남겨 둔 판단과 한계

FaceX 학습/export 전 전수 SHA-256·decode 검증은 유지한다. 이를 캠페인 1회로 줄이는 정책은
불변 데이터 스냅샷·보호 방식·추가 저장 공간을 함께 설계해야 하므로 다음 질문 세션의 선택지다.
단순히 verify_images=False로 바꾸지 않는다. 전체 실행 시간 절감률은 실측하지 않았다.
SETTINGS_PATH는 각 notebook에서 같은 명시적 파일을 선택한다. 자동 최신 선택을 도입하지 않았다.
현재 모델 미등록/새 namespace 준비 미완료와 분할 최적성·부모 identity overlap·작은 safety tail
표본 문제는 이 코드 수정으로 해결되었다고 주장하지 않는다.
기존 ArcFace/MagFace target cosine 경계의 sqrt gradient 특이점도 유지된다. 기존 경계 테스트의
통과는 이 한계를 검증하는 것이며 전 입력 NaN 안전성을 뜻하지 않는다. 안정화 수식 변경은
새 학습 recipe와 provenance가 필요한 별도 결정으로 보고서의 후속 선택지에 남긴다.
