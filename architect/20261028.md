# 2026-10-28 KST — 외부 공용 데이터·모델 저장소

상태: 구현됨. 코드·manifest·소규모 검증은 publish/외부저장소_전환검증_20261028_v1.md에 기록한다.
정식 학습·전체 입력 추출·성능 평가는 수행하지 않았다.

## 배경과 유지한 결정

사용자가 F:/face_datasets와 F:/models를 지정했다. 20261024/20261025의 두 저장소 독립성,
1024D 실험, 고정 identity 역할, score-space 구분, 단계적 실험, target-only 경계 정책을 유지한다.
FaceX-Zoo 과거 fine-tune checkpoint는 실패 조건의 기록용 자료로 보존하며 새 run에서 선택하지 않는다.

## 구조와 흐름

- ronbun의 migration 명령만 명시적인 이전 저장소 경로를 읽는다. raw 이미지를 재복제하거나 삭제하지 않는다.
- roles/train-list의 바이트와 hash는 유지하고, 새 portable v2 protocol에서 상대 경로를 해석한다.
  양 저장소는 공유 protocol을 독립적으로 읽으며 서로의 Python 모듈을 runtime import하지 않는다.
- LFW/RFW의 신규 외부 manifest는 data/raw 접두사만 데이터 루트 기준으로 바꾼다. pair 행은 그대로 복사한다.
- FaceX-Zoo VGGFace2 metadata/archive root와 extracted image root를 분리한다. 후처리 이미지는 각 dataset의
  processed 아래 새 namespace에, 모델/checkpoint/export는 model root의 facex 아래에 생성한다.
- root 환경변수는 FACE_DATASET_ROOT/ FACE_MODEL_ROOT다. 기존 완료 run/spec/settings를 소급 수정하지 않는다.
- 외부 모델의 단순 보관은 1024D export 등록을 뜻하지 않는다. 모델 UID/메타데이터/전처리 검증을 유지한다.
- 생성 시 README.md와 derivation.json을 같은 관측 기록으로 작성한다. 공유 결과는 목적지 lock과 완료 표시를 사용한다.
- ronbun 01의 미사용 EXECUTE/REPORT_DIR 등을 제거하고 04의 REPORT_DIR 역할을 명확히 한다.

## 보존과 재실행

원본/이전 결과는 보존한다. path/code fingerprint가 달라지는 입력·결과는 새 UID로 계산하며 기존 완료 cache에
강제로 연결하지 않는다. 공유 전처리/데이터/model은 KEEP_RAW_RESULTS 삭제 대상이 아니다. 실험 상세 보존 정책은 유지한다.
기존 01 출력은 tmp/shared_storage_migration/original_01_data_preparation.ipynb에 보관 후 새 노트북 출력을 비운다.
환경 및 모듈 변경 후 커널을 재시작한다. Linux에서 경로 변경과 CPU 검증을 지원하지만 A100 실제 학습 검증은 별도다.

## 검증 기준과 범위

고정 역할·pair 내용/hash·인물 분리를 유지하고, 다른 위치로 복사한 fixture에서도 조회해야 한다.
부적절한 root/path·변조·동시 생성·미완료 artifact를 차단해야 한다. 작은 이미지의 resize 결과가 동일해야 한다.
9개 활성 notebook을 새 커널에서 기본 계획 모드로 실행하고, 정식 학습/임베딩/DB 실행은 시작하지 않는다.
모델 미등록, 새 parent/학습/export 필요, 통계적 tail 표본 수, 기존 parent 인물 overlap 한계는 이 경로 변경의 해결 대상이 아니다.
