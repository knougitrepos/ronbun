RESUME_CHECKPOINTS에는 위의 정확한 파일을 지정했다. 커널 재시작 후 02 첫 셀부터 실행하면 된다.

강제 검증은 변경된 이미지의 새 hash를 승인하는 기능이 아니다. 완료 후 False로 되돌린다.

## 검증 기록의 의미

기존 전수 검증 기록이 report/목록/manifest/정책/검증 코드/라이브러리와 정확히 일치함을 확인해,
다음 새 기록으로 출처를 연결했다. 기존 receipt와 원본 전처리 결과는 변경하지 않았다.

`F:/face_datasets/VGGFace2/processed/shared_v1_boundary_mobilefacenet/verification_cache/immutable_v1/297c45e278648760fdc8ac0c8e70b49192786001bc4ef7c2853ad4ab6fded139.json`

3,141,890장 데이터에 대해 실제 재사용 호출은 각각 5.094초, 5.098초였다. 이미지별 검증/
mapping 순회 호출을 금지한 점검에서 성공했고, `image_hashes_checked=0`, `images_decoded=0`을
기록했다. 이 시간은 검증 기록 재사용 구간이며 학습 시작 전체 소요시간이 아니다.

상세 JSON의 주요 항목:

| 항목 | 의미 |
|---|---|
| status / verified_images | 최초 전체 검증의 완료 여부와 이미지 수 |
| contract / source_receipt | report·정책·목록과 이전 검증의 출처 |
| payload_sha256 | 기록 자체의 무결성 값 |
| reused_full_verification | 이번 호출이 과거 완료 기록을 재사용했는지 |
| image_hashes_checked / images_decoded | 이번 호출에서 실제 검사한 수; 재사용이면 0 |
| limitation | 사용자가 데이터를 변경하지 않는다는 전제와 탐지 한계 |

새 receipt는 준비 데이터 cache다. KEEP_RAW_RESULTS와 무관하게 보존하며 외부 dataset root에
남긴다. 원본/전처리 이미지·대용량 manifest는 Git 추적 대상으로 추가하지 않았다.
