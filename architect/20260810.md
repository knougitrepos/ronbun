# 2026-08-10 Architecture Decisions

## 03:32 KST — EdgeFace Grad-CAM 7×7 공통 격자 전환

- 작성일: 2026-08-10 03:32 KST
- 상태: 구현됨, 실제 체크포인트 smoke 검증됨, 전체 데이터셋 재실행 미완료

### 변경 배경

2026-08-09 기록은 EdgeFace의 Grad-CAM target layer를
`model.stages.3.blocks.2.convs.2`로 지정했다. 실제 EdgeFace-XS checkpoint에서 이
계층의 출력은 3×3이었다. SurvFace 전체 실행의 landmark face mask를 3×3으로
내리는 과정에서 유효한 원본 face mask 한 건이 완전히 사라져 Phase 02가
fail-closed로 중단되었다. 기존 ArcFace, AdaFace, MagFace saliency artifact는 모두
7×7이므로 3×3만을 위한 별도 mask 보정은 모델 간 비교 조건과 코드 경로를
불필요하게 분기한다.

### 결정 내용

- 2026-08-09의 EdgeFace target-layer 선택만 폐기하고, checkpoint·전처리·512D
  embedding 계약은 유지한다.
- EdgeFace target layer는 가장 깊은 7×7 convolution인
  `model.stages.2.blocks.8.convs.1`로 변경한다.
- 공통 Grad-CAM 공간 계약을 `expected_heatmap_size: [7, 7]`로 명시한다.
- smoke validation은 선택 계층의 실제 `[B,C,H,W]` 출력을 hook으로 확인하고,
  공간 크기가 7×7이 아니면 실행 전에 중단한다.
- population Grad-CAM도 첫 batch에서 실제 heatmap 크기를 다시 확인해 잘못된
  registry/config 조합을 fail-closed로 막는다.
- `model_uid`는 checkpoint·전처리 identity이므로 target-layer 변경만으로 바꾸지
  않는다. 대신 같은 `model_uid`의 분석 target 개정은 전체 ModelSpec digest를
  붙인 별도 immutable registry 파일로 보존하며, profile 선택 시 target layer까지
  일치시킨다.

### 현재 구현과 목표 구조의 차이

- 변경 전: EdgeFace만 3×3, 나머지 세 모델은 7×7이며 mask resize가 native CAM
  크기에 따라 달라졌다.
- 변경 후: 네 모델 모두 7×7 saliency grid를 사용하고 공통 mask·집계 경로를
  유지한다.
- 아직 남은 차이: 서로 다른 backbone의 7×7 계층은 의미적 깊이와 receptive
  field가 완전히 동일하지 않다. 이번 결정은 공간 해상도 통일이며 계층 의미의
  인과적 동등성을 주장하지 않는다.

### 데이터·모듈 흐름

`step2_pytorch_gradcam.yaml profile` → `ModelSpec target_layer` → profile-aware
immutable registry 선택 → model smoke의 target output 7×7 검증 → run config/source
freeze → population Grad-CAM 첫 batch 7×7 검증 → 7×7 landmark region mask slice →
saliency feature 및 compression join.

### 영향 범위

- 설정: `configs/experiments/step2_pytorch_gradcam.yaml`
- registry/선택: `research/embeddings/manifests.py`
- 공통 준비/smoke: `research/experiments/pipeline_runner.py`
- Step 4 실행: `research/experiments/step4_workflow.py`
- Grad-CAM 추출: `research/explainability/gradcam/extraction.py`
- 노트북: `notebooks/common/model_preparation/*`,
  `notebooks/common/orchestration/00_batch_experiment_runner.ipynb`
- artifact: 기존 3×3 EdgeFace saliency 조건과 새 7×7 조건은 혼합하거나 재사용하지
  않는다. `saliency_spec_uid`에는 target layer가 포함되어 서로 구분된다.

### 재실행 범위

- 기존 ArcFace/AdaFace/MagFace 완료 run은 target과 7×7 계약이 바뀌지 않으므로
  이 결정만을 이유로 무효화하지 않는다.
- 실패한 EdgeFace SurvFace run의 Phase 01 embedding은 checkpoint 관점에서는
  동일하지만, frozen run config가 이전 target을 가리키므로 새 7×7 실험으로
  재개하지 않는다.
- EdgeFace는 새 ModelSpec registry/smoke를 만든 뒤 dataset별 새 run을 Phase 00부터
  시작한다. 이전 incomplete run은 삭제하지 않고 보존하며, active-run 선택은
  사용자가 명시적으로 정리하거나 교체해야 한다.

### 검증 근거 및 기준

- 공식 EdgeFace-XS gamma=0.6 checkpoint, CUDA, 고정 smoke 이미지 8장:
  - 새 `model.stages.2.blocks.8.convs.1`: heatmap `(8,7,7)`, 유효 8/8,
    gradient L2 범위 약 4.409–9.928.
  - 이전 `model.stages.3.blocks.2.convs.2`: heatmap `(8,3,3)`, 유효 5/8.
- unit/integration 기준:
  - 같은 checkpoint/model_uid에서 서로 다른 target manifest를 immutable하게
    병존시키고 profile target으로 정확히 선택한다.
  - 공통 격자가 아닌 heatmap은 첫 Grad-CAM batch에서 예외가 발생한다.
  - 전체 관련 pytest가 통과한다.
- 전체 실험 완료 기준: EdgeFace의 LFW, SurvFace, RFW-Custom 새 run이 각각
  `COMPLETED`이며 phase/artifact manifest와 7×7 saliency shape가 일치해야 한다.

### 미해결 위험

- 더 이른 계층으로 이동하면 공간 세부 정보는 늘지만 최종 identity decision에
  대한 의미적 근접성은 낮아질 수 있다. faithfulness 및 stability 결과를 기존
  모델과 함께 보고 해석해야 한다.
- 7×7은 비교 가능한 격자를 제공할 뿐 backbone 간 receptive field와 channel
  semantics를 동일하게 만들지는 않는다.
- 전체 SurvFace Grad-CAM 비용은 그대로 크므로 실제 full run 완료 전에는 수정의
  데이터셋 전체 성공을 주장하지 않는다.
