## 결정과 데이터 흐름

완료 source run + condition(v2) → frozen model/정렬 이미지/landmark/embedding/protocol 검증 → split별 원본 gallery top1 복원 → calibration Grad-CAM 특징 생성 + calibration 사전 선정 표본의 가림 실험 → 기존 test 특징 검증·재사용 → 입력 파일·manifest 저장 → coverage/faithfulness gate → 통과할 때만 Continuous FIQA 기준 및 saliency 추가 비교 → 단일 split·20개 split 저장.

1. 신규 `research/experiments/saliency_calibration_inputs.py`가 생성 책임을 갖고, 02 노트북은 첫 셀 설정과 실행·표시를 담당한다. 기존 00/01, batch runner, DB, checkpoint, 완료 run과 기존 실험 결과는 변경하지 않는다.
2. CUDA를 요구한다. 실제 device/torch/CUDA runtime을 기록하고 CPU로 조용히 전환하지 않는다. 기본 Grad-CAM batch 4, 처리 묶음 128, 가림 inference batch 32이다. CUDA/PyTorch 패키지를 업그레이드하지 않는다.
3. 기존 calibration seed와 gallery identity 수로 calibration protocol을 복원한다. Test는 official protocol을 사용한다. Query ID·identity·정렬 hash, source/freeze/selected/prepared/model/checkpoint/preprocessing/landmark lineage가 다르면 중단한다.
4. Grad-CAM target은 각 split의 **원본 cosine top1 gallery template**이다. 정답 label이나 ADC score를 gradient target으로 쓰지 않는다. 생성 forward와 frozen embedding cosine 및 target score를 대조한다. 기존 dense landmark 영역 정의로 `outside_face_attention`, `saliency_entropy`를 계산한다.
5. Test 특징은 기본적으로 기존 population artifact를 재사용한다. 파일 hash, 모델·전처리·target layer·region mask, 각 query의 공식 gallery top1 identity와 score를 대조한다. 불일치는 자동 무시하지 않는다. `REUSE_TEST_SALIENCY=False`는 test도 같은 방식으로 새로 생성한다.
6. 가림 실험은 **calibration에서 사전 고정한 최대 10,000장**만 수행한다. Test와 sample ID/identity/정렬 이미지 내용이 겹치는 행을 제외하고 `SHA256(seed:sample_id)` 순서로 선택한다. 기본 seed 8972, 가림 비율 0.1, Random 5회이다. `FAITHFULNESS_MAXIMUM_SAMPLES=None`이면 적격 calibration 전체를 사용한다. 결과를 보고 표본·seed·가림 비율을 바꿔 gate를 통과시키지 않는다.
7. High/Low/Random은 기존 가림 구현을 재사용하며 동일한 unoccluded top1 template을 고정한다. Score drop은 threshold 입력이 아니다. Calibration-fit/safety 및 test의 saliency 특징은 모든 query를 유지하며, 미생성·무효 특징을 임의 대치하거나 평가 cohort에서 삭제하지 않는다.
8. 저장된 실제 faithfulness 행으로 identity-cluster 95% CI를 계산한다(기본 2,000회). 소비할 때도 membership/identity/alignment/split, paired gain 수식, bootstrap 설정·identity 수·CI를 재검산한다. High−Low와 High−Random 두 CI 하한이 양수가 아니면 비교를 차단한다. 일부 target 값이 비어 있는 경우도 차단한다.
9. `max_queries_per_split`은 코드 검증용 제한이며 생성 manifest에 `smoke_only=True`를 기록한다. 제한된 입력은 정식 비교를 승인할 수 없다.
10. 01 test 결과를 참고한 사용자의 기준 선택을 반영해 기본값은 `continuous_fiqa`이다. 자동 test 기반 최적 선택은 하지 않지만, 현재 02의 해석은 **01-test-informed exploratory**임을 기록한다. 원본 gallery가 필요한 offline 추가정보 분석이며 압축 DB만으로 배포 가능함, 압축오차의 인과효과 또는 formal FPIR 보장을 주장하지 않는다.

## 사용자 실행과 재실행 범위

02 첫 셀에서 `SOURCE_MODEL`을 확인하고 **Kernel Restart → Run All**한다. 기본 `BUILD_SALIENCY_INPUTS`, 단일 split RUN/WRITE, 분할 안정성 RUN/WRITE는 모두 True이다. 자료 생성 → 검증 → 통과 시 비교·저장까지 이어진다. 최초 생성은 장시간 걸릴 수 있으며 정식 소요 시간은 아직 측정하지 않았다.

재실행 시 생성 플래그를 그대로 두면 같은 완료 묶음을 검증해 재사용한다. 설정·코드가 달라 UID가 달라지면 별도 입력을 만든다. 명시적 기존 입력 경로를 쓸 때는 BUILD=False와 두 디렉터리를 함께 지정한다. BUILD=False 및 두 경로 None은 기존 자료 진단 경로다.

Gate 실패도 가림 원자료·요약·manifest는 남는다. 이때 단일/분할 안정성의 성능 결과는 생성하지 않는다. 00/01 또는 기본 임베딩 압축 실험을 다시 실행할 필요는 없다.
