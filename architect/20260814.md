## 10:00 KST — 보고서의 누락된 TPIR20 v5 파생 artifact 생성·재개

- 작성일: 2026-08-14 (KST)
- 상태: 구현됨, ArcFace/LFW 실제 완료 run과 output-free 보고서 실행으로 검증됨
- 이전 결정과의 관계: `architect/20260813.md`의 TPIR20 v5 계약과 완료 run 불변성은 유지한다. 다만 “보고서 실행 전에 v5 통합 postprocessing을 별도로 완료해야 한다”는 실행 순서를 보완해, 보고서가 명시적 설정 아래 동일한 canonical producer를 호출할 수 있게 한다.

### 변경 배경

이전 Step 4 완료 run을 선택해 `00_cross_dataset_results.ipynb`를 직접 실행하면 v4 artifact만 존재하는 경우 `search_space_v5_tpir20_multi_fpir` 누락으로 즉시 중단됐다. 오류 메시지는 통합 postprocessing을 먼저 실행하라고 안내했지만, 직접 실행 사용자가 어떤 producer와 설정을 호출해야 하는지 노트북 안에서 확인하거나 재개할 수 없었다. 또한 TPIR20 retention 검증에 사용하는 `numpy` import가 빠져 v5 생성 후 다음 집계 셀에서 `NameError`가 발생했다.

### 결정 내용

1. 보고서 직접 실행의 기본값은 `GENERATE_MISSING_TPIR20_ARTIFACTS=True`로 한다.
2. 선택한 완료 run의 v5 merged manifest가 없을 때만 `scripts.refresh_step4_search_spaces.refresh`를 PCA와 PQ 두 family, FPIR `(0.01, 0.05, 0.10, 0.20, 0.30)`으로 호출한다.
3. 생성 위치는 완료 run 밖의 `results/paper/<dataset>/<run_id>/search_space_v5_tpir20_multi_fpir`로 고정한다. 완료 run과 기존 v4 artifact는 수정하지 않는다.
4. family manifest가 이미 있으면 canonical producer의 기존 재개 계약을 사용한다. 두 family가 모두 끝나지 않아 merged manifest가 없으면 상태를 표시하고 실패한다.
5. 배치 통합 후처리는 보고서보다 먼저 v5를 생성하므로 injected parameter cell에서 `GENERATE_MISSING_TPIR20_ARTIFACTS=False`를 명시한다.
6. `REBUILD_DATASET_SUMMARIES`는 legacy summary 전용으로 남기고 TPIR20 v5 생성과 분리한다.
7. 보고서 설정 셀에 `import numpy as np`를 추가해 retention reconciliation 검증이 독립 커널에서도 실행되게 한다.

### 현재 구현과 목표 구조의 차이

- 구현됨: 직접 보고서 실행의 missing-v5 감지, canonical PCA/PQ 생성 또는 재개, merged manifest 확인, 구체적 복구 메시지, batch parameter 분리, NumPy import.
- 구현됨: source run manifest와 v5 family/output SHA-256 검증, 5-point FPIR coverage 검증, output-free end-to-end 보고서 실행.
- 목표 유지: 논문 최종 artifact는 clean evaluator commit에서 다시 생성해야 한다. 현재 실제 smoke artifact는 코드가 커밋 전이므로 `exploratory_dirty_evaluator`이며 paper-eligible이 아니다.

### 데이터·모듈 흐름

```text
explicit completed Step 4 run selection
  -> report checks v5 merged manifest
  -> present: validate and reuse
  -> missing + explicit generation enabled
       -> canonical refresh(PCA, PQ, five FPIR points)
       -> reuse completed family manifests / resume missing family
       -> publish merged v5 compact manifest
  -> validate source identity, SHA-256, schema, FPIR grid
  -> calculate TPIR20, realized FPIR, thresholds, retention, Rank-1 DIR
  -> optional common report write
```

2. 보고서 설정 셀에서 모델·dataset·완료 run을 명시적으로 선택한다.
3. 과거 run에 v5가 없으면 `GENERATE_MISSING_TPIR20_ARTIFACTS=True`로 실행한다. 이미 완료된 family는 재사용된다.
4. v5가 완성된 뒤에는 같은 설정에서 자동으로 검증·재사용한다.

- SurvFace는 원본 ledger가 크므로 첫 v5 생성 시간이 길다. 진행 로그와 family-level 재개를 사용하되 완료 전에 common report 수치를 주장하지 않는다.
- LFW calibration non-mated 수가 작아 서로 다른 목표 FPIR가 같은 경험적 threshold로 선택될 수 있다. 이는 구현 오류가 아니며 realized FPIR와 false-accept 분자·분모를 함께 해석해야 한다.
- 현재 ArcFace/LFW smoke는 dirty evaluator에서 생성돼 논문 최종 근거로 사용할 수 없다. clean commit 재생성이 필요하다.

## 10:30 KST — 선택적 faithfulness 누락과 필수 결과의 분리

- 작성일: 2026-08-14 (KST)
- 상태: 구현됨, 단위 테스트와 ArcFace/LFW output-free 보고서 실행으로 검증됨
- 이전 결정과의 관계: 같은 문서의 TPIR20 v5 생성·재개 계약은 유지한다. Faithfulness는 TPIR20, 압축, 검색 성능과 독립적인 선택 부록이라는 기존 경계를 실행 정책에도 반영한다.

### 변경 배경과 결정

선택한 완료 run에 `faithfulness_v2_n10000/manifest.json`이 없으면 `INCLUDE_FAITHFULNESS=True`인 보고서가 TPIR20 계산을 모두 끝낸 뒤에도 중단됐다. 이 누락은 TPIR20 v5 또는 압축·검색 artifact의 손상이 아니므로 공통 보고서 전체를 무효화해서는 안 된다.

- canonical loader에 `missing_policy={"raise", "omit"}`를 추가하고 기본값은 기존과 같은 `raise`로 유지한다.
- 공통 보고서는 선택 부록에만 `missing_policy="omit"`를 명시한다.
- `omit`은 dataset별 `manifest.json`이 물리적으로 없을 때만 허용한다. manifest가 존재하면 artifact type, schema, dataset/run/model identity, sample 수, output byte 수와 SHA-256 검증을 전부 유지한다.
- 생략된 dataset과 예상 manifest 경로는 `missing_manifests` 및 notebook 경고 표로 노출한다.
- Faithfulness가 생략돼도 TPIR20, realized FPIR, threshold, retention, Rank-1 DIR과 압축 결과는 계속 계산한다.

### 영향 범위와 검증

- canonical loader: `research/evaluation/faithfulness_artifacts.py`
- 보고서: `notebooks/common/reports/00_cross_dataset_results.ipynb`
- 테스트: `tests/research/test_faithfulness_artifacts.py`, `tests/research/test_notebook_layout.py`
- 실제 ArcFace/LFW run `20260810-R001-e9b2f0fd`는 faithfulness manifest가 없음을 확인했다.
- 누락 생략, 기존 artifact 로드, 잘못된 기존 manifest의 fail-closed, 잘못된 policy 거부 테스트를 통과했다.
- `INCLUDE_FAITHFULNESS=True`, `WRITE_OUTPUTS=False`의 동일 ArcFace/LFW 보고서가 `validated_not_written`으로 끝까지 완료됐다.

### 미해결 위험과 재실행 범위

- 생략은 해당 run에 faithfulness 근거가 없다는 뜻이며 성능이 나쁘거나 좋다는 뜻이 아니다. 논문 표에는 faithfulness 미측정 상태를 명시해야 한다.
- Faithfulness가 논문 필수 분석으로 승격되면 별도 생성 단계를 완료하고 기본 `missing_policy="raise"`로 검증해야 한다.
- Python loader가 변경됐으므로 현재 Jupyter kernel을 재시작한 뒤 보고서를 위에서부터 실행한다. embedding, Grad-CAM, TPIR20 v5는 재실행할 필요가 없다.

## 11:30 KST — TPIR20 retention의 count 기반 compact 직렬화 검증

- 작성일: 2026-08-14 (KST)
- 상태: 구현됨, 실제 ArcFace/SurvFace PCA·PQ family 재사용 병합과 output-free 보고서로 검증됨
- 이전 결정과의 관계: TPIR20 retention 정의 `compressed/origin`은 바꾸지 않는다. 검증 입력을 12자리로 각각 반올림된 rate의 재나눗셈에서 integer 성공 건수·분모로 변경한다.

### 변경 배경

ArcFace/SurvFace v5의 PCA와 PQ family 계산 및 SHA manifest는 완료됐지만 merged artifact 생성 시 `TPIR20 retention drifted`가 발생했다. Origin TPIR20이 0.0976%처럼 작은 행에서는 retention이 최대 26.93배가 되어, `%.12g`로 독립 직렬화된 Origin·compressed rate를 다시 나누면 절대 오차가 PCA `1.66e-11`, PQ `7.17e-11`까지 증폭됐다. 모든 행을 integer TPIR20 성공 건수와 분모에서 재계산해 같은 `%.12g` 형식으로 직렬화하면 저장된 retention과 정확히 일치했다.

### 결정 내용

- canonical `rate_ratio_matches_counts_or_compact_csv`를 추가한다.
- retention은 `(compressed_count/compressed_denominator) / (origin_count/origin_denominator)`로 재구성한다.
- full-precision producer 행과 `%.12g` compact CSV 행을 모두 허용하되, count 범위·정수성·양의 분모를 fail-closed로 검증한다.
- Origin 성공 건수가 0이면 retention과 기대값은 모두 결측이어야 한다.
- producer 병합, cross-model matrix, common report가 같은 canonical 검증 함수를 사용한다.
- 단순 절대 허용 오차 확대는 사용하지 않는다. `1e-6` retention 변조는 계속 거부한다.

### 영향 범위

- metric 계약: `research/evaluation/metrics.py`, `research/evaluation/__init__.py`
- v5 producer: `scripts/refresh_step4_search_spaces.py`
- 4×3 matrix: `research/experiments/cross_model_matrix.py`
- 보고서: `notebooks/common/reports/00_cross_dataset_results.ipynb`
- 테스트: `tests/research/test_metrics.py`, `tests/research/test_refresh_step4_search_spaces.py`, `tests/research/test_cross_model_matrix.py`, `tests/research/test_notebook_layout.py`
- 완료 Step 4 run과 PCA/PQ family output: 변경·재계산 없음

### 검증 및 재실행 범위

- 관련 metric, v5 producer, matrix, notebook 계약 테스트 20개와 Ruff를 통과했다.
- ArcFace/SurvFace run `20260810-R001-5d742943`의 PCA 100행과 PQ 75행을 count 기반으로 검증했다.
- 기존 PCA/PQ family manifest를 `already_completed`로 재사용하고 merged v5 compression 10행·retrieval 175행을 생성했다.
- `INCLUDE_FAITHFULNESS=True`, `WRITE_OUTPUTS=False`의 동일 SurvFace 보고서가 `validated_not_written`으로 끝까지 완료됐다.
- 현재 Jupyter kernel을 재시작하고 보고서를 위에서부터 실행한다. 46만 이미지 embedding·PCA/PQ 검색은 재실행되지 않고 merged v5를 검증·재사용한다.

### 제한

- SurvFace FPIR 1%는 calibration 0.9994%였지만 held-out realized FPIR 1.2412%로 목표를 초과했다. 해당 operating point의 threshold-dependent 주장은 계속 보류한다.
- 현재 merged artifact는 dirty evaluator에서 생성돼 `exploratory_dirty_evaluator`, `derived_evaluation_paper_eligible=false`이다. 논문 최종 artifact는 clean commit에서 재생성해야 한다.
