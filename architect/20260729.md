# 2026-07-29 Architecture 변경 기록

## 01:00 KST — SurvFace detector-free ArcFace embedding 추출 교정

### 문서 정보

- 작성일: 2026-07-29 01:00 KST
- 상태: **구현됨·실제 2표본 GPU smoke 검증됨, 전체 실험 미실행**
- 변경 관계: `architect/20260728.md`의 SurvFace
  `official_face_crop_resize` 결정을 임베딩 단계까지 일관되게 적용한다.

### 변경 배경

`01_official_arcface_embedding_extraction.ipynb`의 첫 실행은 batch commit 뒤
`ProgressReporter.milestone()`에 `processed`를 넘겨 `completed` 필수 인자가
없다는 `TypeError`로 중단됐다. 그러나 실패 attempt의 ledger를 확인한 결과
그 이전 256장도 모두 `no face detected`였다. 임베딩 단계가 원본 SurvFace
face crop을 다시 읽고 detection+recognition `FaceAnalysis`를 실행하고 있었기
때문이다. 이는 전처리 단계에서 detector를 제거한 2026-07-28 결정과 충돌하며,
그대로 진행하면 전체 463,341장 protocol coverage가 다시 훼손된다.

실패 run `20260729-R001-9d60c32a`의 A001에는 256개 실패 ledger가 남았고,
해당 run의 `embedding_512` DB 행은 0개다. 전역 `images` 행은 재사용 가능한
원본 이미지 메타데이터이므로 삭제 대상이 아니다.

### 결정 내용

1. 진행률 호출은 `completed=counts["processed"]`로 교정한다.
2. SurvFace 임베딩 모델 입력은 완료된
   `data/interim/step4/survface/aligned_112/aligned_faces.npy`로 고정한다.
3. 입력 계약은 RGB uint8 NHWC 112×112이며 `aligned_index.csv`의
   `image_id`/`aligned_face_index` 일대일 관계를 검증한다.
4. recognition ONNX `w600k_r50.onnx`만 직접 로드한다. 얼굴 detector 추론은
   실행하지 않는다.
5. 한 배치의 미저장 표본을 모아 GPU recognition을 실행한 뒤 DB에 저장한다.
   `BATCH_SIZE=256`은 모델 배치와 DB commit/ledger flush 경계 모두에 사용한다.
6. DB embedding parameters와 ledger에 model hash, aligned bundle manifest
   hash, aligned row/hash, preprocessing mode와
   `detector_inference=false`를 기록한다.
7. run freeze는 공식 protocol뿐 아니라 aligned manifest/index/_SUCCESS와
   recognition ONNX hash도 입력으로 등록한다.
8. 기존 R001은 실패 근거로 보존한다. 코드·설정·입력 계약이 달라졌으므로
   `00_official_protocol_and_run_freeze.ipynb`에서 새 run을 만든 뒤 01을
   실행한다.

### 데이터·모듈 흐름

```text
training + official manifests
  -> sample_id one-to-one join with aligned_index
  -> aligned_faces.npy RGB uint8 [N,112,112,3]
  -> w600k_r50 recognition-only batch inference on CUDA
  -> L2-normalized origin_512
  -> PostgreSQL embedding_512 + batch ledger
  -> about 10% progress milestones
```

### 현재 구현과 목표 구조의 차이

- 구현됨:
  - recognition-only aligned batch extractor
  - GPU primary-provider fail-fast
  - full aligned coverage/order validation
  - model/aligned lineage freeze
  - restart 시 같은 run의 기존 embedding skip
- 검증됨:
  - 실제 aligned crop 2장 → `(2, 512)` float32
  - 모든 값 유한, L2 norm 약 1.0
  - active provider의 첫 항목이 `CUDAExecutionProvider`
  - 관련 단위·노트북 계약 테스트 통과
- 미검증:
  - 전체 463,341장 처리량과 DB insert 완료
  - 전체 실행의 `failed=0`
  - role별 embedding coverage

### 재실행 범위

Codex는 전체 임베딩 실험을 실행하지 않는다. 사용자는 변경사항을 검토·commit한
뒤 다음 순서로 실행한다.

1. `00_official_protocol_and_run_freeze.ipynb` Kernel Restart → Run All
2. 결과가 새 run ID이고 aligned/model hash가 기록됐는지 확인
3. `01_official_arcface_embedding_extraction.ipynb` Kernel Restart → Run All
4. 약 10% 단위 로그와 `failed` 수를 관찰
5. 완료 후 `full_protocol_complete=true`, `failed=0` 확인

기존 R001 artifact와 `images` 테이블은 삭제하지 않는다.

### 미해결 위험

1. Buffalo-L의 `w600k_r50.onnx`와 Step 4 PyTorch Grad-CAM 모델이 서로 다른
   checkpoint이면 임베딩 검색과 saliency 설명의 모델 정합성이 깨질 수 있다.
   후속 단계 전에 model UID/checkpoint hash를 비교하여 같은 모델 계보인지
   확인해야 한다.
2. ONNX 모델은 동적 batch를 실행하지만 output metadata가 batch 1로 표시되는
   경고가 발생할 수 있다. 로그 severity를 조정했으며 실제 배치 출력 shape를
   검증했지만, 첫 256장 실행에서 처리량과 VRAM을 확인해야 한다.
3. R001은 실패 run으로 남아 있으므로 후속 단계가
   `runs/survface/active_run.json`의 새 run만 사용하는지 확인해야 한다.

## 01:04 KST — DB 임베딩과 Grad-CAM의 ArcFace checkpoint 통일

### 문서 정보

- 작성일: 2026-07-29 01:04 KST
- 상태: **구현됨·실제 64표본 CUDA smoke 검증됨, 전체 실험 미실행**
- 변경 관계: 위 01:00 절의 detector-free aligned 입력 결정은 유지한다.
  다만 `buffalo_l/w600k_r50.onnx`를 사용한다는 모델 결정은 폐기하고 이 절로
  대체한다.

### 변경 배경

01:00 설계를 추가 검토한 결과, DB 검색 벡터를 Buffalo-L R50 ONNX에서 만들고
후속 Grad-CAM을 등록된 MS1MV3 R100 PyTorch checkpoint에서 계산하면 서로 다른
모델의 saliency와 압축 오차를 결합하게 된다. 현재 연구는 landmark saliency와
동일 원본 임베딩의 압축 영향을 비교해야 하므로 이 구성은 타당하지 않다.

현재 저장소에는 다음 ModelSpec과 checkpoint가 이미 검증·등록돼 있다.

- model UID: `arcface-7972a704552df378345f`
- architecture: `iresnet100`
- training dataset: `ms1mv3`
- checkpoint SHA-256:
  `a566a62357f0c55b679d9ff2f022a294486568be0c00665d39029d0e46a8109b`
- preprocessing: RGB uint8 112×112, mean/std 127.5
- Grad-CAM target layer: `layer4.2.conv2`

### 결정 내용

1. SurvFace `origin_512` DB 임베딩은 위 ModelSpec으로 생성한다.
2. `create_pytorch_adapter_from_spec()`을 사용하여 Step 4 Grad-CAM과 같은
   model/preprocessing boundary를 공유한다.
3. 정식 실행 device는 `cuda`, batch size는 검증된 설정과 맞춘 64로 고정한다.
4. run freeze에 ModelSpec JSON과 checkpoint 파일 hash를 모두 등록한다.
5. DB parameters와 summary에 `model_uid`, `checkpoint_sha256`,
   `preprocess_hash`를 기록한다.
6. detector inference는 계속 금지하며 aligned RGB bundle을 직접 입력한다.
7. 01:00 절에서 검토했던 별도 ONNX aligned extractor와 해당 전용 테스트는
   최종 구현에 남기지 않고 기존 공통 PyTorch adapter와 ModelSpec 테스트를
   재사용한다.

### 교정된 데이터 흐름

```text
SurvFace aligned RGB 112×112
  -> registered arcface-7972... PyTorch adapter on CUDA
  -> raw norm + normalized origin_512
  -> DB compression/search
  -> same model UID/checkpoint/preprocess
  -> Grad-CAM landmark saliency
```

### 검증 결과

실제 SurvFace aligned 표본 64장을 DB 쓰기 없이 smoke 실행했다.

- device: `cuda`
- output: `(64, 512)` float32
- finite: true
- maximum unit-norm error: `5.960464477539063e-08`
- raw norm range: `11.0402555`–`24.8962021`
- 관련 테스트: 29개 통과
- Ruff 검사 통과

### 재실행 및 완료 기준

01:00 절과 동일하게 기존 R001은 보존하고 사용자가 00에서 새 run을 만든 뒤
01을 실행한다. 전체 결과의 embedding summary와 후속 Grad-CAM freeze에서
`model_uid`, `checkpoint_sha256`, `preprocess_hash` 세 값이 모두 같아야 한다.

### 남은 위험

전체 463,341장 처리량과 DB transaction 비용은 아직 측정하지 않았다. 첫 10%
로그 전이라도 CUDA OOM 또는 DB 오류가 발생하면 전체 run을 계속하지 말고 해당
attempt ledger와 phase manifest를 먼저 검사한다.
