# 2026-11-06 KST — 재개·입력 cache·threshold·결과 재사용의 검증 강화

상태: 구현됨·관련 회귀 및 실제 checkpoint 복원 검증됨. 정식 학습·실데이터 성능 평가는 미실행.

## 배경과 유지하는 결정

사용자가 추가 감사의 F1–F7 개선을 요청했다. 20261101의 학습 조건, 20261102의
이미지 전처리 복구, 20261104의 immutable 데이터 검증 기록 재사용을 유지한다.
FaceX-Zoo 학습/export와 ronbun 추출/보정/평가의 독립 경계도 유지한다.
원본·전처리 이미지, 기존 checkpoint, 완료 연구 결과는 변경하지 않는다.

## 결정과 영향 경로

- F1: 정식 학습 재개는 모델·optimizer·scheduler·RNG 필수 상태를 검사한다.
  현재 02의 이전 checkpoint와 정확히 검토한 소스 전이만 허용한다. 학습·데이터·모델
  설정 동일성 검사와 미등록 코드 거부는 유지하며 원래 checkpoint hash는 보존한다.
- F2: 중단된 입력 추출은 배치별 파생 배열과 원본 hash ledger의 무결성을 기록하고
  progress가 확정한 prefix만 검증·재사용한다. 검증 정보가 없는 legacy partial은
  fail-closed 처리한다. 완료 reader도 population.csv와 population_hash를 대조한다.
- F3: score >= threshold에서 허용 calibration 오인식률을 넘기지 않는 마지막
  수용집합의 다음 거부 score 바로 위 float64 경계를 사용한다. Global과 Continuous
  safety가 같은 공통 함수를 사용한다. 동점은 쪼개지 않는다. 경험적 규칙이며 test
  오류율 보장으로 해석하지 않는다. 기존 학습 loss·순위·모델 가중치는 바뀌지 않는다.
- F4: 설정·실행 인자에서 빈 목록·중복 dataset 선택을 거부한다.
- F5: input cache 공간 검사를 완료 재사용 확인 후, 잠금 안에서 추가 필요량으로 수행한다.
- F6: 완료 report의 contract hash, run_uid, 디렉터리명과 현재 재사용 요청을 대조한다.
- F7: 소유한 lock의 초기 기록/manifest 쓰기부터 finally로 보호한다. 다른 실행이
  소유한 lock의 획득 실패에서는 그 lock을 삭제하지 않는다.

주 변경 경로는 FaceX-Zoo fine-tune/modules/checkpoint_manager.py 및 명시적 호환성
등록, ronbun research/experiments/facex_inputs.py, facex_workflow.py,
facex_calibration_study.py, research/calibration/rejection.py, continuous.py다.
노트북의 학습 파라미터와 DB schema는 변경하지 않는다.

## 검증 기준과 재실행 범위

누락 상태 거부 및 정상 strict restore, 실제 02 checkpoint의 epoch/batch/optimizer/
scheduler/RNG 복원, 기존 전처리 receipt 재사용을 확인한다. 합성 입력으로 파생 cache
변조·중단 꼬리·정상 재개·저공간 재사용·중복 선택·다른 report 재사용 거부·일반 오류 후
잠금 정리를 검사한다. threshold는 동점·0/1 경계·수치 ceiling 및 public Global/Continuous
경로를 검사한다. 성능 개선이나 정식 캠페인 완료는 이 테스트로 주장하지 않는다.

02는 다음 재개 때 커널을 재시작한 후 같은 명시적 복구 파일에서 이어간다. 현재 실행 중인
학습을 이 수정만을 이유로 강제 종료하지 않는다. 학습 계산·입력이 같으므로
00/01 재실행을 요구하지 않는다. ronbun 보정 비교는 변경된 소스 fingerprint의 새
입력/index/report UID를 따라 실행하고 이전 결과를 덮어쓰지 않는다. 입력 cache의
이전 소스 계약을 무조건 승인하는 예외를 만들지 않는다. 실제 GPU 훈련·전체 추출·
최종 test 평가를 자동 실행하지 않으며, 이로 인한 실데이터 효과 크기는 미측정이다.

## 2026-11-07 KST 최종 검증

중복을 제외한 관련 테스트 264개 통과. 실제 02 checkpoint를 CPU와 GTX 1080 Ti에서
strict restore하여 모델/optimizer/scheduler 및 CPU/CUDA RNG 일치를 확인했다.
epoch 12, next_batch=21,162(다음 1-based batch 21,163), LR=0.0001이다.
전처리 receipt는 3,141,890장 완료 기록을 재사용했고 이미지 hash/decode 호출은 0회였다.
기존 checkpoint SHA, 02 파일과 settings hash가 유지됐다. 학습 업데이트는 하지 않았다.

publish/support/additional_fixes_20261106_v1/validation.json에 있다.
