## 결정 내용

1. geometry와 retrieval 입력 CSV를 각각 100,000행 청크로 읽어 saliency와
   strict join한다.
2. 전체 joined CSV는 청크별로 임시 경로에 기록한다. association 계산에는
   필요한 lineage/group/feature/metric 열만 Zstd Parquet projection으로
   별도 기록한다.
3. join key는 청크 내부에서 즉시 검증하고, 전체 CSV의 key hash에서 반복
   후보가 발견되면 해당 원본 key를 다시 읽어 실제 중복을 확인한다. hash
   충돌만으로 중복 판정을 내리지 않는다.
4. 관측 `spearman_rho`는 기존과 같은 전체 유효 표본의 ordinary Spearman
   값으로 계산한다.
5. bootstrap에서 뽑힌 각 identity의 횟수를 그 identity 행의 정수 weight로
   변환한다. 각 반복의 weighted expanded sample에 대해 tie를 포함한 평균
   rank를 정확히 재구성하고 weighted Pearson correlation을 계산한다.
   따라서 기존 concat 후 rerank와 같은 통계량을 유지하면서 반복마다 대형
   DataFrame을 만들지 않는다.
6. 구현 경계를 결과에
   `bootstrap_rank_strategy=weighted_rerank`와
   `association_algorithm_version=identity-cluster-weighted-rerank-v1`로
   기록한다. 기존 concat 기반 `resampled` API도 호환 경로로 남긴다.
7. 네 개 최종 output은 geometry/retrieval join과 두 association이 모두
   성공한 뒤에만 `os.replace`로 publish한다. 중단 시 임시 directory를
   정리하고 기존 canonical output을 만들거나 덮어쓰지 않는다.
8. phase attempt에는 algorithm version, bootstrap 수·batch size 4, join
   청크 크기, 현재 Git commit 및 세 구현 파일의 SHA-256을 기록한다.
9. 노트북은 10% milestone과 60초 heartbeat를 표시하며 이 단계가 CUDA가
   아닌 CPU/I/O 단계임을 실행 전에 명시한다.
10. 기존 YAML의 `bootstrap_method=identity_cluster`,
    `bootstrap_repeats=500`과 run config hash는 변경하지 않는다.

## 미해결 위험

1. weighted-rerank는 concat 기반 구현과 같은 bootstrap 분포·통계량을
   계산하지만 multinomial count와 같은 validity mask 내 공통 난수를
   사용하므로 기존 pair별 RNG의 개별 CI 숫자와 bitwise 동일하지는 않다.
   결과에는 algorithm version과 seed를 함께 보존한다.
2. 전체 A002는 아직 실행하지 않았으므로 15 GiB 입력의 실제 디스크 처리량,
   전체 strata 시간과 최종 peak RAM은 검증되지 않았다.
3. 전체 joined CSV 자체가 크므로 다음 대표 사례 단계가 이를 전부 적재하면
   별도 병목이 생길 수 있다. A002 완료 후 다음 단계의 실제 peak memory를
   확인해야 한다.
4. 최종 output 네 개의 promotion은 모두 계산된 뒤 수행되지만 파일별
   `os.replace`는 단일 다중 파일 transaction이 아니다. 같은 volume에서
   정상 publish를 전제로 하며, 비정상 filesystem 오류 시 phase manifest와
   네 경로의 존재를 함께 감사한다.
