## 1. 변경 배경

Step 1의 현재 ArcFace 추출기는 InsightFace `buffalo_l` ONNX 모델을 사용한다. 이 경로는 압축 특성 분석을 시작하기에는 충분하지만, 다음 두 목적에는 제약이 있다.

1. ArcFace, AdaFace, MagFace를 동일한 실행 인터페이스와 명시적인 전처리·checkpoint provenance 아래 비교해야 한다.
2. Grad-CAM은 모델 내부 feature map과 gradient가 필요하므로 ONNX 추론 경로만으로는 일관된 분석이 어렵다.

따라서 Step 2에서는 얼굴 검출·정렬과 얼굴 인식 encoder를 분리하고, **인식 encoder만 PyTorch 공통 계층으로 구성**한다. 본 단계는 모델을 새로 학습하는 단계가 아니다. 공개 사전학습 checkpoint를 고정한 추론, 임베딩 압축, 정량 평가 및 사후 Grad-CAM 분석만 수행한다.

## 2. 핵심 결정

### 2.1 연구 주장 단위

- 비교 대상은 ArcFace/AdaFace/MagFace라는 이름만이 아니라 **구체적인 사전학습 checkpoint**이다.
- 같은 PyTorch, backbone, 학습 데이터 표기를 맞추더라도 실제 checkpoint의 학습 recipe, 전처리, 구현 세부가 완전히 같다고 보장할 수 없다.
- 따라서 결과는 `loss 함수 자체의 인과효과`가 아니라 `선정한 사전학습 checkpoint의 압축 민감도 비교`로 보고한다.
- loss만의 인과효과를 주장하려면 동일 데이터·초기화 정책·optimizer·augmentation·schedule에서 loss만 바꾸어 여러 seed로 재학습해야 한다. 이는 현재 연구 범위와 장비 예산에서 제외한다.

### 2.2 후보 모델 조건

우선 후보군은 다음 조건을 최대한 일치시킨다.

| 항목 | 목표 조건 | 현재 상태 |
| --- | --- | --- |
| 모델 | ArcFace, AdaFace, MagFace | 공통 adapter 구현 중 |
| framework | PyTorch | 구현 중 |
| backbone | iResNet-100 우선 | checkpoint 등록 시 검증 필요 |
| 학습 데이터 | MS1MV2 계열 우선 | checkpoint별 문서 확인 필요 |
| embedding 차원 | 512 | adapter에서 검증 |
| 출력 | raw embedding, raw norm, L2-normalized embedding | 구현 중 |

조건을 충족하지 않는 checkpoint를 사용할 수는 있지만, 별도 비교군으로 표시하고 조건 일치 비교와 섞지 않는다.

### 2.3 검출·정렬과 인식 모델의 경계

- 얼굴 검출과 landmark 기반 정렬은 기존 경로를 재사용할 수 있으며 PyTorch로 통일할 필요가 없다.
- 공통으로 정렬된 `112×112` crop을 한 번 생성하고 manifest, 파일 hash, 정렬 설정을 고정한다.
- 각 인식 adapter는 checkpoint가 요구하는 RGB/BGR 순서, 범위, mean/std를 crop 이후에 적용한다.
- 같은 crop artifact를 사용함으로써 모델 비교에서 검출·정렬 변동을 줄인다.

### 2.4 PyTorch 출력 및 provenance 계약

모든 모델 adapter는 최소한 다음 정보를 제공한다.

- `raw_embedding`: L2 정규화 전 512차원 벡터
- `raw_norm`: raw embedding의 L2 norm
- `normalized_embedding`: 검색 및 압축 비교에 사용하는 단위 벡터
- `model_name`, `backbone`, `training_dataset`
- `checkpoint_path`, `checkpoint_sha256`
- 전처리 명세 및 `preprocessing_sha256`
- 코드·설정에서 재현 가능한 `model_uid`
- Grad-CAM target layer 이름

AdaFace와 MagFace에서는 raw norm이 품질 관련 신호일 수 있으므로 정규화 전에 반드시 보존한다. ArcFace에도 동일 schema를 적용한다.

### 2.5 ONNX Step 1과 PyTorch Step 2의 관계

- Step 1 ONNX 결과는 완료된 기준선이며 덮어쓰거나 같은 `run_id`로 재사용하지 않는다.
- Step 2의 PyTorch embedding, PCA 모델, PQ codebook, 검색 결과는 모두 새 lineage에서 다시 생성한다.
- ONNX와 PyTorch가 같은 checkpoint라고 검증되지 않은 경우 두 결과를 동일 모델의 재현 결과로 합치지 않는다.
- 동일 checkpoint 변환본이 확보된 경우에만 고정 crop에서 cosine similarity, norm, 순위 일치도를 검사하는 parity gate를 통과시킨다.
- parity gate 실패는 숨기지 않고 서로 다른 checkpoint 비교로 재분류한다.

### 2.6 압축 경계

Step 2도 Step 1의 독립 압축군 정의를 그대로 따른다.

- 원본: `origin_512_fp32`
- PCA-only: `384`, `256`, `128`, `64`, `32`차원 FP32
- PQ-only: 원본 512D embedding에 직접 적용
- PCA 출력에 PQ를 연속 적용하지 않는다.
- 압축 결과를 원본 재탐색으로 대체하는 fallback은 사용하지 않는다.
- 각 모델의 PCA/PQ는 해당 모델의 development embedding으로 별도 fit한다.

## 3. Grad-CAM 후속 분석 결정

### 3.1 코드 및 노트북 분리

정량적 압축 특성 분석과 Grad-CAM 분석을 다음과 같이 분리한다.

```text
research/embeddings/pytorch/        PyTorch FR adapter와 provenance
research/explainability/gradcam/    pair target, Grad-CAM, 사례 선택, saliency 지표
notebooks/model_validation/         checkpoint 등록·전처리·출력 검증
notebooks/lfw/gradcam/              LFW 후속 설명 가능성 분석 runbook
runs/step2/                         실행 중인 Step 2 정량·Grad-CAM artifact
results/step2/                      검증 후 선별한 Step 2 결과
```

기존 `notebooks/lfw/06_step1_compression_characterization.ipynb`에는 Grad-CAM 코드를 넣지 않는다. 노트북은 설정·단계 실행·artifact 확인만 담당하고, hook·gradient·사례 선택·지표 계산은 `research/`의 Python 모듈이 담당한다.

### 3.2 설명 대상과 target

최초 구현의 설명 대상은 query와 원본 gallery template 사이의 cosine similarity이다.

\[
S(q,g)=
\frac{f(q)}{\lVert f(q)\rVert_2}^{\mathsf T}
\operatorname{stopgrad}\left(
\frac{f(g)}{\lVert f(g)\rVert_2}
\right)
\]

- query branch에만 gradient를 흘린다.
- gallery embedding은 고정하고 gradient를 차단한다.
- hard PQ code나 양자화 연산을 직접 미분하지 않는다.
- Grad-CAM은 “PQ가 어떤 픽셀을 사용했는가”를 설명하는 것이 아니라, 원본 FR pair가 의존한 영역과 그 사례의 압축 민감도를 연결해 분석한다.
- reconstructed template을 target으로 사용하는 변형은 후속 ablation으로 명시하며 최초 결과와 섞지 않는다.

### 3.3 사례 선택

Grad-CAM 사례는 시각적으로 흥미로운 샘플을 임의 선택하지 않고 Step 2 정량 결과에서 결정적으로 선택한다.

- 압축 전후 decision이 유지된 사례
- accept에서 reject 또는 reject에서 accept로 바뀐 threshold-crossing 사례
- Top-1 또는 Top-k rank가 바뀐 사례
- cosine score drift 또는 angular error가 큰 사례
- 가능하면 품질 구간, 모델, 압축 profile별 층화

사례 선택 seed와 규칙, 입력 result hash를 기록한다. 동일한 probe가 여러 profile에 나타나는 paired comparison을 우선한다.

### 3.4 검증 지표

- heatmap 유한값, 범위 `[0, 1]`, 입력 공간 크기 복원
- 같은 입력·checkpoint·target에서 결정적 재현
- 얼굴 내부/외부 saliency 비율 등 기술 통계
- 상위 saliency 영역 가림에 따른 target score 감소
- random 또는 저-saliency 가림과 비교한 deletion/occlusion faithfulness
- 압축 민감도 지표와 saliency 지표의 상관 및 bootstrap 신뢰구간

Grad-CAM 그림만으로 압축 원인을 단정하지 않는다. 정량적 faithfulness와 반복 사례의 통계를 통과한 경우에만 후속 해석 근거로 사용한다.

## 4. 데이터·모듈 흐름

```text
LFW image manifest
    -> 공통 검출·정렬 crop + crop hash
    -> 모델별 PyTorch adapter
       -> raw embedding + raw norm + normalized embedding
       -> model/checkpoint/preprocessing provenance
    -> 모델별 development-only PCA/PQ fit
    -> calibration/test 정량 평가
       -> geometry, score, rank, threshold, DIR/FPIR 결과
    -> 결정적 Grad-CAM 사례 선택
    -> 원본 FR pair cosine target Grad-CAM
    -> saliency 기술 통계 + occlusion faithfulness
    -> 모델 × 압축 profile 비교 보고서
```

SurvFace의 PyTorch 정량 재실행은 같은 adapter가 LFW에서 검증된 뒤 수행한다. 최초 Grad-CAM runbook은 확보 상태와 계산량을 고려하여 LFW에 둔다.

## 6. 재실행 범위

PyTorch checkpoint 하나가 등록될 때마다 다음을 새로 실행한다.

1. checkpoint hash 및 전처리 freeze
2. 고정 crop 기반 model smoke/parity 검사
3. 전체 embedding 추출
4. 해당 모델의 PCA/PQ 재학습 및 materialization
5. calibration/test 정량 평가
6. 정량 결과를 입력으로 한 Grad-CAM 사례 선택과 후속 분석

다른 모델의 기존 결과나 Step 1 결과를 덮어쓰지 않는다. checkpoint 또는 전처리 hash가 바뀌면 downstream artifact를 모두 새 `run_id`로 재생성한다.

- toy CNN에서 target layer hook, gradient, heatmap shape/range, deterministic case selection 테스트가 통과한다.
- 실제 모델마다 512D, 유한값, raw norm 보존, L2 norm, batch 일치성을 검사한다.
- checkpoint 및 전처리 provenance가 모든 embedding과 downstream 결과에 전파된다.
- 기존 Step 1 결과와 Step 2 결과가 서로 다른 lineage로 저장된다.

## 8. 예상 문제와 대응

1. **checkpoint의 완전한 조건 일치가 어려움**
   - 공식 또는 저자 공개 checkpoint의 backbone·학습 데이터·전처리를 표로 기록한다.
   - 일치군과 비일치군을 분리하고 checkpoint 수준 비교로 표현한다.

2. **공식 구현의 오래된 PyTorch/CUDA 의존성**
   - 외부 repository 코드를 연구 핵심에 복사하지 않고 얇은 adapter/factory 경계를 둔다.
   - 현재 환경에서 로드 가능한 checkpoint 변환 또는 고정 dependency 환경을 별도로 기록한다.

3. **GTX 1080 Ti 메모리와 실행 시간**
   - inference batch와 Grad-CAM batch를 별도 설정한다.
   - Grad-CAM은 정량 결과에서 선택된 제한된 사례만 실행한다.

4. **target layer 이름 차이**
   - 모델 명세에 target layer를 명시하고 실행 전 해석 가능 여부와 4D activation을 검증한다.

5. **전처리 차이가 모델 차이로 오인됨**
   - 공통 crop과 모델별 tensor 전처리를 분리하고 각각 hash한다.
   - 색상 순서·범위·정규화의 smoke test를 필수로 둔다.

6. **Grad-CAM 과해석**
   - pair target, case selection, faithfulness 검증을 고정한다.
   - heatmap 예시만으로 loss 또는 압축 오류의 원인을 주장하지 않는다.

7. **raw norm 소실**
   - adapter 출력 계약에서 raw norm을 필수로 하고 L2 정규화 전에 계산한다.

8. **Step 1과 결과 혼합**
   - output root, `run_id`, model/checkpoint/preprocessing hash를 분리하며 완료 artifact를 읽기 전용으로 취급한다.

BalancedFace에서 직접 겹치는 3개 identity를 제거하는 것만으로 checkpoint 가중치의 사전학습 누수는 해결되지 않는다.

- raw archive는 자동 추출하지 않는다.
- JPG/BIN/RecordIO 대체 표현의 수량을 합산하지 않는다.

## 7. 재실행 범위

1. source 파일을 다시 다운로드하거나 교체하면 SHA-256과 EOF 검사를 재실행한다.
2. RFW protocol parser를 재실행하고 `_SUCCESS`를 마지막에 기록한다.
3. RFW identity artifact가 바뀌면 BalancedFace overlap 제거와 split을 모두 재실행한다.
4. RecordIO decoder가 추가되면 전체 decode coverage, image hash, group별 실패율을 새 artifact로 생성한다.
5. checkpoint training source/evidence가 바뀌면 RFW eligibility를 다시 판정한다.
6. 적격 checkpoint만 BalancedFace fit/calibration → RFW frozen evaluation을 새 `run_id`로 실행한다.

## 8. 검증 기준

- tar가 EOF까지 읽히고 unsafe/duplicate/case-collision member가 없어야 한다.
- RFW 4그룹 각각 6,000 pair와 fold별 300/300 순서가 일치해야 한다.

- BalancedFace identity label은 0..27,998 연속이고 identity는 한 그룹에만 속해야 한다.
- RFW source identity 목록 없이 BalancedFace split을 만들 수 없어야 한다.
- overlap identity는 split 전에 전 행 제거되어야 한다.
- development/calibration은 group-stratified identity-disjoint여야 한다.
- `dev` subset을 다시 `real`로 승격하는 chained 호출이 실패해야 한다.
- writer는 기존 `_SUCCESS`를 먼저 무효화하고 모든 파일 기록 후 마지막에 재생성해야 한다.
- RFW checkpoint eligibility가 현재 MS1MV2 후보를 거부해야 한다.

## 9. 미해결 위험

1. **BalancedFace JPG archive 손상**
   - 해당 파일은 재다운로드 전 사용하지 않는다.

2. **RecordIO decoder 부재**
   - 현 단계는 metadata index까지다. decoder 구현 시 `.idx` key와 `.rec` record를 검증하고 그룹별 decode 실패를 기록한다.

3. **RFW aligned BIN의 pickle 형식**
   - 외부 파일에 일반 `pickle.load`를 사용하지 않는다. 허용 opcode를 제한한 parser 또는 별도 신뢰 환경 변환이 필요하다.

4. **checkpoint 사전학습 누수**
   - 현재 MS1MV2 후보의 RFW headline 평가는 차단한다. 보조 compression delta로도 사용할 경우 오염 가능성을 명시한다.

5. **그룹 label 해석**
   - 데이터셋 제공 그룹을 개인의 고정된 실제 인종 label로 과해석하지 않는다.

6. **라이선스·생체정보**
   - 접근 메일은 재배포 라이선스로 간주하지 않는다. 원본·변환 이미지·파생 임베딩 공개 범위를 별도 확인한다.

7. **저장공간·실행 시간**
   - 1.25M 이미지 전체 materialization 전에 예상 용량과 free space를 확인한다. `dev`는 identity subset으로 검증하되 논문 결과로 사용하지 않는다.
