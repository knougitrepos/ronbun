- 상태: 검증됨. 현재 ArcFace 무-SDC 결과에 대한 자동 선택 및 보고서 전체 dry-run과 관련 회귀 테스트를 통과했다.
- 이전 결정과의 관계: `architect/20260901.md`의 model UID 기반 선택, SDC all-or-none 및 명시적 통합 실행 토글을 유지·보완한다.

### 변경 배경

`00_cross_dataset_results.ipynb`의 최초 자동 선택은 ArcFace 20260829 campaign을 골랐지만, 사용자가 드롭다운에서 20260902~20260903의 새 LFW·SurvFace·RFW-Custom run으로 바꾼 뒤에도 PQ SDC, faithfulness 크기 및 TinyFace 경로가 최초 campaign 값으로 남았다. 새 run에는 SDC가 없는데 이전 `((128, 8),)` 계약으로 검증되어 search-mode coverage mismatch가 발생했다.

### 결정 내용과 데이터 흐름

1. 상단 `EXPECTED_PQ_SDC_SETTINGS=None`은 최초 자동 후보가 아니라 드롭다운까지 반영된 최종 3개 run에서 추론한다.
2. 최종 run은 source commit, 실행 mode, data fraction, paper-run 여부 및 PQ SDC 설정이 모두 같아야 한다. 혼합 선택은 fail-closed로 거부한다.
3. faithfulness 자동 크기 선택은 최종 `SELECTED_RUN_IDS`로 다시 계산한다.
4. TinyFace 자동 선택은 최초 날짜형 campaign ID 대신 최종 open-set run과 같은 model UID, source commit 및 SDC 계약을 가진 유일한 completed evaluation만 허용한다. 없으면 supplementary를 생략하고, 둘 이상이면 모호성 오류로 중단한다.
5. model UID 자동 선택은 우선 기존 날짜형 campaign을 검사하고, 배치가 자정을 넘긴 경우 동일 source commit·mode·data fraction·paper-run·SDC 계약 아래 각 데이터셋 run이 정확히 하나씩인 cohort도 허용한다. 동일 계약에서 한 데이터셋이 반복 실행된 경우에는 임의 최신 선택 없이 모호성으로 거부한다.

```text
model UID 기본 cohort(같은 날짜 또는 자정 경계의 동일 실행 계약) 또는 사용자 드롭다운
  -> 최종 LFW / SurvFace / RFW-Custom run 3개
  -> 공통 provenance와 SDC 계약 검증
  -> SDC search-mode 기대 집합 산출
  -> faithfulness artifact 크기 재선택
  -> 동일 source 계약의 TinyFace 선택 또는 생략
  -> summary schema와 search-mode 검증
```

### 영향 범위와 재실행 범위

- 수정: `notebooks/common/reports/00_cross_dataset_results.ipynb`
- 자동 선택 모듈: `research/evaluation/report_selection.py`
- 회귀 테스트: `tests/research/test_notebook_layout.py`, `tests/research/test_report_selection.py`
- 기존 completed run과 `results/paper` artifact는 수정하거나 삭제하지 않는다.
- 보고서 노트북 커널을 재시작하고 처음부터 다시 실행해야 한다. 얼굴 임베딩, Grad-CAM, 압축 및 retrieval 실험 재실행은 필요 없다.

### 검증 기준과 미해결 위험

- 현재 새 ArcFace 3개 run을 선택하면 SDC 계약이 `()`로 계산되고 `pq_sdc_exhaustive`를 기대하지 않아야 한다.
- faithfulness는 세 run에 실제 공통으로 존재하는 artifact 크기를 선택해야 한다.
- 같은 source 계약의 TinyFace가 없으면 오류 없이 미포함되어야 한다.
- 저장 노트북은 유효한 JSON·Python AST이고 실행 output과 execution count를 제거한다.
- 현재 run ID에는 배치 전체를 직접 식별하는 공통 orchestration UID가 없다. 이번 보완은 동일한 불변 실행 계약과 데이터셋별 유일성을 이용해 자정 경계를 처리한다. 향후 동일 commit·동일 계약으로 같은 데이터셋을 반복 실행하면 자동 선택은 의도적으로 중단되므로, 배치 공통 orchestration UID를 manifest에 기록하는 개선은 남아 있다.
