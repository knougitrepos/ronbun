# 2026-08-30 아키텍처 변경 기록

## 배치 실험의 PQ SDC 전체 제외 토글

- 작성일: 2026-08-30 (KST)
- 상태: 구현됨
- 정식 실험 검증 상태: 미검증 (코드·단위·정적 테스트만 수행하며 full dataset run은 실행하지 않음)

### 변경 배경

`architect/20260829.md`에서는 네 데이터셋의 SDC를 PQ-m128 하나로 제한했다. TinyFace의 큰 gallery에서 m128 SDC도 장시간이 걸릴 수 있으므로, 주 비교인 PCA와 PQ reconstruction·one-sided cosine·ADC는 그대로 유지하면서 SDC 보조 ablation 전체를 한 번에 제외할 수 있는 명시적 배치 실행 선택이 필요하다.

### 결정 내용

- 배치 노트북 상단에 boolean `RUN_PQ_SDC`를 둔다.
- `RUN_PQ_SDC=True`이면 `PQ_SDC_SETTINGS=((128, 8),)`이고, `False`이면 `PQ_SDC_SETTINGS=()`이다. 다른 조합이나 boolean 이외의 값은 fail-closed로 거부한다.
- 기본값은 `False`이다. 이 선택은 LFW·SurvFace·RFW-Custom·TinyFace 네 데이터셋에 동일하게 전달된다.
- 비활성화는 SDC만 제거한다. 모든 기존 PCA 조건과 다섯 PQ codebook의 reconstruction·one-sided cosine·ADC 조건은 유지한다.
- TinyFace 예상 조건 수는 활성화 시 27개, 비활성화 시 26개이다.
- `pq_sdc_settings`는 plan ID와 run config/hash에 계속 포함되므로 활성화 run과 비활성화 run은 호환되지 않는다.
- 후처리와 보고서는 검증을 완화하지 않는다. 완료 run의 immutable config/summary contract에서 기대 SDC 집합을 읽고, 비활성화 계약에서는 SDC 행이 정확히 0개인지 검증한다.
- 활성화·비활성화 completed run이 한 보고서 또는 4모델 x 3데이터셋 행렬에 섞이면 실패한다.

### 데이터 및 모듈 흐름

1. `00_batch_experiment_runner.ipynb`가 `RUN_PQ_SDC`로부터 유일한 `PQ_SDC_SETTINGS`를 계산하고 통합 plan builder에 전달한다.
2. 공통 open-set 세 데이터셋은 `config.step4.compression.families.pq.sdc_settings`, TinyFace는 `config.pq_sdc_settings`에 빈 목록 또는 m128 설정을 기록한다.
3. canonical evaluator는 빈 목록일 때 `pq_sdc_exhaustive` calibration/test와 결과 행을 만들지 않는다.
4. compact search-space는 source run 설정을 summary contract에 고정하고 실제 SDC profile 집합과 정확히 대조한다.
5. cross-model matrix와 cross-dataset report는 선택된 모든 completed run이 동일한 SDC 계약인지 확인한 뒤 동적으로 기대 search mode를 정한다.

### 영향받는 코드·노트북·artifact

- 배치 진입점: `notebooks/common/orchestration/00_batch_experiment_runner.ipynb`
- 통합 plan 및 run config: `research/experiments/integrated_pipeline.py`, `research/experiments/pipeline_runner.py`
- TinyFace 조건 계획: `research/experiments/tinyface_pipeline.py`
- compact 후처리: `scripts/refresh_step4_search_spaces.py`
- 교차모델 행렬: `research/experiments/cross_model_matrix.py`
- 보고서 실행/검증: `scripts/run_integrated_postprocessing.py`, `notebooks/common/reports/00_cross_dataset_results.ipynb`
- 새 run의 manifest, retrieval ledger, compact summary와 report lineage에는 비활성화된 빈 SDC 설정이 반영되어야 한다.

### 재실행 범위

- 이 구현 작업은 어떤 기존 run/result도 삭제하지 않는다.
- 사용자가 새 결과를 원하면 네 데이터셋을 같은 `RUN_PQ_SDC=False` 계약으로 처음부터 실행한다.
- 첫 실행은 `START_NEW_RUN=True`를 사용하고, 동일한 미완료 run을 재개할 때만 `False`를 사용한다.
- 활성화된 기존 completed run을 비활성화 보고서에 섞거나 자동 재사용하지 않는다.

### 검증 기준

- 노트북 상단 토글이 엄격한 boolean이며 네 데이터셋 plan에 빈 설정을 전달해야 한다.
- TinyFace 비활성화 조건은 26개이고 `pq_sdc_exhaustive`가 없어야 한다.
- 공통 compact 결과와 TinyFace 결과에서 SDC 행 집합은 정확히 공집합이어야 한다.
- 4모델 x 3데이터셋 비활성화 행렬은 SDC 없이 완성되고, 활성화 run 하나라도 섞이면 거부되어야 한다.
- 활성화 회귀 경로는 계속 m128 SDC만 허용해야 한다.
- 정식 실행 후에는 각 run의 `status=completed`, `COMPLETED`, manifest/config hash, 결과 행 집합과 보고서 lineage를 별도로 승인해야 한다.

### 코드 검증 결과

- 배치·보고서 노트북은 `nbformat` 검증과 모든 코드 셀 문법 검사를 통과했다.
- 배치 parameter/setup 셀 smoke에서 기본값이 `RUN_PQ_SDC=False`, `PQ_SDC_SETTINGS=()`이고 선택된 PQ search mode가 reconstruction·one-sided cosine·ADC 세 가지뿐임을 확인했다.
- 관련 plan, TinyFace, compact refresh, report parameter, cross-model matrix 및 노트북 정적 테스트 83개가 통과했다. TinyFace 비활성화 조건 수는 26개로 검증되었다.
- 비활성화 synthetic 4모델 x 3데이터셋 행렬은 SDC 없이 540 retrieval 행으로 완성되며, 활성화 run 혼합은 거부되는 테스트가 통과했다.
- 전체 `tests/research` 실행은 output-free 전역 테스트를 의도적으로 제외한 상태에서 522개가 통과했다. 0.01초 heartbeat 타이밍 테스트 1개는 부하 중 한 번 간헐 실패했으나 단독 재실행에서 통과했으며 본 변경과 무관하다.
- 기존 m128 SDC completed run 네 개를 선택한 cross-dataset report notebook을 `write_outputs=False`로 실행해 `validated_not_written`을 확인했다. 기존 활성화 계약의 회귀 호환성도 유지된다.
- 현재 실행된 배치 노트북에는 사용자의 과거 실행 횟수와 출력이 남아 있어 저장소 전체 output-free 테스트 1개는 실패한다. 실행 증거 보존을 위해 이 작업에서는 출력을 제거하지 않았다.

### 미해결 위험

- 코드 검증만으로 실제 TinyFace 벽시계 시간과 메모리 사용량 감소폭은 확정할 수 없다.
- 실행된 노트북의 과거 출력에는 이전 활성화 설정이 남아 있을 수 있으므로 새 커널에서 상단부터 다시 실행해야 한다.
- SDC를 제외한 실행은 SDC ablation 근거를 생성하지 않는다. 논문에 SDC 비교가 필요하면 별도의 동질적 `RUN_PQ_SDC=True` 캠페인을 구분해 수행해야 한다.

## Faithfulness 표본 상한의 배치 노트북 노출

- 작성일: 2026-08-30 (KST)
- 상태: 구현됨
- 정식 실험 검증 상태: 미검증 (기존 artifact를 사용한 읽기 전용 보고서 회귀 검증만 수행)

### 변경 배경과 결정

- 기존 배치 노트북은 `RUN_FAITHFULNESS` 실행 여부만 노출하고 표본 상한은 후처리와 보고서에 `10_000`으로 숨겨져 있었다.
- 상단 parameter 셀에 `FAITHFULNESS_MAXIMUM_SAMPLES = 10000`을 추가한다. 숫자 구분용 underscore는 사용자 설정에서 사용하지 않는다.
- 값은 `None` 또는 boolean을 제외한 양의 정수만 허용한다. 양의 정수는 LFW·SurvFace·RFW-Custom 각각의 표본 상한으로 동일하게 적용하며 세 데이터셋을 합친 총량이 아니다.
- `None`은 제한 없음 계약이다. 각 데이터셋의 전체 eligible candidate를 선택하고 manifest JSON에는 `maximum_samples: null`을 기록한다.
- TinyFace official closed-set 경로에는 faithfulness 후처리를 적용하지 않는다.
- 배치 후처리는 `faithfulness_options.maximum_samples`로 값을 전달하고, cross-dataset report parameter injection과 artifact loader도 같은 값을 사용한다.
- 보고서 manifest의 `maximum_samples_per_dataset`도 선택값을 기록한다.
- faithfulness는 immutable completed run에서 생성하는 파생 artifact이며, 유한 상한은 `faithfulness_v2_n<상한>`, 무제한은 `faithfulness_v2_all` 디렉터리로 분리된다. 따라서 서로 다른 계약의 파생 결과를 같은 경로에서 덮어쓰지 않는다.

### 영향과 재실행 범위

- 영향 노트북: `notebooks/common/orchestration/00_batch_experiment_runner.ipynb`, `notebooks/common/reports/00_cross_dataset_results.ipynb`
- 영향 코드: `scripts/run_integrated_postprocessing.py`
- 표본 상한 변경 자체는 원본 embedding·compression·retrieval run의 science config를 바꾸지 않는다. 완료 source run이 보존되어 있다면 해당 run을 명시적으로 선택해 새 상한의 파생 faithfulness artifact만 생성할 수 있다.
- 이 구현 작업에서는 기존 run/result를 삭제하거나 새 full dataset 실험을 실행하지 않았다.

### 검증 결과

- 두 노트북 모두 `nbformat` 및 전체 코드 셀 문법 검증을 통과했다.
- parameter/setup smoke에서 기본값 `10000`, 무제한 `None` 허용과 `0` 거부를 확인했다.
- 후처리 옵션 전달, 사용자 지정 상한 및 무제한 artifact 경로 로드, 보고서 parameter injection 및 노트북 정적 계약 테스트 33개가 통과했다.
- 기존 `faithfulness_v2_n10000` artifact를 선택한 cross-dataset report notebook을 `write_outputs=False`로 실행해 `validated_not_written`을 확인했다.
- `FAITHFULNESS_MAXIMUM_SAMPLES=None`을 주입한 cross-dataset report notebook도 faithfulness artifact 생성 없이 `write_outputs=False`, `INCLUDE_FAITHFULNESS=False`로 실행해 `validated_not_written`을 확인했다.
- 사용자 지정 상한의 정식 데이터 artifact 생성 시간과 결과값은 실제 재실행 후 별도로 검증해야 한다.
