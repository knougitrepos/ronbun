# 2026-10-07 — RFW 1:1 Continuous FIQA Threshold Calibration 연동 및 프로토콜 경계 분리

## 2026-10-07 21:35 KST — RFW Two-Endpoint Identity Disjointness 및 점수 공간 격리 체계 구축

상태: 구현됨·검증됨 (단위/회귀 테스트 52개 전체 통과, synthetic workflow 통과). 실제 RFW 원본 데이터셋 및 저자 미공개 fine-tuned checkpoint를 사용한 대규모 정식 실험은 미검증.

### 변경 배경

branch `ucface-lfw1`에서 RFW 및 TinyFace를 다루면서 발생한 구조적 결함과 프로토콜 혼선:
1. **RFW PQ 프로파일 파싱 오류**: `_m(\d+)` 대신 단순 문자열 슬라이싱으로 인해 비정상 파싱 위험이 존재했음.
2. **PQ 개발 데이터 누수 위험**: RFW test/calibration 임베딩으로 PQ 압축기를 학습할 수 있는 구조적 취약점.
3. **ADC 점수 공간 불일치**: PQ ADC 점수 공간(negative squared L2: `[-4.0, 0.0]`)에 cosine 임계값 격자(`[-1.0, 1.0]`)를 탐색하여 비정상 적합 발생.
4. **1:1 Pair Calibration 간 Identity 누수 (Two-Endpoint 분할 부재)**: 1:1 impostor pair는 서로 다른 두 인물로 구성되므로, 단순 pair 분할 시 동일 인물이 fit과 safety에 걸쳐 나타나는 심각한 identity leakage 발생.
5. **품질 정의 혼선**: LFW의 비대칭 query-only FIQA($q_{\text{pair}} = q_{\text{left}}$)와 RFW의 1:1 대칭 검증 품질($q_{\text{pair}} = \min(q_{\text{left}}, q_{\text{right}})$)이 명확히 구분되지 않았음.
6. **TinyFace 프로토콜 경계 침범**: 1:N closed-set identification 평가에 불필요한 fallback/rejection 로직이 혼입되어 순수 랭킹 지표의 독립성이 훼손될 위험.
7. **근거 없는 주장**: 통계적 관측치를 "수학적 FMR 보장"이나 "공정성 보장"으로 표현하는 오해의 소지.

### 결정 (Architectural Decisions)

1. **Two-Endpoint Identity Disjointness 계약 도입**:
   - 1:1 verification 프로토콜에서 calibration 풀의 모든 identity를 고정 SHA-256 해시 함수로 `fit` (70%) 또는 `safety` (30%) 역할로 결정론적 배정.
   - 좌/우 identity가 모두 `fit`에 속한 pair만 fit에 사용하고, 모두 `safety`에 속한 pair만 safety offset 계산에 사용.
   - 역할이 불일치하는 cross-partition pair는 calibration에서 완전히 제외하고, 제외 수량(`cross_partition_pairs_excluded`)과 calibration 분모를 manifest 및 inventory에 기록.
2. **Score Space Isolation 및 독립 Grid 탐색**:
   - Cosine similarity(`[-1.0, 1.0]`)와 PQ ADC negative squared L2(`[-4.0, 0.0]`)를 완전히 분리된 점수 공간으로 규정.
   - 점수 공간에 따라 후보 임계값 그리드를 독립 할당하며, `frozen_origin` cosine threshold를 PQ ADC에 전이하지 않음.
3. **PQ Development Data 분리 강제**:
   - PQ 압축기(codebook)는 RFW test 및 calibration 데이터셋과 독립된 `development_embeddings`로만 학습되도록 엄격히 강제 (`ValueError` 검증).
4. **대칭적 Pair Quality 연산 (`symmetric_min`) 고정**:
   - RFW 1:1 검증에서는 대칭 품질인 $q_{\text{pair}} = \min(q_{\text{left}}, q_{\text{right}})$를 기본값으로 적용하여 LFW 1:N 모사의 query-only 방식과 분리.
5. **TinyFace 프로토콜 경계 분리**:
   - 1:N Rank-1/5/10/20 및 mAP를 보고하는 공식 1:N closed-set identification 프로토콜과 fallback rejection 시뮬레이션을 명확한 extension 헤더로 분리.
6. **Storage Accounting 계약 정립**:
   - 템플릿 페이로드(Origin 2,048B, PQ m128 128B, m64 64B, m32 32B)와 공유 코드북(524,288B)을 명확히 분리 집계하여 총 저장 비용을 산출.
7. **근거 없는 보장 표현 배제**:
   - `formal_fmr_guarantee = False`, `fairness_guarantee = False`를 명시하고, 경험적 test fold 달성률을 기술 통계로만 취급.

### 데이터 및 모듈 흐름

1. `pairs_df`, `embeddings`, `development_embeddings`, `fiqa_scores` 입력
2. `_parse_pq_m()`으로 서브벡터 수 검증 ($m \in \{128, 64, 32\}$)
3. `PQCompressor`를 `development_embeddings`에 fit -> codebook 생성
4. `compute_rfw_pair_scores()`로 asymmetric distance LUT 기반 ADC 점수 계산
5. `compute_rfw_pair_qualities()`로 `symmetric_min` 대칭 품질 점수 산출
6. 10-fold CV 루프:
   - 1 fold test 추출
   - 9 folds의 calibration pair를 Two-Endpoint Identity Disjointness로 fit/safety 분할
   - `fit_continuous_threshold()`를 통해 각 점수 공간에 맞는 candidate grid에서 threshold 함수 적합
   - held-out test fold에서 `realized_fmr`, `tar`, `target_met_rate` 계산
7. 결과 집계 및 `KEEP_RAW_RESULTS` 정책에 따른 정리 -> `run_manifest.json`, `CHATGPT_SUMMARY.md`, `RFW_CONTINUOUS_CALIBRATION.md` 생성.

### 미해결 위험 및 한계

1. **실제 원본 데이터셋 정식 실행 미검증**: synthetic test set에서는 모든 프로토콜 계약과 edge case가 검증되었으나, 24,000 쌍의 실제 RFW 원본 바이너리를 사용한 GPU 대규모 실험은 아직 수행되지 않음.
2. **저자 Fine-tuned 가중치 미확보**: KAIST 저자의 MobileFaceNet 1024D/512D fine-tuned 체크포인트는 공개되지 않아 현재 연구소 보유 pretrained 512D 가중치로만 baseline이 구성됨.
3. **극저 FMR 표본 분해능 한계**: RFW fold당 impostor 수가 300쌍이므로 10-fold pooled 3,000쌍 기준 $FMR=0.001$은 3건의 false accept에 불과하여 통계적 불확실성이 존재함.
