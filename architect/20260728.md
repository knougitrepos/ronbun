## 1. 변경 배경

Step 3의 LFW 전체 결과는 saliency feature와 압축 metric을 결합했지만 다음
문제가 남았다.

1. 한 sample/profile의 geometry metric이 여러 threshold policy 및 protocol
   retrieval row와 결합되면서 동일 관측치가 중복될 수 있었다.
2. landmark mask는 외부 bundle을 요구했으며 얼굴 전체와 여러 부위를
   재현 가능하게 생성하는 canonical 구현이 없었다.
3. LFW 전용 압축·Grad-CAM 경로를 SurvFace 공식 gallery/mated/unmated
   protocol에 그대로 적용할 수 없었다.
4. 실험 환경은 로컬 컴퓨터인데 실행 안전성을 GitHub CI에 의존하는 제안은
   연구 운영 방식과 맞지 않았다.
5. 기존 SurvFace 공식 pgvector 검색 노트북이 요구하는 공통 search API가
   구현되지 않아 실행 시 `NotImplementedError`가 발생했다.

### 2.1 로컬 실행만을 기준으로 한 안전 계약

- GitHub는 형상관리 용도로만 사용하며 실험 실행·검증에 GitHub Actions나
  원격 CI를 요구하지 않는다.

  읽기 전용으로 확인한다.
  - Git worktree clean 상태
  - PyTorch CUDA 사용 가능 여부와 실제 GPU 이름
  - ONNX Runtime `CUDAExecutionProvider`
  - profile과 일치하는 검증된 ModelSpec
  - dataset manifest와 정렬·landmark bundle 존재 여부
  - 실행·쓰기·덮어쓰기 gate
- 정식 run 생성은 dirty worktree를 기본 거부한다.
- YAML 기본값은 `execute_stage=false`, `write_outputs=false`,
  `overwrite=false`, `allow_dirty=false`로 두어 무심코 Run All해도

  source와 모든 tracked/staged 코드 변경은 계속 정식 run을 차단한다.

### 2.2 geometry와 retrieval 연관 분석 분리

두 분석 단위를 별도 table과 association으로 분리한다.

```text
saliency sample
  + paired embedding geometry
    -> geometry join
    -> profile별 geometry association

saliency sample
  + protocol/threshold retrieval row
    -> retrieval join
    -> protocol·split·threshold policy·mated 상태별 retrieval association
```

geometry join은 한 sample/profile에 여러 retrieval policy가 섞여 행이
복제되는 입력을 거부한다. retrieval association은 최소한 다음 strata를
분리한다.

- dataset
- model UID
- compression family/profile
- protocol UID
- threshold source split
- evaluation split
- threshold policy
- mated 여부

### 2.3 106-point landmark와 saliency 영역

InsightFace `2d106det.onnx`를 aligned 112×112 crop에 직접 적용한다. 원본
이미지에서 얼굴을 다시 검출하지 않으며, 정렬된 crop 좌표계의 landmark만
사용한다. 요청한 primary provider가 CUDA가 아니면 중단한다.

topology ID는 `insightface-2d106-semantic-v1`로 고정하며 다음 영역을
결정적으로 생성한다.

- `face`
- `left_eye`, `right_eye`
- `nose`
- `mouth`
- `left_cheek`, `right_cheek`
- `jaw`
- `outside_face`

landmark 좌표와 index/hash만 immutable bundle로 저장한다. 전체 표본의
고해상도 boolean mask를 미리 저장하지 않고, Grad-CAM native resolution에서
필요한 batch의 mask만 생성해 메모리와 저장량을 줄인다. saliency feature에는
기존 부위별 attention과 함께 `face_attention`, `outside_face_attention`을
기록한다.

### 2.4 LFW·SurvFace 공통 Step 4 workflow

공통 entry point는 다음과 같다.

```text
dataset manifest
  -> dataset/protocol validation
  -> aligned RGB uint8 NHWC crop
  -> 106-point landmark bundle
  -> verified profile PyTorch embedding
  -> frozen saliency target
  -> population Grad-CAM
  -> PCA/PQ compression characterization
  -> geometry/retrieval separate join and association
  -> immutable RunStore completion
```

LFW와 SurvFace는 입력·평가 계약이 다르므로 adapter가 다음을 보존한다.

| 항목 | LFW | SurvFace |
| --- | --- | --- |
| 압축 fit | identity-disjoint development | training development |
| threshold calibration | LFW calibration | SurvFace training calibration |
| 최종 평가 | LFW test open-set | 공식 gallery/mated/unmated test |
| known unknown | protocol에 포함 | 공식 test에서 금지 |
| saliency target | origin leave-one-out identity template | origin top-1 official gallery template |
| Grad-CAM 표본 | 적격 표본 전체 | 역할 균형 결정 표본, 기본 최대 20,000 |

SurvFace unmated probe는 동일 identity template가 정의되지 않으므로
leave-one-out target을 억지로 만들지 않는다. frozen origin embedding에서
선택한 top-1 official gallery template의 cosine을 query branch Grad-CAM
target으로 사용하고 target identity와 score를 artifact에 기록한다.

SurvFace의 압축 fit과 calibration은 공식 test를 사용하지 않는다. 공식
gallery, registered probe, unknown-unknown probe 순서와 `protocol_index`를
보존한다.

### 2.5 SurvFace pgvector 공식 검색 경로

기존 dataset notebook이 요구하던 `run_survface_official_search`를 구현한다.

```text
official gallery DB embeddings
  -> identity별 모든 gallery 이미지 평균
  -> official_all template materialization
  -> pgvector exact 또는 HNSW top-20
  -> registered / unknown_unknown 공식 순서 CSV
```

- `known_unknown` row를 허용하지 않는다.
- `official_all`, `enrollment_target=0`만 허용한다.
- 결과에는 ranked identity/distance, profile, search mode, model UID,
  query latency를 기록한다.
- Step 4의 compression characterization은 PCA/PQ 전체 profile을 비교하는
  exact in-memory 연구 경로이고, pgvector runner는 현재 DB schema가 직접
  검색 가능한 origin/PCA vector의 DB 적응 경로다. PQ code를 pgvector
  vector로 가장하지 않는다.

## 7. 미해결 위험

1. SurvFace는 training과 official test를 합쳐 463,341장이므로 전체 정렬,
   embedding과 landmark 생성 시간이 길다. 최초 실제 run에서 단계별 처리량,
   실패율과 VRAM을 기록해야 한다.
2. SurvFace Grad-CAM은 GTX 1080 Ti 실행 비용 때문에 기본 20,000개의
   registered/unmated 역할 균형 결정 표본을 사용한다. 이는 전체 표본
   compression/open-set 평가와 구분해 coverage와 표본 추출 hash를 보고해야
   하며, 전체 Grad-CAM으로 표현하면 안 된다.
3. 얼굴·세부 부위 mask는 106-point landmark의 기하학적 근사다. 가림,
   extreme pose와 저해상도 영상에서 영역 신뢰도가 낮아질 수 있으므로
   bundle 생성 실패율과 faithfulness를 확인해야 한다.
4. SurvFace unmated saliency는 “진짜 identity 부위”가 아니라 origin
   top-1 gallery 선택을 설명한다. registered LOO saliency와 의미를 섞어
   pooling하지 않는다.
5. 실제 PostgreSQL runner는 template 3,000개와 대규모 probe 검색에서
   index 설정·latency를 별도로 측정해야 한다. synthetic fake repository
   통과만으로 실제 HNSW 완료를 주장하지 않는다.
6. LFW faithfulness를 SurvFace에 자동 전이하지 않는다. SurvFace
   faithfulness는 전체 실행 시간과 landmark 품질을 확인한 뒤 별도 설정으로
   활성화한다.
