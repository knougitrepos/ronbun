# 2026-08-29 아키텍처 변경 기록

## 네 데이터셋 PQ SDC를 PQ-m128로 제한

- 작성일: 2026-08-29 (KST)
- 상태: 구현됨
- 정식 실험 검증 상태: 미검증 (코드·단위·정적 테스트만 수행하며 full dataset run은 이 변경에서 실행하지 않음)

### 변경 배경

`pq_sdc_exhaustive`는 query와 gallery를 모두 PQ code로 검색하는 보조 ablation이다. TinyFace의 큰 gallery에서는 모든 PQ budget에 SDC를 반복할 때 실행 시간이 과도하게 증가한다. 선행 결과에서 PQ-m128이 유효한 운용점이었으므로 SDC만 `(m=128, nbits=8)`로 제한하고, PCA 및 PQ reconstruction·one-sided cosine·ADC 비교는 전체 기존 설정에서 유지한다.

### 결정 내용

- 이 결정은 `architect/20260826.md`의 단일 `INCLUDE_PQ_SDC` boolean 결정을 구체적인 설정 선택 계약으로 보완·대체한다. 이전 기록은 이력으로 유지한다.
- 배치 실행 계약은 `PQ_SDC_SETTINGS = ((128, 8),)` 하나만 허용한다.
- 공통 open-set 설정은 `compression.families.pq.sdc_settings`, TinyFace 설정은 `pq_sdc_settings`에 선택값을 기록한다.
- 선택값은 통합 plan과 run config에 포함되며 plan ID/config hash가 달라지므로 이전 run을 새 계약의 결과로 재사용할 수 없다.
- 일반 Python API에서는 빈 SDC 설정을 비활성화 의미로 허용한다.
- SDC 설정은 전체 PQ 설정의 고유한 부분집합이어야 한다. 중복, 잘못된 정수, 512차원을 나누지 못하는 `m`, 존재하지 않는 설정은 fail-closed로 거부한다.
- SDC의 score metric, threshold calibration, `recalibrated_compressed` 정책, native/decoded audit 정의는 변경하지 않는다.

### 데이터 및 모듈 흐름

1. 배치 노트북이 m128 SDC 선택값을 통합 plan builder에 전달한다.
2. LFW·SurvFace·RFW-Custom은 effective Step 4 YAML의 PQ family에 선택값을 고정하고 canonical open-set compression evaluator로 전달한다.
3. 모든 PQ 프로파일은 reconstruction, one-sided, ADC를 생성한다. SDC calibration/test ledger는 `pq_512_m128_b8`에서만 생성한다.
4. TinyFace plan/config도 동일한 선택값을 포함한다. 예상 조건 집합은 Origin 1 + PCA 10 + PQ 기본 15 + m128 SDC 1 = 27개이다.
5. cross-dataset 보고서와 compact search-space 검증은 SDC 프로파일 집합이 정확히 `{pq_512_m128_b8}`인지 확인하고, 다른 PQ 프로파일의 SDC 행이 있으면 실패한다.

### 현재 구현과 목표 구조의 차이

- 구현 코드, 설정, 노트북 계약 및 정적/단위 테스트는 목표 구조에 맞게 변경되었다.
- LFW·SurvFace·RFW-Custom·TinyFace의 새 completed run artifact는 아직 생성하지 않았다.
- 따라서 상태는 `구현됨`이며, 실제 처리량·완료 시간·최종 행 집합·lineage가 확인되기 전에는 `검증됨`으로 올리지 않는다.

### 재실행 범위

- 코드 작업에서는 기존 run/result를 삭제하지 않는다. 삭제 책임은 사용자에게 있다.
- 기존 결과를 제거한 뒤 LFW·SurvFace·RFW-Custom·TinyFace를 모두 처음부터 재실행한다.
- 첫 정식 실행은 `START_NEW_RUN = True`로 시작한다. 동일한 새 run을 중단 후 이어갈 때만 `False`를 사용한다.
- 기존 completed-run override나 자동 재사용은 사용하지 않는다.
- 실행 전에 이전 코드를 import한 노트북 커널을 완전히 중단하고 새 커널에서 시작한다.

### 검증 기준

- 코드 단계: 선택값 검증, 공통 평가의 profile별 search-mode 집합, 네 데이터셋 plan 전달, plan/config hash 차이, TinyFace 27조건, 노트북 정적 계약 및 보고서 fail-closed 검증이 테스트를 통과해야 한다.
- 정식 run 단계: 각 run에 `status=completed`와 `COMPLETED`가 존재해야 한다.
- SDC 행의 설정 집합은 정확히 `{(128, 8)}`이어야 하며 m8/m16/m32/m64에는 SDC 행이 없어야 한다.
- 모든 PQ 프로파일에 reconstruction·one-sided·ADC와 기존 FPIR operating point가 남아 있어야 한다.
- manifest/config hash와 compact/report lineage가 일치해야 한다.

### 미해결 위험

- TinyFace m128 SDC의 실제 벽시계 시간과 메모리 사용량은 새 full run 전에는 확인할 수 없다.
- 실행 중 강제 종료나 시스템 재부팅이 발생하면 completed marker가 없는 부분 run을 최종 결과로 선택하면 안 된다.
- 과거 artifact는 SDC 전체 sweep 계약일 수 있으므로 새 보고서 검증에서 의도적으로 거부될 수 있다.
