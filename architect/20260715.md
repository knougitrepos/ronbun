## 1. 최종 연구 중심

연구의 중심은 다음과 같다.

> 압축된 ArcFace 얼굴 임베딩을 이용한 1:N open-set 검색에서 압축 오차와 ArcFace의 공간적 집중 특성을 조건으로 점수 이동과 불확실성을 보정하고, 위험이 낮은 질의는 압축 벡터만으로 처리하며 불확실한 질의만 단계적으로 saliency 분석과 원본 임베딩 exact 검색에 넘기는 선택적 검색 방법을 설계한다.

핵심 연결 관계는 다음과 같다.

```text
압축 점수·margin·압축 오차·검색 난이도
                    +
      ArcFace의 pair-conditioned 공간 집중 특성
                    ↓
         압축 점수 잔차의 평균·분산 추정
                    ↓
        accept / reject / defer 의 위험 제어
                    ↓
        필요한 경우에만 origin exact fallback
```

Grad-CAM 자체를 novelty로 주장하지 않는다. 핵심 후보 기여는 `압축 오차만으로 설명되지 않는 질의별 점수 불안정성`을 얼굴 영역 집중 패턴으로 추가 설명하고, 이를 실제 open-set DB 검색의 선택적 실행 정책과 연결하는 데 있다.

## 3. 연구 질문

### RQ1. 압축 점수 잔차의 이질성

압축 점수 잔차를 다음과 같이 정의한다.

\[
r_i=s_i^{512}-s_i^{d}
\]

- \(s_i^{512}\): 원본 512차원 검색 점수
- \(s_i^{d}\): 차원 \(d\)의 압축 검색 점수

동일한 PCA 차원을 사용하더라도 얼굴 품질, 가림, 자세, gallery ambiguity, score margin 및 ArcFace 집중 영역에 따라 \(r_i\)의 평균과 분산이 달라지는지 검증한다.

### RQ2. Saliency의 추가 설명력

재구성오차나 angular error가 같은 질의 사이에서도 ArcFace 집중 패턴이 다르면 압축 후 점수 안정성이 달라지는지 검증한다. Saliency는 단순 시각화가 아니라 잔차 예측에 독립적인 추가 정보를 제공해야 한다.

### RQ3. Open-set 위험과 비용 개선

조건부 보정이 다음을 동시에 개선하는지 평가한다.

- 목표 FPIR 유지
- 원본 512D 대비 DIR 손실 제한
- exact fallback 감소
- 저장량 감소
- Grad-CAM을 포함한 end-to-end latency 감소

### RQ4. 최소 저장 프로파일 선택

위험 제약을 만족하는 압축 프로파일 중 저장량이 최소인 차원 \(d^*\)를 선택한다.

\[
d^*=\arg\min_d \operatorname{Storage}(d)
\]

제약은 최소한 다음을 포함한다.

\[
\operatorname{FPIR}(d)\le\alpha
\]

\[
\operatorname{DIR}(d)\ge\operatorname{DIR}_{512}-\epsilon
\]

\[
\operatorname{CandidateRecall}(d)\ge\rho,
\qquad
\operatorname{Coverage}(d)\ge\gamma
\]

## 4. 전체 실행 아키텍처

### 4.1 오프라인 단계

```text
원본 얼굴 이미지
→ SCRFD 얼굴 검출
→ 5-point landmark 기반 112×112 정렬
→ 필요 시 106-point landmark 추출 및 영역 mask 생성
→ 고정된 ArcFace 512D 임베딩 추출
→ identity-disjoint development/calibration/test 분할
→ development에서 PCA/PQ/OPQ 학습
→ gallery template 생성
→ 압축 프로파일별 PostgreSQL 저장
→ pgvector HNSW index 생성
→ calibration 특징·threshold·잔차 모형 고정
```

### 4.2 온라인 단계

```text
Probe 입력
→ 얼굴 검출·정렬
→ ArcFace 512D probe 생성
→ 선택된 압축 프로파일로 변환
→ pgvector HNSW Top-K 후보 검색
→ score·margin·압축오차·품질·local density 기반 1차 보정
    ├─ 충분히 확실함 → 압축 결과로 accept/reject
    └─ 불확실함 → Top-1 pair-conditioned Grad-CAM
                      → 영역 saliency 특징 기반 2차 보정
                          ├─ 충분히 확실함 → accept/reject
                          └─ 여전히 불확실함 → origin 512D exact fallback
```

이 구조에서 Grad-CAM은 모든 질의에 적용하지 않는다. Saliency 호출 비용이 exact fallback보다 크거나 fallback 절감 효과보다 크면 2단계의 존재 이유가 없어지므로 반드시 end-to-end 비용으로 판단한다.

### 6.2 ONNX와 PyTorch 동일성

\[
\cos\left(f_{\mathrm{ONNX}}(x), f_{\mathrm{PyTorch}}(x)\right)\approx1
\]

검증 항목:

- 동일 이미지별 cosine similarity 분포

- Top-1 identity와 score 순위 일치율
- threshold crossing 비율
- 모델 파일 hash와 전처리 설정

동일성이 충분하지 않으면 이전 ONNX run과 새 PyTorch/Grad-CAM run을 하나의 연속 실험으로 결합하지 않고 별도 baseline으로 다룬다.

## 7. Gallery template

identity \(g\)에 등록 이미지가 \(n_g\)장일 때 기본 template은 다음과 같다.

\[
\mathbf t_g=\operatorname{normalize}\left(\frac{1}{n_g}\sum_{j=1}^{n_g}\mathbf e_{gj}\right)
\]

등록 수 \(n_g\in\{1,2,5\}\)를 비교하고 다음 baseline을 둔다.

1. 단일 이미지
2. 단순 평균 template
3. 이상치 제거 후 평균
4. 품질 가중 평균

다중 등록 조건에서는 하나의 class center가 identity 내부의 local cluster를 손실할 수 있으므로, 평균 template과 local gallery sample 검색을 별도 baseline으로 비교한다. 다만 품질 가중이나 local cluster는 주 novelty가 아니라 검색 안정성을 확인하는 보조 실험이다.

## 8. 압축 및 저장 경계

### 8.1 핵심 프로파일

- Origin-512
- PCA-448
- PCA-384
- PCA-256
- PCA-128

PCA는 development split에서만 학습하고 압축 결과를 재정규화한다.

\[
\mathbf z_i^{(d)}=P_d(\mathbf e_i-\boldsymbol\mu),
\qquad
\widehat{\mathbf z}_i^{(d)}=\frac{\mathbf z_i^{(d)}}{\|\mathbf z_i^{(d)}\|_2}
\]

### 8.2 추가 baseline

- PQ
- OPQ
- half precision 또는 pgvector `halfvec`

PQ/OPQ code는 pgvector HNSW에서 PCA vector와 동일하게 직접 검색되는 것으로 기술하지 않는다. PQ/OPQ는 별도 ANN backend 또는 보조 압축 artifact로 다루고, DB 검색 방식과 저장량을 명확히 분리한다.

## 9. 오류 및 특징 정의

### 9.1 압축 오차

\[
e_{\mathrm{rec}}=\|\mathbf e-\widehat{\mathbf e}\|_2
\]

\[
e_{\mathrm{ang}}=\arccos(\mathbf e^\top\widehat{\mathbf e})
\]

angular error는 open-set 얼굴 검색에서 핵심 특징으로 유지한다. 압축 프로파일 간 raw reconstruction error를 그대로 섞지 않고 프로파일별 정규화 또는 profile indicator를 사용한다.

### 9.2 검색 변화

- origin과 compressed Top-1 identity 차이
- compression-induced rank inversion
- HNSW-induced rank inversion
- compression candidate miss
- HNSW candidate miss
- threshold crossing
- final agreement with origin

### 9.3 정답과 기준선 일치의 분리

다음 두 레이블과 지표를 절대 혼합하지 않는다.

- `ground_truth_correct`: 실제 등록 여부와 실제 identity 기준 정확성
- `agreement_with_origin`: origin-512 exact 판정과의 일치성

origin exact가 틀린 경우도 있으므로 agreement를 correctness로 이름 붙이거나 논문 정확도로 해석하지 않는다.

## 10. 1차 저비용 보정

Grad-CAM 없이 계산 가능한 특징은 다음과 같다.

\[
\mathbf x_i^{\mathrm{cheap}}=
[s_{1,i},m_i,e_{\mathrm{rec},i},e_{\mathrm{ang},i},v_{g,i},q_i,d_{\mathrm{local},i},c_i]
\]

- \(s_1\): Top-1 cosine score
- \(m=s_1-s_2\): Top-1/Top-2 margin
- \(e_{\mathrm{rec}}\), \(e_{\mathrm{ang}}\): 압축 오차
- \(v_g\): gallery template 분산
- \(q\): probe 또는 template 품질
- \(d_{\mathrm{local}}\): gallery local density
- \(c\): compression profile

최초 baseline은 해석 가능한 logistic regression과 BCE를 사용한다. 학습 목표는 다음 두 개를 분리한다.

1. ground-truth 기준 현재 결정의 정확성
2. origin-512 exact 결정 보존 여부

DAM/LocalScore류의 local discrepancy 또는 density 정규화는 C5 수준의 비교 특징으로 두며, 제안 방법의 이름만 바꾼 것으로 오해되지 않게 별도 baseline 결과를 제시한다.

## 11. Pair-conditioned Grad-CAM

### 11.1 목표값

일반 class logit이 아니라 실제 압축 검색에서 반환된 Top-1 gallery template과 probe의 cosine similarity를 목표로 사용한다.

\[
y(x,\mathbf t_1)=\cos(f(x),\mathbf t_1)
\]

이 heatmap은 현재 probe가 특정 Top-1 identity와 유사하다고 판단되는 데 사용된 공간 영역을 설명해야 한다.

### 11.2 적용 계층

- ArcFace IResNet의 마지막 spatial convolution/residual block
- BatchNorm/Flatten 이전
- 완전연결층 이후는 공간 정보가 없어 사용하지 않음

### 11.3 선택적 호출

다음 중 하나를 만족하는 불확실 질의에서만 Grad-CAM을 실행한다.

\[
|s_i^{\mathrm{corr}}-\tau|<b
\]

또는 decision stability가 기준보다 낮거나 Top-1/Top-2 margin이 작을 때 호출한다. 호출 조건 자체도 calibration split에서 고정한다.

## 12. Saliency 특징

초기 구현은 4분면 또는 단순 의미 영역으로 시작하고, 효과가 확인되면 106-point landmark mask로 확장한다.

각 영역 \(R_j\)의 정규화 집중도는 다음과 같다.

\[
a_{ij}=\frac{\sum_{(u,v)\in R_j}H_i(u,v)}{\sum_{u,v}H_i(u,v)+\varepsilon}
\]

후보 영역:

- 왼쪽 눈·눈썹
- 오른쪽 눈·눈썹
- 코
- 입
- 왼쪽 볼
- 오른쪽 볼
- 턱·윤곽
- 얼굴 외부

추가 특징:

- 영역 집중도 벡터
- saliency entropy
- 좌우 비대칭
- 최대 영역 집중도
- 얼굴 외부 집중도

전체 특징은 \(\mathbf x_i^{\mathrm{full}}=[\mathbf x_i^{\mathrm{cheap}},\mathbf x_i^{\mathrm{sal}}]\)로 구성한다.

## 13. Saliency 신뢰성 게이트

시각적으로 그럴듯한 heatmap만으로 연구 기여를 주장하지 않는다.

### 13.1 영역 가림 검증

영역 \(R_j\)를 가린 뒤 similarity 감소량을 계산한다.

\[
\Delta s_{ij}=s_i-s_i^{(-R_j)}
\]

영역 집중도 \(a_{ij}\)와 \(\Delta s_{ij}\) 사이의 Spearman 상관을 측정한다.

### 13.2 S-RISE 비교

전체 데이터가 아닌 층화 표본에 적용한다.

- registered 고점수/저점수
- non-mated 오수락
- threshold 인접 표본
- 안정적인 PCA-384 사례
- 불안정한 PCA-256 사례

### 13.3 제외 조건

다음 중 하나면 saliency를 핵심 방법에서 제외하거나 부록으로 내린다.

- saliency와 실제 occlusion score drop의 관계가 없음
- cheap feature 대비 잔차 예측·calibration 개선이 반복 실험에서 재현되지 않음
- 동일 FPIR에서 DIR 또는 fallback이 개선되지 않음
- Grad-CAM 비용을 포함한 전체 latency가 origin exact보다 불리함
- LFW 효과가 SurvFace에서 유지되지 않음

## 14. 조건부 잔차 평균·분산 보정

목표 통계 모형은 이분산 회귀다.

\[
r_i\sim\mathcal N(\mu_i,\sigma_i^2)
\]

\[
\mu_i=\boldsymbol\beta^\top\mathbf x_i,
\qquad
\log\sigma_i^2=\boldsymbol\gamma^\top\mathbf x_i
\]

보정 점수와 예측구간은 다음과 같다.

\[
s_i^{\mathrm{corr}}=s_i^{d}+\widehat\mu_i
\]

\[
L_i=s_i^{\mathrm{corr}}-q\widehat\sigma_i,
\qquad
U_i=s_i^{\mathrm{corr}}+q\widehat\sigma_i
\]

\(q\)는 calibration split 잔차 분위수에서 정한다. 정규성 가정이 부적절하면 conformalized residual quantile을 비교 baseline으로 둘 수 있지만, 기존 conformal rejection을 단순 재명명하지 않도록 방법 차이를 명확히 해야 한다.

---

## 15. Open-set threshold와 판정 규칙

### 15.1 Threshold

non-mated probe별 gallery 최대 점수 \(M_i\)를 사용한다.

\[
M_i=\max_{g\in G}s_{ig},
\qquad
\tau_\alpha=Q_{1-\alpha}(\{M_i\}_{i\in\mathrm{nonmated}})
\]

평가 운영점은 FPIR 0.1%, 1%, 10%를 기본으로 한다.

### 15.2 직접 수락

\[
L_{i,1}\ge\tau
\quad\land\quad
L_{i,1}>U_{i,2}
\]

threshold 통과와 Top-1 순위 안정성이 모두 보장될 때만 압축 결과를 직접 수락한다.

### 15.3 직접 거부

\[
U_{i,1}<\tau
\]

### 15.4 보류와 fallback

그 외는 defer로 처리한다. 1차 cheap model에서 defer된 질의는 선택적으로 Grad-CAM 2차 보정을 거치고, 여전히 불확실한 경우 origin-512 exact 검색으로 넘긴다.

## 16. 압축 프로파일 선택

각 프로파일에서 다음을 calibration/test 규칙에 맞춰 측정한다.

- FPIR 및 DIR과 95% 신뢰구간
- Candidate Recall@K
- 자동판정 coverage
- Grad-CAM 호출률
- exact fallback 비율
- 저장량과 index 크기
- P50/P95/end-to-end latency

허용 집합은 다음과 같다.

\[
\mathcal F=\left\{d:
\operatorname{UCB}_{95\%}(\operatorname{FPIR}_d)\le\alpha,
\operatorname{LCB}_{95\%}(\operatorname{DIR}_d)\ge\operatorname{DIR}_{512}-\epsilon,
\operatorname{CandidateRecall}_d\ge\rho,
\operatorname{Coverage}_d\ge\gamma
\right\}
\]

\[
d^*=\arg\min_{d\in\mathcal F}\operatorname{Storage}(d)
\]

저장량이 같으면 end-to-end latency, fallback 비율, saliency 호출률 순으로 선택한다.

## 23. 최종 성공 조건

Saliency를 포함한 제안 방법을 핵심 기여로 유지하려면 최소한 다음이 성립해야 한다.

6. 최소 저장 프로파일 선택 결과가 confidence bound를 포함한 사전 정의 제약을 만족한다.

위 조건을 만족하지 않으면 연구의 안전한 핵심은 `압축 오차·검색 특징 기반 저비용 open-set calibration과 선택적 origin fallback`으로 축소하고, saliency는 부정적 결과 또는 보조 분석으로 기록한다.

## 26. 저장공간 주장과 fallback 저장 구조 수정

### 26.1 기존 문제

origin-512 exact fallback을 수행하려면 gallery의 원본 512D template 또는 vector를 보존해야 한다. 압축 vector와 원본 vector를 모두 같은 저장 계층에 보관하면 총 vector payload는 origin-only보다 커질 수 있다. 따라서 `압축을 사용하므로 전체 저장량이 감소한다`는 주장은 자동으로 성립하지 않는다.

예를 들어 float32 PCA-384와 origin-512를 모두 보관하면 vector payload만 다음과 같다.

\[
384\times4+512\times4=1{,}536+2{,}048=3{,}584\ \mathrm{bytes}
\]

이는 origin-512 하나의 2,048 bytes보다 크다.

### 26.2 저장량 분리

앞으로 저장량은 최소한 다음 세 항목으로 분리한다.

\[
S_{\mathrm{hot}}(d)
=S_{\mathrm{compressed\ vector}}(d)+S_{\mathrm{HNSW\ index}}(d)
\]

\[
S_{\mathrm{cold}}
=S_{\mathrm{origin\ fallback}}+S_{\mathrm{cold\ metadata}}
\]

\[
S_{\mathrm{total}}(d)=S_{\mathrm{hot}}(d)+S_{\mathrm{cold}}
\]

주요 최적화 목표는 전체 저장량이 아니라 **검색 시 상주하는 hot index의 저장량과 메모리**로 수정한다.

\[
d^*=\arg\min_{d\in\mathcal F}S_{\mathrm{hot}}(d)
\]

다음은 별도 보고한다.

- hot vector table 크기
- HNSW index 크기
- cold origin 저장량
- 전체 저장량
- query당 cold-storage 접근률
- fallback I/O bytes와 latency
- origin template cache hit/miss가 있다면 그 비율

### 26.3 논문 표현 경계

원본을 계속 보존하는 설계에서는 다음처럼 표현한다.

> 검색용 hot index와 상주 메모리를 줄이고, 원본 접근은 불확실 질의로 제한한다.

다음 표현은 총저장량이 실제로 감소한 실험 근거가 없으면 사용하지 않는다.

> 전체 데이터 저장량을 줄인다.

### 26.4 Grad-CAM과 cold origin 접근

pair-conditioned Grad-CAM 목표에 원본 512D gallery template을 사용하면 saliency 단계에서도 cold origin 접근이 발생할 수 있다. 따라서 다음 두 구현 후보는 아직 확정하지 않고 비용과 설명 범위를 비교한다.

| 후보 | Grad-CAM 대상 | 장점 | 비용·제한 |
| --- | --- | --- | --- |
| G1 | 원본 512D template | 실제 origin pair similarity 설명 | saliency 단계에서 원본 template 조회 필요 |
| G2 | PCA 복원 512D template | 원본 조회를 피할 가능성 | 복원 후보에 대한 설명이며 origin 설명이 아님 |

G1을 선택하면 Grad-CAM 호출률뿐 아니라 Grad-CAM용 cold lookup과 exact fallback용 cold lookup을 분리해 기록한다.

## 27. 점수 잔차를 동일 query–candidate 쌍으로 수정

### 27.1 후보별 잔차

초기 절의 \(r_i=s_i^{512}-s_i^d\)는 origin과 compressed Top-1 identity가 다를 때 서로 다른 후보의 점수를 빼는 문제가 있다. 잔차는 반드시 동일 probe \(i\)와 동일 gallery candidate \(j\) 쌍에서 정의한다.

\[
r_{ij}=s_{ij}^{512}-s_{ij}^{d}
\]

- \(i\): probe
- \(j\): 같은 gallery identity 또는 template
- \(s_{ij}^{512}\): origin 공간의 같은 pair score
- \(s_{ij}^{d}\): 압축 공간의 같은 pair score

### 27.2 학습 레코드 단위

이분산 잔차 모형을 구현한다면 학습 단위는 query 하나가 아니라 query–candidate pair다.

```text
probe i
× retrieved candidate j
→ compressed score
→ 같은 pair의 origin score
→ pair residual r_ij
→ pair feature와 conditional mean/variance target
```

후보별 보정 점수는 다음과 같다.

\[
\widehat s_{ij}=s_{ij}^{d}+\widehat\mu_{ij}
\]

보정 후 모든 반환 후보를 다시 정렬해 최종 후보를 선택한다.

\[
j^*=\arg\max_{j\in\mathcal C_i}\widehat s_{ij}
\]

여기서 \(\mathcal C_i\)는 HNSW가 반환한 candidate set이다.

### 27.3 계산 비용 기록

calibration에서 \(r_{ij}\)를 만들기 위해 같은 후보의 origin score를 계산해야 한다. 이는 학습·분석용 offline 비용으로 분리한다. 온라인에서 origin score를 모든 후보에 다시 계산하면 압축 검색의 이점이 약해지므로, 온라인 제안 방법은 예측된 \(\widehat\mu_{ij},\widehat\sigma_{ij}\)만 사용하고 실제 origin score는 fallback에서만 계산하는 구조를 우선 검토한다.

---

## 28. 후보별 불확실성을 반영한 판정 규칙

### 28.1 예측구간

각 candidate \(j\)에 대해 다음 구간을 계산한다.

\[
L_{ij}=\widehat s_{ij}-q\widehat\sigma_{ij},
\qquad
U_{ij}=\widehat s_{ij}+q\widehat\sigma_{ij}
\]

후보별 분산이 다를 수 있으므로 raw score의 Top-2만 비교해서는 안 된다. 3위 이하 후보가 더 큰 upper bound를 가질 수 있다.

### 28.2 직접 수락

보정 점수가 가장 큰 candidate를 \(j^*\)로 정한 뒤 다음을 모두 만족할 때 candidate set 안에서 직접 수락한다.

\[
L_{ij^*}\ge\tau^{(m)}
\quad\land\quad
L_{ij^*}>\max_{j\in\mathcal C_i,\ j\ne j^*}U_{ij}
\]

### 28.3 직접 거부

모든 반환 후보의 upper bound가 threshold보다 낮을 때 직접 거부한다.

\[
\max_{j\in\mathcal C_i}U_{ij}<\tau^{(m)}
\]

### 28.4 Defer

그 외는 defer다. 이 수식은 후보별 평균·분산 모델이 실제로 구현되고 calibration coverage가 검증된 경우에만 사용한다. 최소 연구인 logistic stability classifier에서는 이 구간 규칙을 사용하지 않고 예측 risk와 미리 정한 coverage 경계로 defer를 결정한다.

---

## 29. Grad-CAM gallery template 차원과 목표 후보 명시

### 29.1 원본 512D 대상

ArcFace 출력 \(f_{512}(x_i)\)와 cosine을 계산하는 gallery template도 512차원이어야 한다.

```text
압축 HNSW에서 candidate identity j 선택
→ 같은 identity의 512D template 조회
→ cos(f_512(x_i), t_j^512)를 Grad-CAM 목표로 사용
```

\[
y_{ij}^{\mathrm{origin}}
=\cos\left(f_{512}(x_i),t_j^{512}\right)
\]

### 29.2 PCA 복원 대상

원본 template 대신 복원 template을 사용한다면 다음처럼 명시한다.

\[
\widehat t_j^{512}=P_d^{-1}(t_j^d)
\]

\[
y_{ij}^{\mathrm{reconstructed}}
=\cos\left(f_{512}(x_i),\widehat t_j^{512}\right)
\]

이 경우 heatmap은 origin pair가 아니라 복원된 template과의 similarity를 설명한다.

### 29.3 아직 확정하지 않는 사항

- origin template과 reconstructed template 중 어느 대상을 주 방법으로 사용할지
- Top-1 한 후보만 saliency를 계산할지, 경쟁 후보도 계산할지
- saliency 단계의 cold-storage 접근을 허용할지

이 결정은 faithfulness, residual prediction 증가분과 end-to-end latency를 측정한 뒤 확정한다.

## 30. Candidate-conditioned 보증 범위

HNSW가 반환한 Top-K candidate만 검사하는 certificate 또는 interval 판정은 전체 gallery에 대한 결정론적 보증이 아니다. HNSW가 누락한 identity가 더 높은 origin score를 가질 가능성을 개별 query에서 배제할 수 없기 때문이다.

따라서 제안 방법의 보증 범위는 다음처럼 제한한다.

> **Compression-Induced Decision Stability within Retrieved Candidates**  
> 검색된 후보 집합 내 압축 유발 결정 안정성

또는:

> **Candidate-conditioned decision stability**  
> 후보 집합 조건부 결정 안정성

다음 주장은 사용하지 않는다.

> 전체 gallery에서 순위가 절대 뒤집히지 않는다.

Candidate Recall@K는 시스템의 경험적 품질 지표이며 개별 query의 전역 보증이 아니다.

\[
\operatorname{CandidateRecall@K}\ge\rho
\]

를 만족해도 후보 밖에 더 가까운 identity가 없음을 수학적으로 보증하지는 않는다. 논문에는 candidate-conditioned stability와 empirical candidate recall을 나란히 보고한다.

## 31. 최소 연구와 강한 확장 연구의 역할 분리

### 31.1 방향 A — 우선 구현할 현실적 최소 연구

저비용 특징 또는 선택적 saliency 특징으로 다음 확률을 추정한다.

\[
P(\mathrm{stable}\mid\mathbf x)
\quad\text{또는}\quad
P(\mathrm{ground\ truth\ correct}\mid\mathbf x)
\]

모델은 logistic regression과 BCE를 우선한다. 예측 risk가 낮으면 압축 결과를 사용하고 높으면 exact fallback한다.

이 방향에서 주장할 수 있는 핵심은 다음이다.

- compression-aware selective risk classification
- saliency가 추가될 경우 saliency-conditioned risk classification
- 목표 FPIR에서 coverage/fallback/latency trade-off

이 방향만 구현된 상태에서는 `점수 잔차의 평균과 분산을 직접 보정했다`고 주장하지 않는다.

### 31.2 방향 B — 결과가 지지할 때 승격할 강한 연구

동일 pair의 잔차에 대해 다음을 직접 추정한다.

\[
r_{ij}\sim\mathcal N(\mu_{ij},\sigma_{ij}^2)
\]

후보별 구간으로 candidate-conditioned accept/reject/defer를 수행한다. B가 실제로 구현되고 예측구간 coverage와 비용 이득이 검증되면 최종 핵심 방법으로 승격할 수 있다.

### 31.3 현재 결정

현재 시점에는 A와 B 중 최종 논문 방법을 확정하지 않는다. 구현 순서는 A를 먼저 완성하고, 다음 게이트를 통과한 경우에만 B를 추가한다.

- 같은 pair residual 데이터가 올바르게 생성됨
- 잔차 평균 예측이 zero-mean 또는 profile-only baseline보다 개선됨
- 분산 예측이 calibration coverage를 만족함
- 후보별 추론 비용이 fallback 절감 이익을 훼손하지 않음

## 32. 점수 체계별 threshold 분리

원본 cosine, PCA raw score, cheap calibration score, saliency score 및 이분산 보정 score는 분포가 다르다. 각 방법 \(m\)의 threshold를 calibration split에서 별도로 정한다.

\[
\tau_{\alpha}^{(m)}
=Q_{1-\alpha}\left(
\max_j s_{ij}^{(m)}
\mid i\in\mathrm{nonmated}
\right)
\]

두 평가 목적을 분리한다.

### 32.1 위험 보정 성능 평가

- 방법별 threshold 재보정
- 동일 target FPIR에서 DIR, coverage, fallback과 latency 비교
- 실제 open-set 운용 성능을 평가

### 32.2 Origin 결정 보존 평가

- origin threshold를 고정
- compression 또는 calibration이 origin 결정을 얼마나 보존하는지 측정
- ground-truth 성능과 별도로 agreement를 보고

방법별 재보정 결과와 origin threshold 고정 결과를 하나의 지표로 혼합하지 않는다.

## 33. Cheap feature의 현재 가용성 구분

초기 기본 특징은 현재 실제 계산 가능한 다음 항목으로 제한한다.

\[
\mathbf x_i^{\mathrm{base}}
=[s_{1,i},m_i,e_{\mathrm{rec},i},e_{\mathrm{ang},i},c_i]
\]

다음은 구현과 데이터 조건을 충족한 뒤 추가하는 조건부 특징이다.

| 특징 | 사용 조건 | 현재 해석 주의 |
| --- | --- | --- |
| quality \(q_i\) | 실제 FIQA 또는 검증된 품질 estimator 구현 | 상수 0이면 정보가 없으므로 특징으로 주장하지 않음 |
| template variance \(v_g\) | enrollment가 2장 이상 | 단일 등록에서는 의미 없음 |
| local density \(d_{\mathrm{local}}\) | local gallery sample/anchor와 정의 구현 | 임의 scalar로 DAM/LocalScore를 대체하지 않음 |
| landmark saliency | landmark 검출·mask 품질 검증 | 실패 검출 처리 규칙 필요 |

각 실험의 feature schema에는 `available`, `constant`, `missing`, `estimated` 상태를 기록한다. 값이 상수인 feature를 포함해 성능이 개선된 것처럼 해석하지 않는다.

## 34. Grad-CAM 목표 ablation 보완

Top-1 similarity Grad-CAM은 출발점으로 유지하되, 1:N 순위 결정을 더 직접적으로 설명하기 위해 contrastive margin target을 ablation에 포함한다.

### 34.1 Top-1 similarity target

\[
y_{\mathrm{top1}}(x_i)=\cos(f(x_i),t_{j_1})
\]

질문: 어떤 영역이 후보 \(j_1\)과의 유사도를 높였는가?

### 34.2 Contrastive target

\[
y_{\mathrm{margin}}(x_i)
=\cos(f(x_i),t_{j_1})-\cos(f(x_i),t_{j_2})
\]

질문: 왜 후보 \(j_2\)보다 \(j_1\)을 선택했는가?

압축 rank inversion과 Top-1/Top-2 margin 안정성에는 contrastive target이 더 직접적일 수 있다. 다만 두 후보의 Grad-CAM 비용과 후보 차원 문제를 함께 측정하며, contrastive target을 무조건 주 방법으로 확정하지 않는다.

## 35. FPIR 운영점과 표본 크기

LFW의 non-mated probe가 약 1,688개인 현재 규모에서는 한 건의 false positive가 약 0.059%다. 따라서 LFW만으로 0.1% FPIR의 95% 상한을 안정적으로 증명하기 어렵다.

### 35.1 LFW

- 주 operating point: FPIR 1%
- 보조 operating point: FPIR 10%
- FPIR 0.1%: 탐색적 결과로만 표시
- 0건 오류를 곧바로 `0.1% 보장`으로 해석하지 않음

### 35.2 더 큰 non-mated 평가

SurvFace 등 충분한 non-mated probe가 있는 평가에서 FPIR 0.1%를 정식 운영점으로 검토한다.

### 35.3 신뢰구간

- FPIR: point estimate와 단측 95% upper confidence bound
- DIR: point estimate와 95% lower confidence bound
- Candidate recall: 가능하면 95% lower confidence bound
- Coverage: 가능하면 95% lower confidence bound
- identity 상관을 고려한 bootstrap 또는 적절한 binomial interval 사용

압축 프로파일 허용 조건은 표본 크기가 충분할 때 다음처럼 적용한다.

\[
\operatorname{UCB}_{95\%}(\operatorname{FPIR})\le\alpha
\]

\[
\operatorname{LCB}_{95\%}(\operatorname{DIR})
\ge\operatorname{DIR}_{512}-\epsilon
\]

## 36. LFW와 SurvFace 평가 역할 수정

LFW에서 모든 설정을 고정해 SurvFace에 직접 적용하는 실험만으로 방법 자체의 유효성을 판단하지 않는다. 도메인 이동과 방법 실패를 구분하기 위해 두 프로토콜을 둔다.

### 36.1 주 실험 — SurvFace 내부 검증

```text
SurvFace identity-disjoint development
→ PCA와 모델 학습
→ SurvFace calibration에서 threshold·fallback 정책 고정
→ SurvFace test에서 최종 평가
```

이 결과를 저품질 surveillance 환경에서 방법 자체의 주 유효성 평가로 사용한다.

### 36.2 추가 실험 — Cross-dataset transfer

```text
LFW에서 PCA·calibration·threshold·정책 고정
→ SurvFace에 직접 적용
```

이 실험은 일반화 강도를 평가한다. 실패하면 다음 원인을 분리해 분석한다.

- PCA subspace 이동
- 얼굴 품질·자세·가림 차이
- score와 threshold 분포 이동
- saliency 특징 분포 이동

Cross-dataset 실패만으로 동일 데이터셋 내 방법 유효성까지 자동으로 부정하지 않는다.

## 37. Gallery template 생성 순서 고정

기본 방법은 **origin embedding을 집계한 뒤 압축**하는 방식으로 고정한다.

### 37.1 기본 — 집계 후 압축

\[
t_g^{512}
=\operatorname{normalize}\left(\frac1{n_g}\sum_j e_{gj}\right)
\]

\[
t_g^d
=\operatorname{normalize}\left(P_d(t_g^{512}-\mu)\right)
\]

### 37.2 Ablation — 압축 후 집계

\[
t_g^d
=\operatorname{normalize}\left(
\frac1{n_g}\sum_j
\operatorname{normalize}(P_d(e_{gj}-\mu))
\right)
\]

정규화 순서 때문에 두 방식은 일반적으로 동일하지 않다. DB의 origin/compressed template lineage에는 aggregation order를 필수 metadata로 기록한다.

3. base feature 중 실제로 비상수이며 누수 없이 계산 가능한 것은 무엇인가?
4. candidate set의 같은 pair origin/compressed score를 재현 가능하게 만들 수 있는가?
5. logistic/BCE risk classifier만으로 fallback trade-off가 개선되는가?
6. PyTorch와 ONNX ArcFace가 동일 lineage로 볼 만큼 일치하는가?
7. Grad-CAM 한 건의 GPU 시간과 origin exact fallback 한 건의 비용은 각각 얼마인가?
8. saliency가 cheap feature 이후 residual 또는 risk 예측을 추가로 개선하는가?
9. SurvFace 내부 dev/cal/test split과 충분한 non-mated 표본을 확보했는가?

이 게이트 결과에 따라 A형 최소 연구, A+saliency 또는 B형 후보별 잔차 모형 중 최종 구현 범위를 정한다.

## 41. 검토 반영 최종 요약

- 기존 아키텍처는 연구 목적과 단계적 검증 방향을 대체로 올바르게 이해했다.
- 그러나 문서에 적힌 모든 요소를 무조건 구현하는 것으로 해석하지 않는다.
- 총저장량이 아니라 hot index 절감과 cold origin 접근 비용을 분리한다.
- 점수 잔차는 동일 query–candidate pair의 \(r_{ij}\)로 정의한다.
- 후보별 구간을 사용하며 모든 반환 후보의 upper bound를 비교한다.
- certificate는 전체 gallery가 아닌 retrieved candidate set 조건부 안정성으로 제한한다.
- Grad-CAM 대상 template은 512D origin 또는 PCA 복원 512D 중 무엇인지 명시하고 비용·설명 범위를 비교한다.
- logistic/BCE 위험 분류를 우선 구현 후보로 두고, 이분산 잔차 평균·분산 모형은 실험이 지지할 때 승격한다.
- 점수 체계별 threshold를 별도로 calibration하고 origin 보존 평가는 분리한다.
- 초기 cheap feature는 실제 가용한 score, margin, reconstruction/angular error, profile로 제한한다.
- LFW에서는 FPIR 1%를 주 운영점으로 두고 0.1%는 탐색적으로 해석한다.
- SurvFace 내부 검증을 주 실험으로, LFW→SurvFace 전이를 추가 일반화 실험으로 분리한다.
- 기본 template 생성은 집계 후 압축으로 고정하고 반대 순서는 ablation으로 둔다.
- 최종 구현 범위는 cheap calibration, saliency의 독립적 효과, 후보별 잔차 모형의 비용·성능 게이트를 순서대로 통과한 뒤 결정한다.
