## 07:31 KST — Saliency–score shift–threshold crossing 파생 metric 계약

- 상태: `검증됨`
- 기준 브랜치: `step9`
- 기준 커밋: `ab1d0105ba69cd2f84976b037adf214bafd52286` 위 작업 트리

### 변경 배경

기존 Phase 05는 saliency feature와 signed `top1_score_drift`, winner agreement,
`threshold_crossing`의 Spearman 연관을 계산했다. 그러나 signed drift만으로는
saliency가 압축 오차의 크기와 임계값 판정 변경에 어떤 관계가 있는지 분리해
설명하기 어렵다. 또한 PQ ADC처럼 원본 cosine과 압축 ADC의 score space가 다른
경우 raw score 차이를 정의하면 안 된다.

### 결정 내용

1. 기존 Step9 FPIR target 계약 `(0.01, 0.05, 0.10, 0.20, 0.30)`은 변경하지
   않는다. 이번 변경은 target 추가·삭제나 threshold 산출 규칙 변경이 아니다.
2. fallback 경로나 fallback 정책은 추가·수정하지 않는다. 연구 중심은 압축
   score의 threshold 보정과 그 판정 안정성 분석이다.
3. query 단위 retrieval row에서 다음 파생 metric을 계산한다.
   - 최대 decision statistic 변화: `absolute_top1_score_drift`
   - 원본 winner를 고정한 동일 후보 score 변화:
     `absolute_origin_winner_score_drift`
   - 각 score space 내부의 signed margin과 threshold 거리:
     `origin_threshold_margin`, `compressed_threshold_margin`,
     `origin_threshold_distance`, `compressed_threshold_distance`
   - 비교 가능한 score space에서만 margin 변화:
     `threshold_margin_shift`, `absolute_threshold_margin_shift`
   - 판정 변경 방향: `accept_to_reject_crossing`,
     `reject_to_accept_crossing`
4. `score_spaces_comparable=False`인 PQ ADC row에서는 raw score drift와
   margin shift를 결측으로 유지한다. 다만 원본·압축 score를 각자의 threshold와
   비교한 내부 margin/distance 및 crossing 방향은 유효하다.
5. 기본 retrieval association은 saliency feature와 signed/absolute score drift,
   origin threshold distance, winner agreement, 전체 crossing 및 양방향 crossing을
   model·dataset·compression profile·search mode·target FPIR·threshold policy·mated
   strata별로 계산한다. 기존 identity-cluster bootstrap 계약은 유지한다.
6. 이 분석에서 saliency Spearman rho는 threshold의 직접 보정값이 아니다.
   saliency가 큰 query에서 score 이동 또는 경계 통과가 집중되는지 보여 주는
   보조 근거이며, 실제 threshold는 calibration split의 기존 규칙으로 산출한다.

### 미해결 위험

- Spearman rho는 연관성이지 인과 효과나 query별 threshold 보정량이 아니다.
- binary crossing의 rho는 crossing 발생 집중도를 요약하지만, 발생 수가 적은
  strata는 CI가 넓거나 통계량이 정의되지 않을 수 있다.
- 실제 논문 표에 사용하려면 각 model·dataset의 새 Phase 05를 동일 코드/계약으로
  생성하고 target별 crossing count와 bootstrap CI를 함께 보고해야 한다.

## 22:01 KST — Threshold 보정 전후 paired saliency 통계와 보고 계약 보강

- 상태: `구현됨` (합성·회귀 테스트 `검증됨`, 실제 12-run 결과 `미검증`)
- 기준 브랜치: `step9`
- 기준 커밋: `f965df0` 위 작업 트리
- 이전 결정: 같은 날짜 07:31 절의 threshold 산출 규칙과 fallback-free 범위를
  유지하면서, 미완성이던 crossing 검증·실패 분해·보정 전후 직접 비교를 보완한다.

### 변경 배경과 결정

기존 구현은 saliency와 score drift/crossing의 병렬 Spearman 연관만 제공하여
`saliency → score·margin 교란 → threshold 사건`과 보정 전후 saliency rho 변화를
직접 확인하기 어려웠다. Threshold는 계속 calibration split에서 독립적으로
산출하며, saliency rho를 threshold 값의 입력이나 보정계수로 사용하지 않는다.

1. score와 threshold에서 accept/reject, crossing 방향, TPIR@Rank-K를 다시
   계산하여 원시 boolean과 모순되면 Phase05를 중단한다.
2. non-mated는 새 false accept와 해소된 false accept로, mated TPIR 손실은
   threshold 미달과 true identity의 Top-K 이탈로 분해한다.
3. `absolute_top1_score_drift`, `absolute_threshold_margin_shift` 등 교란량과
   방향별 threshold 사건의 직접 Spearman 연관을 계산한다.
4. 같은 query·identity를 frozen-origin과 recalibrated-compressed 정책 사이에서
   짝지어 사건률 차이와 identity-cluster bootstrap CI를 계산한다.
5. 핵심 saliency인 `outside_face_attention`, `saliency_entropy`에 대해
   `rho_recalibrated - rho_frozen`과 paired bootstrap CI를 별도 산출한다.
6. event와 non-event가 각각 5개 미만인 binary association은 rho와 CI를
   결론용으로 비활성화한다. 핵심 가설 행은 `prespecified_primary`, 나머지는
   `exploratory`로 구분한다.
7. 보고 로더는 FPIR `(0.01, 0.05, 0.10, 0.20, 0.30)`의 정확한 집합과
   `saliency-threshold-metrics-v1` 동질성을 강제한다.
