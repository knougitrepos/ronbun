## 1. 핵심 결론

1. **LFW full은 완료·clean lineage·artifact 무결성이 확인된 유효한 full run이다.** 다만 여기서 full은 정렬 가능한 LFW 전체 13,195장을 압축/Grad-CAM 분석했다는 뜻이다. 실제 1:N 검색 gallery는 50 identity의 mean template이며, 공식 LFW 6,000-pair verification protocol이 아니다.
2. **LFW에서는 PCA256이 가장 보수적인 압축 기준점이다.** 2,048 B에서 1,024 B로 payload를 50% 줄이면서 관측된 rank-1, DIR, FPIR이 origin과 같았다. PCA128은 75% 절감의 공격적 후보지만 rank-1 1건이 감소했고, PCA64는 false accept가 1건에서 9건으로 늘었다.
3. **SurvFace quick 0.5는 absolute performance 추정에 낙관적 편향이 있다.** origin rank-1은 quick 6.1272% 대 full 4.2649%, rank-20은 22.1861% 대 16.8479%였다. quick은 pipeline/profile 순서와 보존 경향을 확인하는 용도에는 유효하지만 full 성능의 대용값으로 사용하면 안 된다.
4. **SurvFace의 nominal FPIR 10% calibration은 test에서 실패했다.** origin realized FPIR은 quick 41.4356%, full 48.3111%였다. calibration gallery 200 identity와 test gallery 1,500/3,000 identity의 차이가 핵심 원인 후보이며, 현재 threshold는 FPIR 보장이 아니라 calibration 표본에서의 경험적 선택이다.
5. **SurvFace의 PCA reconstruction angle은 retrieval fidelity의 대리변수가 아니다.** PCA384의 mean reconstruction angle은 quick/full 모두 약 0.473°이지만 full rank-20은 origin 16.8479%에서 12.2304%로 감소했다. geometry는 inverse-transformed 512D reconstruction을 평가하고 검색은 centered PCA 좌표를 직접 cosine 검색하기 때문에 서로 다른 양이다.
6. **현재 PQ 결과는 ADC/PQ code-search가 아니다.** Faiss `IndexPQ`를 `sa_encode`/`sa_decode` codec으로 사용한 뒤 복원된 dense vector를 exact cosine 검색한다. 따라서 PQ 검색 latency, PQ index size, pgvector PQ 검색 효율 또는 ADC 성능은 아직 검증되지 않았다.
7. **Grad-CAM association은 탐색적 근거다.** SurvFace quick/full의 상관 패턴은 수치적으로 안정적이지만 SurvFace faithfulness 행은 0이고, 다중검정·교란 통제·held-out 정책 효과 검증이 없다. saliency 기반 fallback의 유효성은 검증 필요 상태다.
8. **Step 4의 두 SurvFace full 기록은 목적이 다르므로 합치면 안 된다.** `cccb59d5`는 quick과 직접 비교할 in-memory compression/Grad-CAM full run이고, `3c19d8dc`는 Origin/PCA256의 PostgreSQL exact/HNSW 운영 참고 run이다.

- outside-face attention mean: quick 54.4592%, full 54.9217%
- geometry rho 벡터 quick↔full:
  - Pearson 0.99793, Spearman 0.99708
  - mean `|Δrho|=0.00716`, sign agreement 99.47%
- retrieval rho 벡터 quick↔full:
  - Pearson 0.98584, Spearman 0.96477
  - mean `|Δrho|=0.00928`, sign agreement 90.96%
- nominal 95% bootstrap CI가 0을 제외:
  - full geometry 537/570, retrieval 1,867/2,280
  - quick geometry 533/570, retrieval 1,794/2,280

이는 subset 수치 안정성에는 강한 supporting evidence다. 하지만 다음 이유로 정책/인과 근거는 아니다.

1. N이 매우 크고, profile·metric·policy가 반복되는 종속 가설이다.
2. FDR 등 multiplicity correction이 없다.
3. pose, blur, quality, origin score/margin 등의 confound를 통제하지 않았다.
4. SurvFace Grad-CAM target은 `origin_top1_gallery_cosine`이며 unmated probe는 임의 top-1 gallery identity를 설명한다.
5. Quick gallery 1,500과 full gallery 3,000이 달라 같은 probe의 reference identity가 일치한 비율은 50.87%뿐이다.
6. LFW target은 leave-one-out same-identity cosine이므로 LFW와 SurvFace rho 크기를 직접 비교할 수 없다.

## 6. Step 4 PostgreSQL/pgvector full 참고 결과 (`3c19d8dc`)

이 run은 full official role/order의 182,159 probes와 3,000 gallery identities를 사용했지만, evaluator는 `normalized mean template + pgvector cosine distance` adapter다. 공식 MATLAB의 `mean template + Euclidean distance + 1,000 threshold grid`와 동일한 baseline이 아니다.

### 6.1 검색 정확도

| profile/mode | rank-1 | rank-20 | AUC TPIR20–FPIR |
|---|---:|---:|---:|
| Origin512 exact | 4.2649% | 16.8479% | 0.075996 |
| Origin512 HNSW | 4.2649% | 16.8479% | 0.075996 |
| PCA256 exact | 4.1342% | 14.6501% | 0.059270 |
| PCA256 HNSW | 4.1276% | 14.6037% | 0.059221 |

PCA256 exact은 origin 대비 rank-20이 2.20 pp, 상대 약 13.0% 감소했고 AUC는 상대 약 22.0% 감소했다. PCA exact와 HNSW의 top-1 agreement는 99.5751%, mean top-20 Jaccard는 0.9660으로 HNSW approximation 영향은 PCA compression 영향보다 작았다.

Legacy 1,000-grid에서 TPIR20은 약 FPIR 0.1/0.2에서 PCA가 약간 높고 0.3에서는 origin이 높아 curve가 교차한다. 이는 각 curve/test grid에서 다른 threshold를 고른 결과이므로 `PCA가 open-set 성능을 개선했다`는 증거가 아니다.

### 6.2 latency와 저장량

| profile/mode | mean query time |
|---|---:|
| Origin512 exact | 14.8853 ms |
| Origin512 HNSW | 14.8745 ms |
| PCA256 exact | 6.0198 ms |
| PCA256 HNSW | 3.5191 ms |

| relation snapshot | `pg_total_relation_size` |
|---|---:|
| Origin512 | 2,971,402,240 B |
| PCA256 | 1,622,736,896 B |
| PQ auxiliary table | 361,668,608 B |

PCA relation snapshot은 origin보다 약 45.4% 작다. PQ auxiliary table은 약 87.8% 작지만 searchable pgvector vector가 아니므로 검색 저장효율로 표현하면 안 된다.

이 수치는 다음 제약 때문에 운영 참고자료로만 사용한다.

- latency는 mean만 있고 p50/p95, warm/cold, 반복 run, query plan artifact가 없다.
- relation size는 run-scoped clean measurement가 아니라 relation-wide snapshot이다.
- index ensure 시간은 clean HNSW build time이 아니다.
- top run manifest는 `running`, source는 dirty이며 archive가 phase 00/01의 일부 참조 파일을 포함하지 않아 self-contained paper artifact가 아니다.
- PQ artifact는 `IndexPQ.ntotal=0` codec이며 ADC search가 없다.

## 7. 연구 주장 경계

### 현재 결과로 말할 수 있는 것

- 해당 custom LFW 50-identity-gallery protocol에서 PCA256은 50% payload 절감과 관측 primary outcome 보존을 달성했다.
- LFW PCA128은 더 높은 압축률에서 작은 rank 손실만 보였고, PCA64부터 false accept 증가가 뚜렷해지는 sensitivity trend가 있다.
- SurvFace quick은 compression geometry, profile 보존 순서, association 방향을 진단하는 데 유용하다.
- SurvFace full에서 decoded PQ128은 origin rank 결과를 PCA 계열보다 잘 보존했다.
- 별도 PostgreSQL full adapter에서 PCA256은 relation size/mean query time 감소와 rank-20/AUC 손실의 trade-off를 보였다.
- Step 5는 공통 실행, subset rebase, resume, provenance 기록을 개선했지만 평가 계약 전체를 완료한 것은 아니다.

### 현재 결과로 말하면 안 되는 것

- PQ ADC 또는 PQ code-search가 검색 latency/저장량/정확도를 개선했다.
- nominal FPIR 1%/10%가 test에서 보장됐다.
- DB cosine adapter가 공식 QMUL-SurvFace MATLAB 결과를 재현했다.
- LFW 결과가 공식 LFW verification 성능 또는 대규모 gallery 성능을 뜻한다.
- 작은 reconstruction angle이 검색 점수·순위 보존을 보장한다.
- Grad-CAM correlation이 compression error의 원인이거나 saliency fallback이 DIR/FPIR을 개선한다.
- Quick 0.5 absolute metric이 full metric을 대표한다.

## 8. 개선점과 우선순위

아래는 분석 결과에 따른 제안이며 이번 작업에서 구현하지 않았다.

### P0: 논문 결과 확정 전에 필수

1. **Calibration/evaluation contract 수정**
   - calibration과 test의 gallery 규모를 맞추거나 100/500/1,000/1,500/3,000 identity sensitivity를 사전 정의한다.
   - frozen origin과 recalibrated compressed threshold를 분리하고 comparator/tie policy를 명시한다.
   - profile/policy마다 FP count/denominator, realized FPIR, DIR count/denominator, binomial 또는 identity-cluster CI를 저장한다.
   - compressed profile 비교는 matched realized FPIR 또는 전체 DIR–FPIR curve로 수행한다.

2. **PCA 검색거리 계약 검증**
   - inverse-transformed reconstruction geometry와 centered PCA search-space cosine을 별도 metric family로 명시한다.
   - projected-vector cosine, reconstructed-vector cosine, 필요 시 whitening/mean 처리 ablation을 동일 split에서 비교한다.
   - 작은 reconstruction angle을 retrieval preservation proxy로 사용하는 해석을 중단한다.

3. **실제 PQ ADC baseline 구현·검증**
   - original float query 대 PQ-coded gallery의 exhaustive ADC를 우선 baseline으로 둔다.
   - Faiss index의 `add/search`, `ntotal`, codes/codebook/index bytes를 artifact로 저장한다.
   - exact decoded search와 ADC를 별도 `search_family`로 보고한다.
   - candidate recall@K, exact rerank/fallback, p50/p95 latency를 측정한다.

4. **Paper-final SurvFace lineage 고정**
   - 하나의 clean Step 5 commit과 동일 checkpoint/preprocess/evaluation contract로 full run을 동결한다.
   - run 시작 commit뿐 아니라 phase별 implementation hash와 algorithm version을 기록한다.
   - `cccb59d5` phase 05의 사후 streaming implementation 차이를 해소한다.

5. **Immutable compact result artifact 추가**
   - raw ledger와 독립적으로 profile/policy별 hashed compact summary를 보존한다.
   - summary에 schema, row count, SHA-256, numerator/denominator, CI, source ledger hash를 기록한다.
   - completed run의 기존 raw artifact는 수정하지 말고 별도 correction/summary artifact로 남긴다.

### P1: 해석 타당성 강화

1. LFW retrieval output에서 `probe_type`을 보존해 known-unknown/unknown-unknown FPIR을 직접 산출한다.
2. LFW에서 38개 alignment 실패와 99.71% coverage를 보고하고 제외 민감도를 확인한다.
3. LFW PQ fit에 실제 development-only 추가 데이터 또는 적절한 centroid/nbits 설정을 사용한다. 현재 7,742 training points는 Faiss 권고 9,984보다 적다.
4. Quick와 full을 두 방식으로 분해한다.
   - 각 scope에서 refit하는 현재 방식: pipeline/profile-order 진단
   - full에서 compressor/threshold/gallery를 freeze하고 probe만 subset하는 방식: 순수 표본 안정성 진단
5. 여러 deterministic quick seed를 실행해 absolute metric이 아니라 rank/geometry/association의 분산을 추정한다.
6. 공식 mean/Euclidean baseline과 DB normalized-mean/cosine baseline을 `baseline_family`로 분리한다.

### P1: Saliency 검증

1. SurvFace target을 config/manifest에 `origin_top1_gallery_cosine`으로 정확히 기록하고 artifact에서 validation한다.
2. Quick/full 비교 시 full gallery를 freeze하거나 probe-independent target을 사용한다.
3. SurvFace에도 high/low/random occlusion faithfulness를 수행한다.
4. 사전 지정한 소수 가설 또는 FDR 보정을 적용하고 effect size를 중심으로 보고한다.
5. origin score/margin, pose, blur, quality, face coverage를 통제한다.
6. saliency를 실제 accept/reject/exact-fallback 정책에 연결해 matched-FPIR DIR 및 비용을 held-out set에서 검증한다.

### P2: 시스템 기여 검증

1. 동일 clean lineage에서 PostgreSQL/pgvector exact/HNSW를 재실행한다.
2. run-scoped table/index size, clean build time, query plan, warm/cold p50/p95 latency, recall을 기록한다.
3. PQ는 Faiss ADC 시스템 결과로 분리하고 pgvector PQ vector처럼 표현하지 않는다.
4. candidate recall과 exact rerank 비용을 측정하고 certificate가 candidate-conditioned임을 명시한다.
5. 대형 CSV join은 compact columnar 형식 또는 정규화된 top-k table로 바꾸고, 분석용 요약은 별도 보존한다.

## 9. 최종 연구 판단

현재 Step 5 결과에서 가장 방어 가능한 핵심은 다음 세 가지다.

1. **LFW custom protocol:** PCA256은 50% payload 절감에서 관측 성능을 보존했다. PCA128은 다음 실험 후보지만 더 큰 gallery 검증이 필요하다.
2. **SurvFace:** quick 0.5는 geometry/association/profile-order 진단에는 유용하지만 absolute 성능은 full보다 낙관적이다. Full에서 PQ128 decoded-search가 rank를 가장 잘 보존했으나 실제 ADC 근거는 아니다.
3. **DB 운영 참고:** 별도 full adapter에서 PCA256은 저장량·평균 지연 감소와 rank-20/AUC 손실의 trade-off를 보였다. provenance와 측정 계약 때문에 paper-final 시스템 결과는 아니다.

연구의 다음 병목은 압축률 자체가 아니라 **gallery-size-aware calibration, matched-FPIR 평가, PCA search-space 계약, 실제 PQ ADC, clean run lineage**다. 이 다섯 항목을 먼저 해결해야 압축 프로파일과 exact fallback/DB 비용을 공동 최적화한다는 논문 기여를 안전하게 주장할 수 있다.
