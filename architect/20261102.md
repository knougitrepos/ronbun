# 2026-11-02 KST — FaceX-Zoo 전처리의 검증 기반 재개

상태: 구현됨. 검증 결과는 아래에 별도 기록한다. 실제 대용량 재개는 미실행.

## 배경과 유지하는 결정

01 VGGFace2 전처리 중 Windows 0x133 오류로 재부팅되어 완료 report 없이
manifest 마지막 행과 train list가 불일치했다. 20261101의 학습 조건과
20261028 이후 외부 저장소 경계, 데이터 분할, 정렬/리사이징 정책은 유지한다.
FaceX-Zoo fine-tune 내부에 복구 실행 경로를 추가하며 ronbun 소비 계약은 변경하지 않는다.

## 결정과 구현

- `fine-tune/modules/alignment_resume.py`: 입력 목록/정책/복구 코드 계약,
  OS lock과 사망한 같은 호스트 PID lock 회수, 순차 journal, 원본·출력 hash/decode 검증.
- 시작 계약이 없는 과거 중단 출력은 현재 변환 결과와 픽셀 비교하여 PNG 재사용을 결정한다.
  무조건 빠른 skip은 하지 않는다. 새 journal의 검증된 기록은 hash와 decode를 통해 재사용한다.
- 잘린 마지막 행과 orphan 이미지를 복구한다. 내부 행 손상/순서/label/출처 변경은 중단한다.
  교체 이미지와 게시 전 metadata는 recovery 시도 폴더에 보존한다. 원본 데이터는 변경하지 않는다.
- 완료 artifact는 검증만 한다. report 게시 후 COMPLETED 직전 중단은 전체 검증 후 marker를 복구한다.
- CLI `--resume` → process_runner `resume` → 01/03 `RESUME_PREPROCESSING` 연결.
  `PREPROCESS_MAX_IMAGES=None`만 지원한다. 새 출력도 같은 경로에서 시작 가능하다.
- 학습 epoch checkpoint resume와 별개이며 02/04 기능을 변경하지 않는다.

## 재실행과 한계

커널 재시작 후 01 설정부터 실행한다. archive가 이미 추출되어 있으면
EXTRACT_TRAIN_ARCHIVE=False로 둔다. 최초 legacy 검증도 수백만 이미지를 읽고 변환하므로
시간이 걸린다. Windows crash 원인 자체는 해결하지 않는다. 새 코드/정책/분할로
contract가 달라지면 자동 승인하지 않는다. 살아 있는 PID·다른 호스트 lock은 수동 확인한다.
recovery metadata/교체 파일은 자동 정리하지 않으며 외부 dataset root에 남긴다.
학습 KEEP_RAW_RESULTS와 무관한 준비 cache로 취급한다. 기존 원본 Git ignore 정책을 유지한다.

## 검증 기준

신규·기존 완료·반복 중단·실제 자식 프로세스 강제 종료·stale/live/foreign lock·잘린 JSONL·
orphan/손상 PNG·입력 변경·부분 실행 거부·CLI 전달을 검사한다. 최종 결과는 기존
verify_alignment로 source/order/label/hash/전체 coverage를 검증한다. 실제 완료 전처리,
parent 학습 또는 인식 성능 검증으로 해석하지 않는다.


검증 결과: 재개 전용 10개를 포함한 관련 테스트 31개 통과(실제 자식 프로세스 os._exit 중단 포함).
01/03 계획 모드 순차 실행 통과. 기존 실제 VGGFace2 첫 3개 이미지의 현재 cropper 픽셀 대조 일치.
전체 suite는 사용자 노트북 EXECUTE=True/저장 출력과 배포용 safe-default 조건의 충돌로
실패했으며 실제 입력 점검까지 이어져 중단했다. 전체 테스트 통과로 보고하지 않는다.
검증 기록: publish/support/alignment_resume_20261102/verification.json.
실제 중단 폴더는 수정하지 않았고 장시간 재개/정식 학습은 시작하지 않았다. 커밋·푸시 미실행.


## 재개 실행 오류의 진단 경로 보완

사용자 01 출력에는 CalledProcessError(exit 1)만 남고 자식 traceback이 저장되지 않았다.
기존 실패의 근본 원인은 이 기록만으로 확정할 수 없다. process_runner에 명시적
UTF-8 stdout/stderr pipe와 launch별 console.log 저장을 추가했다. 새 실행 실패는
노트북에도 원인 traceback을 표시한다. interrupt는 자식을 종료하고 재개 산출물을 보존한다.
재개/전처리 관련 19개 테스트 통과. 실제 VGGFace2 3장 복사본과 공식 landmark를 사용한
CLI --resume 점검은 completed=true, reused=3, regenerated=0으로 통과했다.
진단 경로: C:/ronbun/tmp/resume_cli_diagnostic/49ccff390e2e48c9be19ad4da88f2e58.
실제 207만 장 중단 폴더는 변경하지 않았다. 이 bounded 성공으로 이전 실패 원인 해결이나
대용량 복구 완료를 주장하지 않는다.
