## 1. 변경 배경

기존 `thesis3`는 압축 ArcFace 임베딩을 PostgreSQL/pgvector에서 검색하고, 불확실한 결과를 원본 512D exact 검색으로 재탐색하는 시스템 완성을 목표로 했다. 이 구조에서는 fallback이 강한 압축에서 발생하는 실패를 최종 결과에서 가릴 수 있고, 시스템 구성 요소가 많아 각 FR 표현의 압축 민감도를 독립적으로 설명하기 어렵다.

연구 목적을 다음과 같이 좁힌다.

> 사전학습된 FR checkpoint의 임베딩에 post-hoc 압축을 적용했을 때 모델·데이터 품질·압축 강도에 따라 embedding geometry, score, rank 및 open-set 성능이 어떻게 변하는지 원본 결과로 대체하지 않고 분석한다.

연구 결과물은 서비스 파이프라인이 아니라 재현 가능한 비교 실험, 압축별 artifact 및 특성 분석표다.

## 2. 핵심 결정

### 2.1 FR 모델

계획 모델은 다음 세 계열이다.

| 표시 이름 | 비교 역할 | 현재 구현 상태 |
| --- | --- | --- |
| ArcFace | 고정 additive angular margin 기준 | InsightFace `buffalo_l` 경로만 구현됨 |
| AdaFace | 품질 적응형 margin | adapter/checkpoint 미구현 |
| MagFace | magnitude와 품질을 연결한 표현 | adapter/checkpoint 미구현 |

세 이름은 엄밀히는 서로 다른 학습 objective 계열이다. 동일 backbone·학습 데이터·전처리를 보장하지 못하면 결과를 loss의 인과효과가 아니라 **사용한 checkpoint 수준의 비교**로 보고한다. 입력 정렬, 색상 순서, 정규화, embedding 차원 및 checkpoint hash를 반드시 기록한다.

L2 정규화 전 feature norm은 AdaFace/MagFace의 품질 관련 분석에 필요할 수 있으므로, 모델 adapter 확장 시 정규화 벡터와 raw norm을 함께 보존한다.

### 2.2 데이터셋

현재 확보된 데이터만 구현 범위에 포함한다.

| 데이터셋 | 주 역할 | 해석 경계 |
| --- | --- | --- |
| LFW | 고품질 sanity check, PCA/PQ 학습용 development, 파생 1:N 진단 | 공식 open-set benchmark라고 표현하지 않음 |
| QMUL-SurvFace | 저품질 surveillance 및 공식 open-set 평가 | 공식 gallery/mated/unmated 역할과 순서 보존 |

MegaFace, VGGFace2, RFW 등은 다운로드·사용권·저장공간이 확인되기 전에는 코드의 필수 입력이나 논문 결과 조건으로 두지 않는다.

### 2.3 압축군 분리

PCA와 PQ를 독립 실험군으로 정의한다.

#### 원본 기준선

- `origin_512_fp32`
- 압축 결과의 손실을 계산하기 위한 offline reference다.
- 온라인 fallback 또는 압축 결과 대체에 사용하지 않는다.

#### PCA-only

- `pca_384_fp32`
- `pca_256_fp32`
- `pca_128_fp32`
- `pca_64_fp32`
- `pca_32_fp32`

PCA 출력 차원은 384, 256, 128, 64, 32이며 양자화 bit 수가 아니다. 각 PCA는 development split에서만 학습하고, 변환 벡터는 FP32로 유지한다. 따라서 이 실험은 **차원 축소 민감도**를 측정한다.

#### PQ-only

- PQ 입력은 각 FR 모델의 원본 512D embedding이다.
- 프로파일은 `pq_512_m{m}_b{nbits}`로 표기한다.
- code 크기는 `m × nbits` bit이며 출력 차원 384/256/128/64/32와 혼동하지 않는다.
- PQ code, codebook 및 복원 벡터는 서로 다른 artifact로 기록한다.
- PQ code를 pgvector HNSW 검색 벡터나 FP32 복원 벡터 저장량으로 보고하지 않는다.

#### 제외되는 결합

- PCA 축소 벡터에 다시 PQ를 적용하지 않는다.
- `PCA-d INT8` scalar quantization도 주 실험에서 제외한다.
- OPQ는 내부적으로 회전 후 PQ를 수행하는 별도 방법이므로 Step 1 필수군에 넣지 않는다.
- 결합 압축은 향후 명시적인 ablation으로 승인된 경우에만 별도 이름과 저장 budget으로 추가한다.

## 3. 연구 질문

1. 동일 FR checkpoint에서 PCA 차원이 감소하거나 PQ code budget이 작아질 때 angular error와 cosine-score drift는 어떻게 증가하는가?
2. ArcFace, AdaFace, MagFace checkpoint 간 압축 민감도 곡선이 다른가?
3. genuine/impostor 분포, threshold crossing, Top-k rank inversion 및 open-set DIR/FPIR 중 어떤 지표가 가장 먼저 악화되는가?
4. LFW와 SurvFace의 품질·도메인 차이가 모델별 압축 민감도에 어떤 영향을 주는가?
5. 원본 threshold 고정 결과와 압축별 threshold 재보정 결과의 차이는 회복 가능한 score shift와 비회복 rank/geometry 손실을 구분하는가?

## 4. 실행 범위 제어

모든 데이터셋 노트북 상단에서 다음 설정을 노출한다.

```python
MODE = "dev"            # "dev" 또는 "real"
DATA_FRACTION = 0.10     # 0 < fraction <= 1
SEED = 42
```

공통 Python 모듈의 `ExperimentScope`가 값을 검증하고 실제 선택을 수행한다.

### 4.1 `dev`

- 코드·경로·artifact schema를 빠르게 확인하는 비논문 실행이다.
- `DATA_FRACTION`을 적용할 수 있다.
- identity를 deterministic hash로 먼저 선택하고 해당 identity의 행을 모두 유지한다.
- 같은 seed에서 작은 fraction의 identity 집합은 큰 fraction의 부분집합이 되도록 nested subset을 만든다.
- 결과에는 `dev`임을 기록하며 정식 성능으로 인용하지 않는다.

### 4.2 `real`

- 논문용 전체 프로토콜 실행이다.
- 기본값과 정식 보고는 `DATA_FRACTION=1.0`이다.
- SurvFace 공식 순서와 역할을 보존한다.
- 1.0 미만의 scale 실험이 필요하면 정식 benchmark 결과와 분리하여 `fraction ablation`으로 표기한다.

### 4.3 open-set 안전 조건

- 행을 먼저 무작위 표본추출하지 않는다.
- development, calibration, test identity는 겹치지 않는다.
- gallery identity는 enrollment와 registered probe를 구성할 최소 이미지 수를 만족해야 한다.
- unknown identity는 gallery에 절대 포함하지 않는다.
- SurvFace subset은 gallery identity와 해당 registered probe의 연결을 함께 보존하고, unmated probe는 역할별로 결정론적으로 선택한다.
- 낮은 fraction에서 FPIR 표본 수가 부족하면 해당 운영점은 계산 불가로 표시하며 0으로 채우지 않는다.
- PCA-384 학습에는 최소 384개보다 많은 유효 development vector가 필요하다.
- PQ `nbits=8`은 codebook 학습 표본이 부족할 수 있으므로, 조건 미충족 시 설정을 몰래 낮추지 않고 해당 프로파일을 명시적으로 skip/fail 처리한다.

## 5. 데이터·모듈 흐름

```text
LFW / SurvFace image manifest
    → ExperimentScope(mode, fraction, seed)
    → identity/protocol-aware deterministic subset
    → 모델별 정렬 crop 및 embedding 추출
       → normalized 512D embedding
       → raw feature norm 및 모델/checkpoint lineage
    → development-only compressor fit
       ├─ PCA-only: 512D → dD, d ∈ {384,256,128,64,32}
       └─ PQ-only: 512D → PQ code, (m, nbits)
    → calibration/test에 동결 compressor 적용
    → 원본과 압축 결과를 동일 probe/template 단위로 paired 평가
    → 데이터셋별 결과 artifact
    → 공통 집계·시각화 노트북
```

SurvFace official test에서는 PCA/PQ를 fit하지 않는다. 확보된 `training_set`을 identity-disjoint development/calibration으로 나누어 compressor와 threshold를 학습하고 공식 gallery/mated/unmated test에는 동결 적용한다. LFW development에서 학습한 compressor를 SurvFace에 적용하는 경우는 별도의 cross-dataset transfer 실험으로 명시한다.

## 6. fallback 및 시스템 경계

- 새 Step 1 결과에는 accept/reject/defer 후 원본 exact fallback을 적용하지 않는다.
- 압축 결과가 실패하더라도 원본 identity, score 또는 decision으로 교체하지 않는다.
- 원본 512D 계산은 paired degradation을 측정하는 offline baseline으로만 수행한다.
- 기존 `research/search/open_set.py`, certification 및 LFW fallback 코드는 과거 실험 재현을 위해 즉시 삭제하지 않는다.
- 새 설정에서 certification/fallback을 비활성화하고 새 노트북은 해당 경로를 호출하지 않는다.
- PostgreSQL/pgvector 및 HNSW latency는 Step 1의 주 기여가 아니다. PCA 검색 표현의 보조 시스템 측정으로만 유지할 수 있다.

## 8. 결과 artifact와 지표

모든 결과 행은 최소 다음 식별자를 가진다.

- `run_id`, `mode`, `data_fraction`, `seed`
- `dataset`, `protocol_role`, `split`
- `model_name`, `checkpoint_hash`, `preprocessing_hash`
- `compression_family`, `compression_profile`
- PCA: `source_dim`, `output_dim`, `dtype`
- PQ: `source_dim`, `m`, `nbits`, `code_bytes`, `codebook_bytes`
- `probe_id`, `identity_id` 또는 개인정보를 노출하지 않는 안정적 key

핵심 지표는 다음과 같다.

- embedding: reconstruction MSE, angular error, cosine similarity to origin
- score: genuine/impostor score drift, 분포 간격, threshold crossing
- ranking: Top-1/Top-k identity agreement, rank inversion, Recall@k
- verification: TAR@FAR 또는 데이터셋 공식 지표
- open-set: DIR/TPIR@FPIR, FNIR, FPIR
- calibration 진단: origin threshold 고정 결과와 profile별 재보정 결과
- 효율: vector/code bytes, codebook/metadata bytes, compression/encoding 시간

`agreement_with_origin`과 ground-truth 정확도를 분리한다. 원본과 같다는 사실을 정답으로 해석하지 않는다.

- 브랜치가 `step1`이며 기준 커밋이 기록되어 있다.
- PCA sweep이 정확히 384/256/128/64/32다.
- PQ fit 입력 차원이 512이며 PCA 출력이 PQ 입력으로 전달되지 않는다.
- 모든 노트북에서 `MODE`, `DATA_FRACTION`, `SEED`를 찾을 수 있다.
- 같은 seed의 fraction별 identity 선택이 nested이며 identity 행이 분리되지 않는다.
- LFW split identity가 disjoint다.
- SurvFace 공식 역할·순서가 `real/1.0`에서 변하지 않는다.
- 압축 결과에 fallback 사용 또는 원본 decision 대체 필드가 없다.
- origin agreement와 ground-truth metric이 별도로 계산된다.
- dataset-specific notebook과 common visualization notebook이 유효한 nbformat 문서다.
- 단위 테스트와 notebook 정적 검증이 통과한다.

## 12. 미해결 위험

1. 현재는 ArcFace extractor만 구현되어 세 모델 비교가 아직 불가능하다.
2. 공개 checkpoint의 backbone·학습 데이터·전처리가 다르면 loss 차이로 해석할 수 없다.
3. LFW는 성능이 포화되어 강하지 않은 압축 차이가 통계적 잡음에 묻힐 수 있다.
4. 작은 fraction에서는 PCA/PQ 학습 또는 낮은 FPIR 추정에 필요한 표본 수가 부족하다.
5. SurvFace training identity와 official test identity의 비중복을 artifact 수준에서 검증해야 하며 official test로 compressor를 fit하면 안 된다.
6. PQ의 code budget과 PCA FP32 bytes가 크게 달라 단순 정확도 비교가 공정하지 않을 수 있다. 저장량-Pareto와 family 내부 곡선을 함께 보고한다.
7. dequantize 후 FP32 거리만 계산하면 실제 저비트 검색 latency 향상을 주장할 수 없다.
8. 모델별 raw norm을 L2 정규화 전에 보존하지 않으면 AdaFace/MagFace의 품질 관련 분석이 제한된다.
9. 압축 실패를 fallback으로 가리지 않기 때문에 저차원·저비트 결과가 크게 악화될 수 있다. 이는 오류가 아니라 연구 결과로 그대로 보고한다.

## 13. Step 1 완료 조건

Step 1은 다음 조건을 모두 만족할 때 `구현됨`으로 변경한다.
