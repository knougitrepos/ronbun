### 변경 배경

아직 새 Phase05 결과 CSV를 생성하지 않았으므로 이번 변경은 실험 근거 추가가 아니라

있었다.

- 정책별 최대 `|rho|` 특징을 따로 선택한 표는 동일 특징의 paired `Delta rho`가 아니다.
- generic `threshold_crossing`이 canonical paired-rho 기본 사건에 없었다.
- score 자체는 threshold 정책과 무관해야 하지만 정책 간 불변성 검증이 불완전했다.
- non-ADC 정책/query 쌍 누락, 결측 bootstrap identity, 다른 extraction 간 잘못된 pairing을
  fail-closed하지 못했다.
- 공통 loader가 support gate, scientific grain별 FPIR, Phase05 파일 hash 및 12-run 구현
  동질성을 충분히 검증하지 않았다.

### 결정 내용

1. metric 계약을 `saliency-threshold-metrics-v2`로 올린다.
2. paired primary saliency 특징은 사전 지정된 `outside_face_attention`,
   `saliency_entropy` 두 개를 유지한다. canonical paired 사건은
   `threshold_crossing`, `false_accept_gain`, `tpir_at_rank_k_loss`,
   `tpir_threshold_loss`, `tpir_rank_loss`로 고정한다. 다른 허용 특징·사건은 설정으로
   실행할 수 있지만 `exploratory`로 분류한다.
3. frozen/recalibrated 비교는 같은 sample, identity, extraction 및 사용 가능한 lineage를
   요구한다. 결측·공백 identity와 lineage, query 집합 또는 event applicability 불일치,
   정책 불변 raw score/rank/drift 불일치는 즉시 중단한다.
4. `pq_adc_exhaustive`는 `recalibrated_compressed`만 허용하고 paired 비교에서는 제외한다.
   그 외 score mode는 frozen/recalibrated 두 정책을 모두 요구한다.
5. 사건률 CSV에는 frozen/recalibrated count·rate, resolved/introduced count,
   rate difference와 identity-cluster paired bootstrap CI를 함께 기록한다. paired-rho CSV는
   동일 특징의 `rho_recalibrated - rho_frozen`, CI, event/non-event support와 최소 사건 수를
   기록한다. 최소 support 미달은 rho·CI를 `NaN`으로 억제한다.
6. YAML에서 paired 특징·사건·최소 사건 수·confidence level을 명시하고, Phase05
   implementation manifest에 이 목록과 bootstrap seed/repeats/unit/rank strategy,
   source commit 및 source SHA-256을 기록한다.
7. Phase05가 publish하는 compact CSV 6개의 run-relative path, byte 수, SHA-256을 manifest에
   기록한다. 공통 loader는 이 6개 파일을 exact contract로 확인하고 선택 run 전부의 구현
   fingerprint가 같은지 검사한다.
8. loader는 파일 전체 합집합이 아니라 model/profile/search/protocol/policy/mated/feature/event
   scientific grain별로 FPIR `(0.01, 0.05, 0.10, 0.20, 0.30)`을 정확히 요구한다. paired
   base grain 전체 누락, mated/non-mated 사건 적용 범위 위반, count/rate/transition/CI 및
   analysis tier 모순도 거부한다.
9. 공통 결과 notebook은 primary 사건 목록을 코드 상수에서 읽고, paired-rho를
   `prespecified_primary`이면서 support-eligible인 논문 후보 표와 억제·탐색 진단 표로
   분리한다.

### 현재 구현과 목표 구조

```text
retrieval_metrics.csv + population saliency
  -> score/threshold/TPIR 사건 재계산
  -> frozen/recalibrated query·identity·lineage·score 불변성 검증
  -> paired 사건률 + resolved/introduced + paired CI
  -> 동일 saliency 특징별 paired Delta rho + support gate + paired CI
  -> Phase05 compact CSV 6개 staged publish
  -> Phase05 path/bytes/SHA + implementation fingerprint 기록
  -> cross-dataset loader의 grain별 FPIR·support·provenance 검증
  -> primary eligible 표 / diagnostic 표 분리
```

구현과 합성 검증은 완료됐지만 실제 12-run Phase05 CSV와 공통 보고서는 아직 없다.
따라서 현재 상태는 검증된 capability이며 saliency attenuation에 대한 실험 evidence가 아니다.

  conclusion-grade 결과로 받지 않는다.
