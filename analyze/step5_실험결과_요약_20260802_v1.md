## 5. 수정 필요 사항

1. **ArcFace compact summary 생성**: `scripts/generate_step4_compact_summaries.py`를 ArcFace runs에 대해 실행 → `results/paper/` 에 저장
2. **ArcFace 교차 데이터셋 보고서 생성**: `results/paper/common/arcface/` 디렉토리 미존재
3. **ArcFace population 크기 불일치**: LFW 4,186(vs. 13,195), SurvFace 135,529(vs. 463,341) — 동일 manifest 기반으로 재실행 필요
4. **SurvFace faithfulness 미수행**: 3개 모델 모두 `faithfulness_rows = 0` → Grad-CAM faithfulness 평가 단계 추가 필요
5. **SurvFace saliency coverage_by_protocol_role에 gallery = 0**: gallery 대상 Grad-CAM 미수행, 의도적 설계인지 확인
6. **recalibrated_compressed threshold에서 FPIR 제어 실패**: SurvFace에서 recalibrate 적용 후에도 FPIR > 0.4인 프로파일 다수 — 보정 로직 점검 필요

## 6. 종합 결론

### 공통 현상
- **PCA-384/256**: 두 데이터셋, 세 모델 모두에서 cos > 0.99로 사실상 무손실. 검색 순위 변화도 미미
- **PQ-m128(128B)**: PCA-128(512B) 대비 동등 이상의 왜곡 수준에서 **4배 저장 효율** → 실용적 최적점
- **극단적 압축(pq_m8, pca_32)**: cos < 0.6, agreement < 25%로 검색 신뢰도 붕괴
- **frozen_origin 임계값의 취약성**: 압축으로 점수 분포가 이동하면 FPIR이 비정상 폭증하거나 DIR이 급락
- **MagFace가 AdaFace보다 압축 내성 우수**: 모든 프로파일에서 cos, angular error 모두 MagFace 우위

### 데이터셋 간 차이
- **LFW (고화질, 소규모)**: origin DIR@R1 ≈ 97%, 압축에 의한 rank-1 정확도 저하 미미. 임계값 문제도 상대적으로 경미
- **SurvFace (저화질, 대규모)**: origin DIR@R1 ≈ 2%, 원본 자체가 어려운 과제. 압축 시 FPIR 폭증이 더 심각. 단, 대규모 데이터 덕분에 PCA/PQ 학습 왜곡은 LFW보다 낮음
- **핵심 인사이트**: 데이터 품질이 낮을수록 압축 후 임계값 보정이 더 중요하며, 단순 frozen_origin 정책으로는 open-set 운영 불가
