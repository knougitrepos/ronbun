## 19:14 KST — 공통 보고서의 최종 run 선택 종속 계약 동기화

- 작성일: 2026-09-03 (KST)
- 상태: 검증됨. 현재 ArcFace 무-SDC 결과에 대한 자동 선택 및 보고서 전체 dry-run과 관련 회귀 테스트를 통과했다.
- 이전 결정과의 관계: `architect/20260901.md`의 model UID 기반 선택, SDC all-or-none 및 명시적 통합 실행 토글을 유지·보완한다.

### 변경 배경

`00_cross_dataset_results.ipynb`의 최초 자동 선택은 ArcFace 20260829 campaign을 골랐지만, 사용자가 드롭다운에서 20260902~20260903의 새 LFW·SurvFace·RFW-Custom run으로 바꾼 뒤에도 PQ SDC, faithfulness 크기 및 TinyFace 경로가 최초 campaign 값으로 남았다. 새 run에는 SDC가 없는데 이전 `((128, 8),)` 계약으로 검증되어 search-mode coverage mismatch가 발생했다.

### 결정 내용과 데이터 흐름

1. 상단 `EXPECTED_PQ_SDC_SETTINGS=None`은 최초 자동 후보가 아니라 드롭다운까지 반영된 최종 3개 run에서 추론한다.
2. 최종 run은 source commit, 실행 mode, data fraction, paper-run 여부 및 PQ SDC 설정이 모두 같아야 한다. 혼합 선택은 fail-closed로 거부한다.
3. faithfulness 자동 크기 선택은 최종 `SELECTED_RUN_IDS`로 다시 계산한다.
4. TinyFace 자동 선택은 최초 날짜형 campaign ID 대신 최종 open-set run과 같은 model UID, source commit 및 SDC 계약을 가진 유일한 completed evaluation만 허용한다. 없으면 supplementary를 생략하고, 둘 이상이면 모호성 오류로 중단한다.
5. model UID 자동 선택은 우선 기존 날짜형 campaign을 검사하고, 배치가 자정을 넘긴 경우 동일 source commit·mode·data fraction·paper-run·SDC 계약 아래 각 데이터셋 run이 정확히 하나씩인 cohort도 허용한다. 동일 계약에서 한 데이터셋이 반복 실행된 경우에는 임의 최신 선택 없이 모호성으로 거부한다.

```text
model UID 기본 cohort(같은 날짜 또는 자정 경계의 동일 실행 계약) 또는 사용자 드롭다운
  -> 최종 LFW / SurvFace / RFW-Custom run 3개
  -> 공통 provenance와 SDC 계약 검증
  -> SDC search-mode 기대 집합 산출
  -> faithfulness artifact 크기 재선택
  -> 동일 source 계약의 TinyFace 선택 또는 생략
  -> summary schema와 search-mode 검증
```

### 영향 범위와 재실행 범위

- 수정: `notebooks/common/reports/00_cross_dataset_results.ipynb`
- 자동 선택 모듈: `research/evaluation/report_selection.py`
- 회귀 테스트: `tests/research/test_notebook_layout.py`, `tests/research/test_report_selection.py`
- 기존 completed run과 `results/paper` artifact는 수정하거나 삭제하지 않는다.
- 보고서 노트북 커널을 재시작하고 처음부터 다시 실행해야 한다. 얼굴 임베딩, Grad-CAM, 압축 및 retrieval 실험 재실행은 필요 없다.

### 검증 기준과 미해결 위험

- 현재 새 ArcFace 3개 run을 선택하면 SDC 계약이 `()`로 계산되고 `pq_sdc_exhaustive`를 기대하지 않아야 한다.
- faithfulness는 세 run에 실제 공통으로 존재하는 artifact 크기를 선택해야 한다.
- 같은 source 계약의 TinyFace가 없으면 오류 없이 미포함되어야 한다.
- 저장 노트북은 유효한 JSON·Python AST이고 실행 output과 execution count를 제거한다.
- 현재 run ID에는 배치 전체를 직접 식별하는 공통 orchestration UID가 없다. 이번 보완은 동일한 불변 실행 계약과 데이터셋별 유일성을 이용해 자정 경계를 처리한다. 향후 동일 commit·동일 계약으로 같은 데이터셋을 반복 실행하면 자동 선택은 의도적으로 중단되므로, 배치 공통 orchestration UID를 manifest에 기록하는 개선은 남아 있다.

## 20:21 KST — FIQA 단계 C의 ADC score replay 스키마 수정

- 작성일: 2026-09-03 (KST)
- 상태: 구현됨. 단위·회귀 테스트는 통과했으며 실제 160,408-query calibration replay와 다섯 threshold 재현은 재실행 검증이 필요하다.
- 이전 결정과의 관계: `architect/20260902.md`의 “calibration ADC search replay only” 결정을 유지하고, 실제 구현이 불필요한 origin cosine retrieval schema에 의존하던 오류를 제거한다.

### 변경 배경과 원인

FIQA 단계 C의 `replay_survface_adc_condition_scores()`가 `origin_cosine_retrieval()`의 경량 결과를 `compare_pq_adc_retrieval()`에 전달했다. 전자는 origin top-k 목록을 의도적으로 보존하지 않지만 후자는 `origin_top_k_gallery_ids`, identity ranking, score ranking 및 latency 열을 요구하므로 실제 실행에서 `KeyError: origin_top_k_gallery_ids`가 발생했다. FIQA calibration은 compressed ADC score와 Rank-1/Rank-20 correctness만 사용하므로 origin 비교 전체를 생성할 필요가 없다.

### 결정 내용과 데이터 흐름

1. calibration protocol과 frozen PQ-m128 codec은 기존과 동일하게 재사용한다.
2. ADC search의 distance와 index에서 `negative_squared_l2_adc` score, mated 여부, Rank-1 및 Top-K correctness를 직접 구성한다.
3. origin cosine retrieval과 광범위한 Step-4 comparison row 생성을 단계 C에서 제거한다.
4. 생성된 calibration score로 기존 persisted Step-4의 다섯 ADC threshold를 `1e-12` 이내에서 재현해야만 condition artifact를 기록하는 fail-closed 감사는 유지한다.

```text
completed SurvFace run + frozen PQ-m128 codec
  -> calibration protocol 복원
  -> ADC search 1회
  -> compressed score / Rank-1 / Rank-20 최소 frame
  -> persisted threshold 재현 감사
  -> condition score artifact
```

### 영향 범위와 재실행 범위

- 수정: `research/experiments/fiqa_threshold_calibration.py`
- 회귀 테스트: `tests/research/test_fiqa_threshold_calibration.py`
- 기존 FIQA score artifact와 completed Step-4 run은 수정하지 않는다.
- 단계 B는 재실행하지 않고 단계 C부터 다시 실행한다. 실패 시점에는 condition artifact가 생성되지 않았으므로 삭제할 중간 결과가 없다.

### 검증 결과와 승인 기준

- origin retrieval 열 없이 ADC distance/index만으로 score와 rank correctness를 구성하는 회귀 테스트를 추가했다.
- FIQA calibration 및 compression characterization 관련 테스트 21개와 Ruff 검사가 통과했다.
- 정식 승인 조건은 단계 C 재실행에서 calibration/test row 수가 출력되고, 다섯 `global_threshold_reproduction.absolute_difference`가 모두 `<=1e-12`이며 condition artifact가 completed 상태로 기록되는 것이다.

## 20:57 KST — FIQA 노트북 멱등 순차 실행과 Random faithfulness gate

- 작성일: 2026-09-03 (KST)
- 상태: 검증됨. 모든 실행·쓰기 플래그를 임시로 `True`로 둔 실제 ArcFace top-to-bottom 실행과 관련 회귀 테스트를 통과했다.
- 이전 결정과의 관계: `architect/20260902.md`의 thin/restartable notebook, Random negative-control 및 calibration saliency 누수 차단 계약을 강화한다. 기존 실행 변수와 주석 구획은 유지한다.

### 변경 배경

- 기존 노트북은 B/C/D 셀이 순서대로 배치됐지만 `RUN=True`일 때 완료 artifact가 이미 존재하면 `FileExistsError`로 중단됐다. 모든 단계 플래그를 함께 켠 재실행이 멱등하지 않았다.
- High−Low CI만 양수인 경우에도 saliency 보정을 허용하면, Random occlusion이 High보다 더 큰 현재 SurvFace 결과를 무시하게 된다. Random은 threshold feature가 아니지만 strong faithfulness의 필수 음성 대조군이어야 한다.

### 결정 내용과 데이터 흐름

1. `OVERWRITE_OUTPUTS=False`에서 B/C/D의 완료 artifact가 있으면 SHA-256 loader와 현재 run/model/profile lineage 검증 후 재사용한다. artifact가 없을 때만 B → C → D 순서로 생성한다.
2. `WRITE=True`인데 대응하는 `RUN=False`인 모순 설정은 설정 셀에서 즉시 거부한다. 완료 artifact의 의도적 재생성은 기존 `OVERWRITE_OUTPUTS=True` 계약으로만 허용한다.
3. faithfulness summary는 manifest와 파일 SHA-256을 검증해 선택한다. `Random`은 보고 및 negative control에만 사용하고 threshold feature로 노출하지 않는다.
4. strong faithfulness는 identity-cluster bootstrap의 `High−Low`와 `High−Random` paired CI 하한이 모두 0보다 클 때만 통과한다. 실패하면 gated High/Low contrast를 0으로 만든다.
5. 실제 saliency correction 활성화에는 strong faithfulness 통과와 calibration/test saliency coverage readiness 통과가 모두 필요하다. 현재는 두 gate가 모두 통과하지 않으므로 correction은 0이며 새 threshold는 생성하지 않는다.

```text
사용자 설정 셀
  -> B: 완료 FIQA 검증·재사용 또는 새 생성
  -> C: 완료 ADC condition score 검증·재사용 또는 새 생성
  -> D: 완료 Global/FIQA 비교 검증·재사용 또는 새 생성
  -> verified faithfulness summary
       -> High−Low paired CI gate
       -> High−Random paired CI gate (Random negative control)
  -> calibration/test saliency coverage gate
  -> 둘 다 통과할 때만 향후 saliency correction 후보
```

### 영향 범위와 재실행 범위

- 사용자 노트북: `notebooks/calibration/00_fiqa_conditioned_threshold_calibration.ipynb`
- canonical gate: `research/evaluation/saliency_faithfulness.py`, `research/evaluation/__init__.py`
- 회귀 테스트: `tests/research/test_saliency_faithfulness.py`, `tests/research/test_fiqa_calibration_notebook.py`
- 기존 completed run과 `results/calibration`, `results/paper` artifact는 수정하지 않았다.
- 사용자는 안전 기본값을 유지하거나 필요한 모든 RUN/WRITE 플래그를 함께 켜고 위에서부터 한 번 실행할 수 있다.

### 검증 결과와 미해결 위험

- 실제 GTX 1080 Ti에서 S/L smoke가 각각 64/64 finite였고, 모든 B/C/D 플래그가 `True`인 상태에서 세 완료 artifact가 `reused_verified`로 처리돼 top-to-bottom 실행이 완료됐다.
- 다섯 ADC persisted/reproduced threshold 차이는 모두 0이었다.
- 현재 ArcFace/SurvFace 전체 표본에서 High−Low는 `0.0574695547902`이고 CI 하한은 `0.0567440417339`였지만, High−Random은 `-0.0252778021765`이고 CI 상한도 `-0.0244245290594`였다. strong faithfulness는 `blocked`, gated contrast는 0으로 확인됐다.
- calibration saliency coverage도 0이므로 FIQA+Saliency는 계속 차단된다. 향후 이 coverage를 확보하더라도 Random gate를 같은 calibration 또는 사전 고정된 외부 검증 근거로 평가해야 하며, test 결과를 본 뒤 method를 선택해서는 안 된다.
- 저장 노트북은 다시 안전 기본값과 output-free 상태로 정리한다.
