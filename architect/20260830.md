# 2026-08-30 아키텍처 변경 기록

## 배치 실험의 PQ SDC 전체 제외 토글

- 작성일: 2026-08-30 (KST)
- 상태: 구현됨
- 정식 실험 검증 상태: 미검증 (코드·단위·정적 테스트만 수행하며 full dataset run은 실행하지 않음)

### 변경 배경

`architect/20260829.md`에서는 네 데이터셋의 SDC를 PQ-m128 하나로 제한했다. TinyFace의 큰 gallery에서 m128 SDC도 장시간이 걸릴 수 있으므로, 주 비교인 PCA와 PQ reconstruction·one-sided cosine·ADC는 그대로 유지하면서 SDC 보조 ablation 전체를 한 번에 제외할 수 있는 명시적 배치 실행 선택이 필요하다.

### 결정 내용

- 배치 노트북 상단에 boolean `RUN_PQ_SDC`를 둔다.
- `RUN_PQ_SDC=True`이면 `PQ_SDC_SETTINGS=((128, 8),)`이고, `False`이면 `PQ_SDC_SETTINGS=()`이다. 다른 조합이나 boolean 이외의 값은 fail-closed로 거부한다.
- 기본값은 `False`이다. 이 선택은 LFW·SurvFace·RFW-Custom·TinyFace 네 데이터셋에 동일하게 전달된다.
- 비활성화는 SDC만 제거한다. 모든 기존 PCA 조건과 다섯 PQ codebook의 reconstruction·one-sided cosine·ADC 조건은 유지한다.
- TinyFace 예상 조건 수는 활성화 시 27개, 비활성화 시 26개이다.
- `pq_sdc_settings`는 plan ID와 run config/hash에 계속 포함되므로 활성화 run과 비활성화 run은 호환되지 않는다.
- 후처리와 보고서는 검증을 완화하지 않는다. 완료 run의 immutable config/summary contract에서 기대 SDC 집합을 읽고, 비활성화 계약에서는 SDC 행이 정확히 0개인지 검증한다.
- 활성화·비활성화 completed run이 한 보고서 또는 4모델 x 3데이터셋 행렬에 섞이면 실패한다.

### 데이터 및 모듈 흐름

1. `00_batch_experiment_runner.ipynb`가 `RUN_PQ_SDC`로부터 유일한 `PQ_SDC_SETTINGS`를 계산하고 통합 plan builder에 전달한다.
2. 공통 open-set 세 데이터셋은 `config.step4.compression.families.pq.sdc_settings`, TinyFace는 `config.pq_sdc_settings`에 빈 목록 또는 m128 설정을 기록한다.
3. canonical evaluator는 빈 목록일 때 `pq_sdc_exhaustive` calibration/test와 결과 행을 만들지 않는다.
4. compact search-space는 source run 설정을 summary contract에 고정하고 실제 SDC profile 집합과 정확히 대조한다.
5. cross-model matrix와 cross-dataset report는 선택된 모든 completed run이 동일한 SDC 계약인지 확인한 뒤 동적으로 기대 search mode를 정한다.

## Faithfulness 표본 상한의 배치 노트북 노출

- 작성일: 2026-08-30 (KST)
- 상태: 구현됨
- 정식 실험 검증 상태: 미검증 (기존 artifact를 사용한 읽기 전용 보고서 회귀 검증만 수행)

### 변경 배경과 결정

- 기존 배치 노트북은 `RUN_FAITHFULNESS` 실행 여부만 노출하고 표본 상한은 후처리와 보고서에 `10_000`으로 숨겨져 있었다.
- 상단 parameter 셀에 `FAITHFULNESS_MAXIMUM_SAMPLES = 10000`을 추가한다. 숫자 구분용 underscore는 사용자 설정에서 사용하지 않는다.
- 값은 `None` 또는 boolean을 제외한 양의 정수만 허용한다. 양의 정수는 LFW·SurvFace·RFW-Custom 각각의 표본 상한으로 동일하게 적용하며 세 데이터셋을 합친 총량이 아니다.
- `None`은 제한 없음 계약이다. 각 데이터셋의 전체 eligible candidate를 선택하고 manifest JSON에는 `maximum_samples: null`을 기록한다.
- TinyFace official closed-set 경로에는 faithfulness 후처리를 적용하지 않는다.
- 배치 후처리는 `faithfulness_options.maximum_samples`로 값을 전달하고, cross-dataset report parameter injection과 artifact loader도 같은 값을 사용한다.
- 보고서 manifest의 `maximum_samples_per_dataset`도 선택값을 기록한다.
- faithfulness는 immutable completed run에서 생성하는 파생 artifact이며, 유한 상한은 `faithfulness_v2_n<상한>`, 무제한은 `faithfulness_v2_all` 디렉터리로 분리된다. 따라서 서로 다른 계약의 파생 결과를 같은 경로에서 덮어쓰지 않는다.

### 영향과 재실행 범위

- 영향 노트북: `notebooks/common/orchestration/00_batch_experiment_runner.ipynb`, `notebooks/common/reports/00_cross_dataset_results.ipynb`
- 영향 코드: `scripts/run_integrated_postprocessing.py`
- 표본 상한 변경 자체는 원본 embedding·compression·retrieval run의 science config를 바꾸지 않는다. 완료 source run이 보존되어 있다면 해당 run을 명시적으로 선택해 새 상한의 파생 faithfulness artifact만 생성할 수 있다.
- 이 구현 작업에서는 기존 run/result를 삭제하거나 새 full dataset 실험을 실행하지 않았다.

### 검증 결과

- 두 노트북 모두 `nbformat` 및 전체 코드 셀 문법 검증을 통과했다.
- parameter/setup smoke에서 기본값 `10000`, 무제한 `None` 허용과 `0` 거부를 확인했다.
- 후처리 옵션 전달, 사용자 지정 상한 및 무제한 artifact 경로 로드, 보고서 parameter injection 및 노트북 정적 계약 테스트 33개가 통과했다.
- 기존 `faithfulness_v2_n10000` artifact를 선택한 cross-dataset report notebook을 `write_outputs=False`로 실행해 `validated_not_written`을 확인했다.
- `FAITHFULNESS_MAXIMUM_SAMPLES=None`을 주입한 cross-dataset report notebook도 faithfulness artifact 생성 없이 `write_outputs=False`, `INCLUDE_FAITHFULNESS=False`로 실행해 `validated_not_written`을 확인했다.
- 사용자 지정 상한의 정식 데이터 artifact 생성 시간과 결과값은 실제 재실행 후 별도로 검증해야 한다.

## 22:14 KST — Model UID 기반 cross-dataset report campaign 자동 선택

- 상태: 구현됨
- 정식 보고서 쓰기 상태: 미실행 (`WRITE_OUTPUTS=False` 검증만 수행)

### 변경 배경과 결정

- `00_cross_dataset_results.ipynb`를 직접 실행할 때 동일 checkpoint의 LFW·SurvFace·RFW-Custom에 대해 `MODEL_UIDS`와 `RUN_IDS`를 데이터셋별로 반복 입력해야 했다.
- 직접 실행의 기본 selector를 단일 `MODEL_UID`로 축소한다. `MODEL_NAME`과 데이터셋별 `MODEL_UIDS`는 UID 접두부와 세 open-set 데이터셋 계약에서 파생한다.
- run은 데이터셋별 최신값을 독립적으로 섞지 않는다. `run_id`의 `YYYYMMDD-RNNN` 접두부를 campaign ID로 사용하고, 세 데이터셋의 report-ready completed run이 모두 있는 최신 campaign만 선택한다.
- 같은 campaign 안에서 model UID, Git commit, 실행 mode, data fraction, paper-run 여부와 PQ SDC 설정이 모두 같아야 한다. 누락·중복·혼합은 fail-closed로 거부한다.
- 같은 model UID와 campaign의 completed TinyFace run이 있으면 closed-set supplementary 결과로 자동 포함한다. open-set campaign과 Git commit 또는 PQ SDC 계약이 다르면 거부한다.
- 배치 runner가 검증된 명시적 run 경로를 주입하는 기존 `CROSS_DATASET_REPORT_PARAMETERS_INJECTED` 계약은 유지한다.
- 직접 실행의 faithfulness 상한은 현재 campaign artifact 계약과 맞춰 `None`으로 두어 LFW·SurvFace·RFW-Custom의 `faithfulness_v2_all`을 모두 읽는다.

### 데이터·모듈 흐름과 영향 범위

1. 노트북이 completed Step 4 후보의 identity, campaign ID, 실행 범위, Git commit 및 PQ SDC 설정을 수집한다.
2. `research.evaluation.report_selection.select_model_uid_report_cohort`가 단일 model UID의 최신 완전·동질 campaign을 선택한다.
3. 선택된 세 run ID와 SDC 계약을 기존 report loader에 전달한다.
4. 같은 campaign의 TinyFace completed run을 탐색하고 기존 `load_tinyface_completed_evaluation` 검증 경로로 전달한다.

- canonical selector: `research/evaluation/report_selection.py`
- public API: `research/evaluation/__init__.py`
- 직접 실행 UI: `notebooks/common/reports/00_cross_dataset_results.ipynb`
- 회귀 테스트: `tests/research/test_report_selection.py`, `tests/research/test_cross_dataset_saliency.py`, `tests/research/test_notebook_layout.py`
- 완료 run과 기존 result artifact는 수정하거나 삭제하지 않는다.

- selector 단위 테스트는 최신 완전 campaign 선택, 더 최신인 불완전 campaign 배제, 혼합 commit 거부, 불완전 dataset 집합 거부 및 run ID 형식 검증을 포함해 7개가 통과했다.

## 23:10 KST — Faithfulness artifact 자동 선택과 대용량 결과의 Git LFS 분리

- 작성일: 2026-08-30 (KST)
- 상태: 구현됨
- 보고서 검증 상태: 검증됨 (`WRITE_OUTPUTS=False` ArcFace·AdaFace 실제 artifact 읽기)

### 변경 배경과 결정

- 앞 절의 직접 실행 기본값 `FAITHFULNESS_MAXIMUM_SAMPLES=None`은 `faithfulness_v2_all`만 정확히 선택하므로, `faithfulness_v2_n10000`만 있는 ArcFace campaign의 faithfulness section이 비었다.
- 직접 실행 기본값을 `"auto"`로 바꾼다. 선택된 LFW·SurvFace·RFW-Custom run에 `faithfulness_v2_all`이 모두 있으면 이를 우선하고, 아니면 세 run에 공통으로 존재하는 가장 큰 `faithfulness_v2_nN`을 선택한다.
- 명시적 `None`은 계속 `all`, 양의 정수는 정확한 `nN` 계약을 뜻한다. dataset 사이에 공통 artifact 계약이 없으면 임의 혼합하지 않고 중단한다.
- 자동 선택은 디렉터리와 manifest 존재 여부만 탐색한다. model UID, run ID, sampling 계약, byte 수와 SHA-256의 최종 검증은 기존 loader가 그대로 fail-closed로 수행한다.
- 노트북 사용자 설정 영역의 각 변수에 짧은 역할 주석을 추가하고, 최종 상태에 faithfulness summary 행 수·dataset 수·선택 cap을 표시한다.
- 대용량 row-level CSV는 로컬 payload를 보존한 채 Git LFS로 관리한다. 대상은 common saliency retrieval/threshold-instability, TinyFace per-query, dataset faithfulness rows, LFW·SurvFace run-level saliency retrieval이다. 경량 summary CSV, manifest JSON과 PNG는 일반 Git에 유지한다.

### 데이터·모듈 흐름과 영향 범위

1. 단일 model UID로 동질적 completed campaign과 세 open-set run을 먼저 확정한다.
2. `resolve_common_faithfulness_maximum_samples`가 세 run의 공통 faithfulness 계약을 결정한다.
3. 기존 `load_selected_faithfulness_artifacts`가 선택된 artifact의 lineage와 SHA-256을 검증해 하나의 summary로 결합한다.
4. common report는 결합된 faithfulness summary만 경량 CSV로 내보내며 원시 row CSV는 dataset artifact를 참조한다.
5. Git checkout에서는 LFS가 원본 payload를 복원하고, Git commit 자체에는 작은 pointer가 들어간다.

- canonical loader/selector: `research/evaluation/faithfulness_artifacts.py`
- public API: `research/evaluation/__init__.py`
- 직접 실행 UI: `notebooks/common/reports/00_cross_dataset_results.ipynb`
- 저장 정책: `.gitattributes`
- 회귀 테스트: `tests/research/test_faithfulness_artifacts.py`, `tests/research/test_notebook_layout.py`

### 검증 결과와 재실행 범위

- 자동 선택 단위 테스트는 largest common finite cap, common `all` 우선, 공통 계약 부재 거부를 검증했다.
- 실제 ArcFace `20260829-R001` campaign은 `faithfulness_v2_n10000`을 선택해 3 datasets, summary 90행을 포함했다.
- 실제 AdaFace `20260830-R001` campaign은 `faithfulness_v2_all`을 선택해 3 datasets, summary 90행을 포함했다.
- 두 campaign 모두 새 커널 top-to-bottom 실행이 `computed_not_written`으로 완료됐다. 원본 실험이나 dataset-level faithfulness artifact의 재실행은 필요하지 않다.
- 노트북은 커밋 전에 실행 횟수와 출력을 제거해 restartable source 상태로 유지한다.
- LFS 전환은 CSV의 로컬 내용이나 report manifest SHA lineage를 변경하지 않고 Git 저장 방식만 바꾼다.

### 미해결 위험

- `"auto"`는 서로 다른 cap을 dataset별로 섞지 않는다. 공통 계약이 없으면 하나의 cap artifact를 추가 생성하거나 명시적 선택을 해야 한다.
- LFS payload를 받으려면 clone 환경에 Git LFS가 설치되어 있어야 하며 필요 시 `git lfs pull`을 실행해야 한다.
