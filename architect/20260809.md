# 2026-08-09 Step 7 architecture decisions

## 21:30 KST — EdgeFace 추가 및 RFW 진단 평가 분리

- 작성일: 2026-08-09 (KST)
- 상태: 구현 중
- 작업 브랜치: `step7`

### 변경 배경

기존 정식 비교는 ArcFace, AdaFace, MagFace 체크포인트에 한정되어 있었다.
세 체크포인트는 학습 데이터와 전처리가 완전히 통제된 loss ablation이 아니므로,
모델 계열을 넘어 반복되는 압축 경향을 확인하려면 다른 경량 구조와 학습 소스를
가진 외부 체크포인트가 필요하다. 사용자가 공식 EdgeFace-XS gamma=0.6 가중치를
`models/edgeface/edgeface_xs_gamma_06.pt`에 배치했다. 또한 RFW는 추가 데이터셋으로
사용하되 BalancedFace는 이번 단계에서 유예한다.

### 결정 내용

1. EdgeFace-XS gamma=0.6을 네 번째 checkpoint-level 비교 대상으로 추가한다.
   - family: `edgeface`
   - architecture: `edgeface_xs_gamma_06`
   - training dataset: `webface12m`
   - input: RGB 112x112, `(x - 127.5) / 127.5`
   - strict loader: official `edgenext_x_small` + recursive low-rank linear
     replacement(gamma=0.6)
   - target layer: `model.stages.3.blocks.2.convs.2`
2. MagFace 기본 체크포인트 경로를 의미가 명확한
   `models/magface/magface_ms1mv2.pth`로 변경한다. 체크포인트 내용과 lineage는
   SHA-256으로 구분하며 파일명 자체를 새로운 모델로 해석하지 않는다.
3. RFW는 공식 4-group 10-fold 1:1 verification 진단으로만 사용한다.
   - RFW를 open-set DIR/FPIR 평가로 재명명하지 않는다.
   - RFW 영상/쌍에서 PCA 또는 PQ codec을 fit하지 않는다.
   - LFW 또는 SurvFace development split에서 fit한 frozen codec을 RFW에 적용하는
     cross-dataset transfer만 허용한다.
   - 각 held-out fold의 threshold는 같은 그룹의 나머지 9개 fold에서 선택한다.
4. BalancedFace의 source inventory는 보존하되 Step 7 실행 입력, codec fit,
   threshold calibration에서 제외하고 `deferred_by_step7_scope`로 기록한다.
5. LFW 프로토콜은 현재 코드 구성 그대로 유지한다. query를 고위험/저위험으로
   나누는 uncertainty/defer 실험은 추가하지 않는다.
6. 기존의 두 실행 인터페이스를 모두 유지한다.
   - all-in-one: `notebooks/common/orchestration/00_batch_experiment_runner.ipynb`,
     `notebooks/common/reports/00_cross_dataset_results.ipynb`
   - step-by-step: `notebooks/lfw/**`, `notebooks/survface/**`
   공통 Python 모듈을 canonical 구현으로 사용하되 어느 한 인터페이스를 제거하거나
   합치지 않는다. `ARTIFACT_STORAGE_MODE`, 실행 승인, run 재사용/새 run 선택처럼
   재현성과 비용에 영향을 주는 설정 변수는 유지한다. 정말 제거해야 할 경우 해당
   노트북과 architecture 기록에 삭제 이유, 대체 경로, 재실행 영향을 먼저 남긴다.

### 현재 구현과 목표 구조의 차이

- 구현됨: EdgeFace family/adapter/backbone/strict loader/profile/runner alias,
  MagFace 경로 변경, RFW pair-scoring 평가 함수, BalancedFace 유예 계약.
- 검증 필요: 실제 EdgeFace 체크포인트 smoke test와 Grad-CAM target의 gradient,
  전체 회귀 테스트, LFW/SurvFace full experiment.
- 미구현: RFW tar/BIN에서 112x112 입력을 materialize하고 네 모델의 전체 임베딩을
  추출하는 장시간 실행 단계. 따라서 이번 변경만으로 RFW 수치 결과가 생성되지는
  않는다.

### 데이터 및 모듈 흐름

```text
EdgeFace checkpoint
  -> strict official loader
  -> common PyTorch adapter
  -> unchanged LFW/SurvFace Step 4
  -> origin/PCA/PQ metrics

RFW official pair manifest
  + origin embeddings or externally fitted frozen-codec embeddings
  -> cosine pair scores
  -> group-wise 9-fold threshold selection
  -> held-out accuracy/TAR/FAR and group gap
```

### 영향 범위

- 코드: `research/embeddings/**`, `research/experiments/pipeline_runner.py`,
  `research/evaluation/rfw_verification.py`
- 설정: `configs/experiments/step2_pytorch_gradcam.yaml`,
  `configs/experiments/rfw_balancedface_quantization.yaml`
- 실행 문서: `notebooks/common/orchestration/00_batch_experiment_runner.ipynb`,
  `notebooks/common/orchestration/README.md`
- 환경: `requirements-step2.txt`, `requirements-step2-cu118.lock.txt`
- 테스트: EdgeFace strict-load/adapter, 공통 runner/config, RFW fold 평가 및
  BalancedFace 유예 계약

### 재실행 범위

기존 ArcFace/AdaFace/MagFace 완료 run은 immutable하게 유지한다. EdgeFace는 새
`model_uid`로 LFW와 SurvFace를 각각 새 full run으로 실행해야 한다. RFW 결과는
별도 supplementary diagnostic artifact로 만들며 기존 LFW/SurvFace open-set 표에
동일 metric인 것처럼 합치지 않는다.

### 검증 기준

- EdgeFace 공식 체크포인트가 missing/unexpected key 없이 strict load된다.
- uint8 RGB 입력에서 raw 512D, raw norm, unit-normalized 512D가 유한하다.
- 선언한 Grad-CAM target layer가 존재하고 backward gradient를 받는다.
- 공통 runner가 `edge` 별칭을 EdgeFace profile과 정확한 로컬 경로로 resolve한다.
- RFW 평가에서 held-out fold가 threshold 선택에 포함되지 않는다.
- RFW summary가 `open_set_protocol=false`, `codec_fit_on_rfw=false`를 기록한다.
- LFW의 기존 protocol/config는 바뀌지 않는다.
- all-in-one 및 step-by-step 인터페이스와 사용자 설정 변수의 존재가 유지된다.

### 미해결 위험

- WebFace12M과 RFW의 identity non-overlap 증거가 없으므로 EdgeFace의 RFW 결과도
  headline 일반화 근거가 아니라 보조 진단으로 제한한다.
- 모델들의 architecture, training data, preprocessing가 다르므로 네 모델 비교는
  loss function의 인과 효과를 증명하지 않는다.
- `timm==0.9.16`을 CUDA 11.8/GTX 1080 Ti 환경에서 고정했지만 실제 full run의
  VRAM/throughput은 첫 EdgeFace run에서 기록해야 한다.
- Frozen codec transfer에서는 codec source(LFW 또는 SurvFace)를 결과 행과
  manifest에 명시해야 하며 서로 섞어 하나의 RFW 결과로 평균내지 않는다.

## 05:39 KST — RFW streaming extraction, frozen-codec transfer, codec persistence

- 작성일: 2026-08-09 (KST)
- 상태: 구현됨, 정식 GPU 실험은 미검증
- 이전 결정과의 관계: 21:30 KST 절의 EdgeFace/RFW 분리 원칙을 보완한다. LFW 프로토콜 유지, BalancedFace 유예, RFW supplementary 1:1 경계는 변경하지 않는다.

### 변경 배경

RFW pair evaluator만으로는 raw aligned BIN에서 동일 모델의 임베딩을 재현 가능하게 추출할 수 없었고, 완료된 LFW/SurvFace run은 compact metrics만 남겨 fitted PCA/PQ codec을 다른 데이터셋에 적용할 수 없었다. 또한 기존 저장량 회계는 PQ codebook은 포함하지만 PCA projection/mean은 제외해 비대칭이었다. 실험 seed도 Faiss PQ centroid 학습 seed로 명시적으로 전달되지 않았다.

### 결정 내용

1. RFW aligned BIN은 archive 전체를 이미지 폴더로 풀지 않고 공식 pair 순서에 따라 batch streaming decode한다. archive SHA-256, 네 group, group당 12,000 occurrences와 6,000 labels를 fail-closed 검증한다.
2. RFW origin embedding artifact는 model UID, checkpoint SHA, preprocessing hash, protocol hash, archive SHA, TTA 설정과 산출물 SHA를 고정하고 `_SUCCESS`가 일치할 때만 재사용한다.
3. RFW에는 LFW 또는 SurvFace에서 fit한 codec만 적용한다. codec file SHA, fit source run ID, fit manifest SHA가 모두 필요하며 RFW 평가 함수 안에서는 `fit()`을 호출하지 않는다.
4. PCA는 direct-coordinate cosine과 reconstructed cosine을 분리하고, PQ는 reconstructed cosine과 symmetric ADC negative squared-L2를 분리한다. RFW 결과에는 open-set 지표를 생성하지 않는다.
5. 다음 LFW/SurvFace compression phase부터 실제 사용한 PCA/PQ 객체를 attempt-qualified run artifact로 저장하고 `frozen_codec_manifest.json`에 source dataset/run/model/seed/SHA를 기록한다.
6. PQ experiment seed는 `faiss.IndexPQ.pq.cp.seed`에 전달한다. PCA/PQ 총저장량은 공통 `codec_parameter_bytes`를 사용하며 PCA projection+mean과 PQ codebook을 모두 합산한다.
7. 기존 all-in-one runner/report를 유지하고 RFW에는 `00_data_preparation → 01_embeddings → 02_compression` 단계별 노트북을 추가한다. `ARTIFACT_STORAGE_MODE`, 실행 승인, 쓰기/재사용 설정은 삭제하지 않는다.

### 현재 구현과 목표 구조의 차이

- 구현됨: streaming BIN loader, immutable origin artifact, frozen-codec evaluator, fold-bootstrap CI, EdgeFace report alias, codec 저장 경로, PQ seed, 대칭 storage accounting, RFW 단계별 노트북.
- 미실행: EdgeFace LFW/SurvFace full paper run, EdgeFace RFW 48,000-occurrence extraction, 새 codec manifest를 이용한 RFW transfer.
- 기존 completed run에는 새 codec artifact가 없으므로 소급 생성하지 않는다. 다음 정식 run 이후에만 RFW `CODEC_CONFIGS`를 SHA-pinned 값으로 채운다.

### 데이터 및 모듈 흐름

```text
RFW pair_protocol.csv + RFW_test.tar.gz + model registry JSON
  -> streaming aligned pair batches
  -> common PyTorch adapter
  -> immutable origin_embeddings.npy + occurrence manifest

LFW/SurvFace development embeddings
  -> seeded PCA/PQ fit
  -> attempt-qualified .joblib/.faiss + frozen_codec_manifest.json
  -> SHA-pinned FrozenCodecSpec
  -> RFW direct/reconstruction/ADC pair scores
  -> group-wise 9-fold calibration + held-out metrics + fold bootstrap CI
```

### 영향 범위

- 코드: `research/datasets/rfw_aligned_bin.py`, `research/experiments/rfw_pipeline.py`, `research/evaluation/rfw_verification.py`, compression/Step 4 workflow와 compact-summary generator.
- 설정: `configs/experiments/step2_pytorch_gradcam.yaml`, `configs/experiments/rfw_balancedface_quantization.yaml`.
- 노트북: 기존 common all-in-one 두 파일 유지, RFW embeddings/compression 단계별 두 파일 추가.
- artifact: 다음 LFW/SurvFace run부터 codec 파일과 manifest가 추가되며, 기존 completed run은 변경하지 않는다.
- DB: 이번 변경은 PostgreSQL/pgvector materialization 또는 index schema를 변경하지 않는다.

### 재실행 범위 및 검증 기준

1. 변경 코드를 clean commit으로 고정한 뒤 EdgeFace LFW와 SurvFace full run을 각각 새 run ID로 실행한다.
2. 각 run에서 model/checkpoint/preprocess lineage, CUDA device, codec manifest, PQ seed, codec artifact SHA를 확인한다.
3. RFW 전체 protocol bundle을 생성하고 EdgeFace origin embeddings를 추출한다.
4. LFW-source와 SurvFace-source codec을 섞지 않고 source별 RFW 결과를 별도로 생성한다.
5. 모든 RFW manifest에서 `open_set_protocol=false`, `fit_on_rfw=false`, held-out fold exclusion, 24,000 pair/48,000 occurrence를 검증한다.
6. PCA/PQ storage summary가 `codec_parameter_bytes`를 포함하고 compact summary schema 3에서도 역사적 artifact fallback이 유지되는지 검증한다.

### 미해결 위험

- WebFace12M과 RFW identity overlap이 검증되지 않아 EdgeFace-RFW는 supplementary diagnostic을 넘는 일반화 근거로 사용하지 않는다.
- RFW symmetric ADC는 pair verification을 위한 양방향 점수이며 PostgreSQL/pgvector 1:N latency 증거가 아니다.
- 현재 PQ latency는 exhaustive Faiss 측정이고 IVF-PQ/pgvector ANN 실험이 아니다.
- 새 codec persistence는 다음 run부터 유효하므로 기존 세 모델 결과의 RFW transfer를 만들려면 세 모델의 compression phase를 새 코드로 재실행해야 한다.

## 06:17 KST — 단일 Step 4 후처리 경로와 FPIR 10%/1% 다중 operating point

- 작성일: 2026-08-09 (KST)
- 상태: 구현됨, 정식 v4 파생 산출물 생성은 미실행
- 이전 결정과의 관계: 21:30 및 05:39 KST 절의 완료 run 불변성, LFW
  프로토콜 유지, RFW 보조 진단, BalancedFace 유예 결정을 유지하면서 Step 4
  파생 평가와 공통 보고 계약을 보완한다.

### 변경 배경

기존 정식 결과의 후처리 경로가 모델별로 달랐다. ArcFace는 구형
`generate_step4_compact_summaries.py`가 만든 `summaries`만 있었고, AdaFace와
MagFace는 `refresh_step4_search_spaces.py`가 만든 `search_space_v2` 또는
`search_space_v3_matched_calibration`을 사용했다. 동일 protocol UID만으로 원천
데이터의 유효성은 확인할 수 있지만, producer·schema·검색 공간·calibration
diagnostics가 다른 artifact를 한 논문 표에 섞으면 검증 계약이 비대칭이 된다.
또한 SurvFace의 대표 operating point가 FPIR 10%에만 집중되어 더 엄격한 1%에서의
압축 검색 보존을 함께 확인할 필요가 있었다.

### 결정 내용

1. 여섯 개 기존 ArcFace/AdaFace/MagFace × LFW/SurvFace 완료 run의 원본 artifact는
   변경하지 않는다. 동일한 `scripts/refresh_step4_search_spaces.py`만 사용해
   `results/paper/<dataset>/<run_id>/search_space_v4_multi_fpir`에 새 compact 파생
   산출물을 만든다.
2. PCA/PQ transform과 검색 score 계산은 profile·search mode별로 한 번만 수행한다.
   같은 calibration/test score ledger에서 FPIR 10%와 1% threshold를 각각 선택해
   중복 GPU embedding 추출이나 중복 search를 피한다.
3. retrieval summary grain은 `family × profile × search_mode × threshold_policy ×
   target_fpir`로 확장한다. 압축 geometry summary는 target과 무관하므로 기존
   `family × profile` grain을 유지한다.
4. v4 manifest에는 단일 producer 경로, 두 target FPIR, PCA/PQ family manifest,
   target별 origin calibration signature, compact CSV SHA-256을 기록한다. 각 family는
   `origin_calibration_diagnostics.json`을 별도 보존한다.
5. 공통 보고 노트북은 기본적으로 v4만 허용하고 선택 dataset 사이의 artifact type을
   균질하게 검증한다. v3/v2/legacy 재사용은
   `ALLOW_LEGACY_POSTPROCESSING=True`인 탐색 실행에서만 가능하며 논문 표의 기본
   경로가 아니다.
6. all-in-one runner와 step-by-step 노트북 구조, `ARTIFACT_STORAGE_MODE`, 실행 승인,
   write/reuse 설정은 유지한다. 유지보수 cleanup 노트북은 source checkout이나 DB
   reset을 기본 실행하지 않는 안전값으로 되돌리고 모든 노트북 출력은 비운다.

### 데이터 및 모듈 흐름

```text
immutable completed Step 4 run
  -> one canonical refresh_step4_search_spaces.py
  -> fit/transform/search once per PCA/PQ profile and search mode
  -> calibrate the same scores at FPIR 0.10 and 0.01
  -> PCA/PQ family diagnostics + SHA-256 manifests
  -> search_space_v4_multi_fpir compact merge
  -> homogeneous common report selection
```

### 영향 범위

- 코드: `research/experiments/step2_compression.py`,
  `scripts/generate_step4_compact_summaries.py`,
  `scripts/refresh_step4_search_spaces.py`,
  `scripts/run_integrated_postprocessing.py`
- 설정: `configs/experiments/evaluation_contract_v1.yaml`,
  `configs/experiments/step2_pytorch_gradcam.yaml`
- 노트북: common report의 v4 fail-closed 선택과 유지보수 notebook 안전 기본값;
  all-in-one/step-by-step 구조 및 사용자 실행 변수는 유지
- artifact: 기존 `summaries`, `search_space_v2`,
  `search_space_v3_matched_calibration`은 역사적 산출물로 보존하고 v4를 새 디렉터리에
  생성
- DB: PostgreSQL/pgvector schema나 index는 변경하지 않는다.

### 재실행 범위

코드와 설정을 clean commit으로 고정한 뒤 기존 여섯 완료 run마다 통합
postprocessing만 실행한다. embedding extraction, Grad-CAM, 원본 Step 4 run은 다시
실행하지 않는다. EdgeFace는 아직 완료 run이 없으므로 향후 LFW/SurvFace full run이
생긴 뒤 같은 v4 후처리를 적용한다. 공통 보고서는 선택된 모든 dataset의 v4가
준비된 이후 실행한다.

### 검증 기준

- 단일-target 호출은 기존 결과 행 수와 primary diagnostics 계약을 유지한다.
- 두 target 호출에서 score/search 계산 횟수는 증가하지 않고 retrieval 행만 target
  수에 따라 증가한다.
- 모든 v4 retrieval 행은 target FPIR가 정확히 `{0.10, 0.01}`이고 중복 grain이 없다.
- PCA/PQ origin calibration signature가 target별로 일치한다.
- 공통 보고서는 v4 family manifest와 diagnostics SHA-256을 확인하며 v4/legacy
  혼합을 거부한다.
- 노트북은 output-free이고 all-in-one/step-by-step 구조 및
  `ARTIFACT_STORAGE_MODE`를 유지한다.

### 미해결 위험 및 명시적 유예

- FPIR 1%의 held-out realized FPIR가 목표를 초과하면 해당 target의 threshold-dependent
  주장은 manifest의 `validation_required` 제한을 따른다. 단순히 calibration 목표를
  추가한 것만으로 성능 보장을 주장하지 않는다.
- EdgeFace–RFW identity overlap은 확인되지 않았으므로 RFW 결과는 strict unseen
  identity 일반화 증거가 아니라 supplementary diagnostic이다.
- Faiss IVF-PQ operational ANN baseline은 후속 연구로 유예한다.
- PostgreSQL/pgvector IVFFlat도 실행 시간과 연구 범위 확대 위험 때문에 유예한다.
  현재 latency는 exhaustive search의 단일 관측치일 뿐 안정적인 DB benchmark가 아니다.
