## 현재 실행 방법

완료된 FaceX export와 동일 stem의 `_meta.json`이 필요하다. 현재 설정의
`F:/FaceX-Zoo/fine-tune/checkpoints/exported/adjust1`은 확인 시 존재하지 않았다.
따라서 실제 학습 모델을 임의 선택하거나 등록하지 않았다.

```powershell
py -3.11 -m research.embeddings.facex_zoo "F:/path/to/EXPORT.pt" --registry-root "runs/facex_model_registry"
py -3.11 -m research.experiments.facex_lfw_config --model "surv_arc_s8972=REGISTERED_SPEC.json" --output-dir "configs/experiments/facex_lfw_run1" --artifact-root "F:/ronbun_results/facex_lfw_run1"
```

경로의 EXPORT.pt와 REGISTERED_SPEC.json을 실제 파일·첫 명령의 출력으로 바꾼다.
여러 모델은 `--model`을 반복한다. 생성은 config 준비만 하며 학습·추출을 실행하지 않는다.
01–03의 CONFIG_PATH를 생성된 pairs.yaml로 지정하고 02의 INPUT_CONFIG_PATH=None을 유지한다.
새 모델의 입력을 생성할 때만 PREPARE_INPUTS=True로 설정한다. 커널 재시작 후 순차 실행한다.
새 source 생성은 CUDA가 없으면 중단한다. 실행 안내는 `notebooks/README.md`에 반영했다.

기존 기본 YAML은 기존 네 512D 모델을 계속 가리킨다. 새로운 모델을 자동으로 최신 checkpoint로
대체하지 않는다. FaceX-Zoo 학습 dataset·seed별 alias와 checkpoint UID가 명시된 새 YAML을 사용한다.

SurvFace 권고는 gallery 인물이 FR 학습에서 이미 보인다는 점을 명시한다. 비등록자 fit/safety만
SurvFace downstream fine-tune unseen이며, VGGFace2 부모 학습과의 인물 중복은 별도 감사가 필요하다.
공식 test 전체를 유지하되 training 수가 바뀌므로 UCFace와 동일한 학습 split 재현으로 부르지 않는다.
FaceX-Zoo 기존5,319명 모델은 위 새 holdout 정책 모델로 간주할 수 없다.

주 검증값은 **같은 조건에서 Continuous-FIQA의 Global 대비 TPIR@20 개선과 실제 FPIR**이다.
현재 학습은 비등록자 조건부 score quantile을 적합하며 TPIR@20 직접 최적화가 아니다.
threshold는 순위를 바꾸지 않는다. TinyFace/SCFace의 rank-20으로 평가만 바꿔도 이 점은 같다.
LFW/RFW는 TAR/FMR를 사용하며 이 실험만으로 1:N 효과를 입증하지 않는다.

## 재실행 범위와 남은 경계

새 checkpoint별 FR 임베딩 → PQ → 점수 → 보정을 새로 생성해야 한다.
기존 LFW512 입력은 재사용할 수 있지만 새 fold 경계의 PQ·보정은 별도 campaign에서 재계산한다.
기존 완료 artifact·52개 legacy notebook·원본 데이터·checkpoint는 보존했다.
KEEP_RAW_RESULTS는 기존 정책을 유지한다. 생성된 입력의 상세 payload/cache는 Git에서 제외하고,
검증된 이번 보고서·경량 validation만 선별 노출했다.

현재 01–04는 LFW 실행점이다. 1024D artifact 지원이 PostgreSQL `vector(512)` DB migration,
512D 과거 orchestrator 변경, RFW 공식 workflow, SCFace 입력 준비까지 뜻하지 않는다.
정식 학습·전체 GPU 추론·새 전체 calibration·commit·push는 수행하지 않았다.
