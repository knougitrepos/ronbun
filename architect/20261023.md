기존 완료 결과는 당시 정책의 결과로 보존하며 새 정책의 결과라고 재명명하지 않는다.

## 구현 결정과 데이터 흐름

1. FaceX-Zoo 완료 export + `_meta.json` → `research/embeddings/facex_zoo.py` 검증 → 불변 ModelSpec 등록.
   완료·non-smoke, SHA, embedded/sidecar metadata, source config hash, head·차원·dataset·preprocessing을
   검증하고 state_dict를 strict load한다. source training protocol은 checkpoint hash 안에 보존되며
   이 등록이 학습 인물 비중첩 인증을 뜻하지 않는다.
2. `pytorch/facex_backbone.py`는 upstream parameter 이름과 inference 연산을 보존한다.
   ArcFace/CosFace/MagFace/AdaFace의 backbone을 지원하며 raw feature·norm·normalized feature를 유지한다.
   RGB-source → BGR-model, 112×112, (pixel−127.5)/128을 명시한다. crop/alignment는 입력 artifact 책임이다.
3. ModelSpec/EmbeddingOutput 및 공통 prepared artifact는 512/1024 차원을 검증한다.
   PCA/PQ, Step2 artifact 검색 평가, TinyFace 모듈은 실제 원본 차원으로 학습·명명·비용 집계한다.
   frozen codec replay도 직렬화된 차원과 profile 이름을 대조한다.
4. `facex_lfw_config.py`는 등록 파일로부터 명시적 model_uids·차원·입력 경로를 갖는 inputs/pairs YAML을 만든다.
   같은 head의 dataset/seed가 다른 checkpoint는 다른 alias와 UID로 고정한다. 자동 최신 선택은 없다.
   기존 512D YAML은 기존 명시적 모델 매핑으로 계속 읽을 수 있다.
5. LFW loader는 artifact 선언과 실제 배열 차원을 대조한다. `model_bindings.py`는 producer/evaluator의
   UID·차원 계약을 공유한다. 02는 pair YAML의 input_config_path를 사용하며 서로 다른 모델 경로를 차단한다.
6. `outer_fold_unused_identities`는 people.csv의 10-fold 경계·전체 인물/이미지 수·pair fold 대응을 검증한다.
   PQ fit은 outer fold마다 수행하고 partition seed 사이에서만 재사용한다. codebook cache key에 fold를 넣고,
   people hash·fold별 assignment hash·실제 학습량을 campaign과 inventory에 남긴다.
   현재 fold별 1,302–1,360명 / 1,361–1,438장이다. 원저자 people.txt byte 인증은 미확인이다.
7. 01은 PQ 후보와 fold별 실제 학습량을 구분해서 표시하고, 04는 운영 결과와 paired 비교를 함께 표시한다.

기존 DB 기반 SurvFace Step1 및 512D 고정 과거 orchestrator가 1024D로 전환되었다는 뜻은 아니다.

새 FaceX checkpoint는 FR 임베딩·model UID·codec·점수·보정을 새로 생성한다. 기존 512D artifact를

새 people-fold 정책에서는 PQ와 pair score·calibration을 새 campaign에서 재계산해야 한다.
module/guide hash 변경으로 이전 campaign 재개 namespace가 달라진다. notebook 커널 재시작이 필요하다.
