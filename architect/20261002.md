## 배경과 이전 결정의 변경

사용자는 BLUFR benchmark 성능 곡선보다 공개 LFW 분할을 차용한 압축·독립 threshold 보정을 원한다.

목록 다운로드·해석·검증과 기존 benchmark Python/YAML은 변경하지 않고 보존한다.
기존 matched_calibration은 과거 사용자 정의 test를 유지하는 선택 경로로 남긴다.
전체 LFW를 40/40/20으로 재분할하거나 공개 test를 100명 gallery로 줄이는 안은 적용하지 않는다.

## 확정한 프로토콜

- 공개 10 trials의 train/test 인물·이미지 목록, test gallery 1,000명과 probe 목록 및 순서를 그대로 보존한다.
- 각 trial의 train 1,500명 내부에서 압축 학습:보정을 5:5, 6:4, 7:3, 8:2, 4:6, 3:7, 2:8로 비교한다.
  압축 학습 인물 수는 각각 750, 900, 1,050, 1,200, 600, 450, 300명이다. 나머지가 보정 인물이다.
- 각 trial에서 다중 이미지가 있는 100명을 보정 gallery로 먼저 고정한다. 인물마다 seeded hash로 한 장을 등록하고
  나머지를 mated probe로 사용한다. 다른 보정 인물의 이미지는 non-mated probe다.
  비율의 분모에는 gallery 인물 100명도 포함한다. 동일한 hash 순서로 보정 non-mated 인물을 줄이면서
  압축 학습 인물을 늘린다. 따라서 gallery/mated probe는 일곱 비율 사이에서 고정되고 개발 인물은 nested다.
- 압축 학습·보정·test 인물은 분리한다. 보정 내부 fit/safety 역시 기존 모듈의 identity 분리와 20 seeds를 사용한다.
  이미지 수 비율과 인물 수 비율은 다르므로 역할별 실제 이미지 수를 inventory에 기록한다.
- calibration gallery 100명 → test gallery 1,000명의 불일치를 의도적으로 유지한다.
  calibration은 seeded 등록 이미지, test는 공개 등록 이미지이므로 선택 방식도 기록한다.
  이 설계는 검색 규모·등록 조건 전이의 영향을 제거하지 않으며 FPIR 안정성을 보장하지 않는다.

## 구현과 데이터 흐름

1. `research/datasets/lfw_blufr.py`의 고정 SHA 공개 목록과 원본 face manifest를 대응한다.
2. 새 `research/datasets/lfw_blufr_calibration.py`가 역할·분할 inventory와 assignment hash를 만든다.
3. 새 `research/experiments/lfw_blufr_calibration.py`가 명시적 완료 source와 FIQA의 coverage/lineage/hash를 검사한다.
4. 동일 FR 임베딩을 재사용하되 **각 trial·비율의 개발 인물만으로 PQ codebook을 새로 학습**한다.
   origin cosine 및 PQ ADC에서 보정/test 검색을 각각 다시 계산한다. genuine score와 rank를 함께 사용한다.
5. 기존 `run_origin_pq_split`을 호출하여 Origin+3PQ 각각 Global-safe·FIQA 5-bin·Continuous FIQA를 독립 적합한다.
   test score는 적합·threshold 선택에 쓰지 않는다. 과거 PQ threshold와 gallery 의존 saliency는 전용하지 않는다.

신규 설정: `configs/experiments/lfw_blufr_calibration.yaml`.
4모델×10 trials×7비율의 입력 280개, ×20 fit/safety seeds의 보정 5,600 jobs를 명시한다.
기존 5 FPIR 목표와 PQ m128/m64/m32 조건을 유지한다. 새 모드는 LFW만 실행한다.
DB 스키마·기존 run·원본 전처리 artifact에는 변경이 없다.

영향받는 노트북과 책임:

- LFW 준비 00: `blufr_lists`, 공개 목록 준비만 담당한다.
- 공통 batch 00: `blufr_calibration`, 선택 모델의 읽기 전용 점검만 담당한다. EXECUTE=True도 benchmark를 실행하지 않는다.
- 공통 calibration 01: 새 모드에서 입력/PQ 준비만 선택적으로 수행한다.
- calibration 03: 새 모드의 주 실행점. 입력 준비와 실제 보정을 함께 수행한다. 기본 EXECUTE=False다.
- 공통 reports 00: `blufr_calibration_report`로 명시적 완료 보고서만 읽는다. benchmark 보고 메뉴는 제외한다.

01과 03의 PQ/FIQA 설정이 YAML과 다르면 중단한다. 03의 DATASETS/RUN_MATRIX/과거 PQ-model reuse는
새 모드에 적용하지 않는다고 명시한다. 03의 모델·fit 설정·partition seeds·job/thread/메모리 제한은 적용한다.
과거 사용자 변경이 있던 batch/준비 노트북은 필요한 분기만 수정하고 다른 설정을 보존한다.

## 저장·재실행 계약

신규 결과는 `results/calibration/lfw_blufr_based/`에 저장한다. 입력/코덱/assignment는 `inputs.sqlite3`,
상세 보정 모델·paired 비교·interaction·진단은 설정별 `campaign-*.sqlite3`의 transaction 단위로 보존한다.
입력 출처/hash, 코드 hash, runtime, 설정이 같을 때만 재사용한다. 기존 완료 source를 덮어쓰지 않는다.
중단 시 완료 job을 보존하고 같은 설정의 재실행으로 이어간다. RAM 점검은 단계 사이의 점검이며 강제 OS 상한이 아니다.
완료 보고서는 요약 Parquet ZIP+manifest, 채팅용은 CSV ZIP+manifest로 제한한다.
채팅 표는 모델/trial/비율/profile/method/target별로 seed 범위를 요약하며 비율이나 trial을 합치지 않는다.
각 snapshot의 완료/전체 작업 수를 표시한다. 세부 fitted model과 paired CI는 SQLite에 있다.

호환 FR/FIQA를 재사용할 수 있어도 기존 분할의 PQ codebook·검색 점수·threshold는 다시 계산해야 한다.
Python 변경 후 노트북은 반드시 커널 재시작 후 실행한다.

## 검증 기준과 미해결 사항

- 공개 70 trial/비율 조합의 exact 목록·순서 보존, train=1,500명, test gallery=1,000명, cal gallery=100명,
  개발 이미지 최소 256장, identity 비중첩과 nested allocation을 검증한다.
- 합성 데이터에서 실제 Faiss PQ fit/ADC→기존 FIQA 보정을 실행하고, test score 변경이 fitted model에
  영향을 주지 않음을 검증한다. 입력 부족 시 파일 생성 전 중단, SQLite 재개/무재계산, 비율별 CSV 보존도 검증한다.
- 노트북 AST/schema 및 새 커널 순차 실행을 확인한다. 기존 benchmark 회귀 테스트도 유지한다.
- 현재 명시적 실제 source 네 모델은 13,233장 중 각각 임베딩/FIQA 38장이 부족하다. 공개 목록 자체는 대응한다.
  자동 제외하지 않고 `ready=False`로 실행을 차단한다. 누락 복구용 새 전처리/FR/FIQA artifact 연결이 남아 있다.
- 전체 GPU 추론, 5,600 jobs의 실제 성능 실험, DB 실험은 실행하지 않았다.
- 공개 목록은 고정 hash의 toolkit mirror다. 저자 인증 byte equality와 FR 학습 identity overlap은 미확인이다.
- 같은 trial의 일곱 비율은 동일 test를 공유하고 trial/seed도 겹친다. 이들을 독립 반복으로 간주하지 않는다.
  test 성능을 보고 비율을 고르면 탐색 결과로 구분하며 사전 고정/별도 검증 없이 확정 성능으로 주장하지 않는다.
- 기존 LFW의 97.90% 반복이나 FPIR 전이 문제가 해결됐다는 성능 주장은 아직 할 수 없다.
