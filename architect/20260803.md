### 변경 배경

`notebooks/common/orchestration/00_batch_experiment_runner.ipynb`는 공통 Step 4 dispatcher를 호출할 수 있었지만 한 번에 한 데이터셋만 실행했다. 또한 2026-08-02에 추가된 PCA direct/reconstruction, PQ reconstruction/ADC 파생 평가와 SurvFace faithfulness, `notebooks/common/reports/00_cross_dataset_results.ipynb` 생성은 자동으로 이어지지 않았다. 저장된 과거 실행 출력과 `EXECUTE=True`, `START_NEW_RUN=True`도 남아 있어 재실행 시 불필요한 독립 run을 만들 위험이 있었다.

### 결정 내용

1. 공통 batch notebook은 `DATASET_IDS=("lfw", "survface")`처럼 한 개 또는 여러 데이터셋을 선택하고, 하나의 검증된 FR checkpoint로 데이터셋별 plan/preflight/run을 순차 실행한다.
2. `START_NEW_RUN=False`를 기본값으로 하여 동일 plan의 완료 run을 우선 재사용한다. 실제 실행은 계속 `EXECUTE=True`와 `ACKNOWLEDGE_LOCAL_EXECUTION=True`의 이중 확인을 요구한다.
3. 완료 run 내부는 수정하지 않는다. `scripts/run_integrated_postprocessing.py`가 `COMPLETED`, run/freeze ID, fallback-free 상태를 확인하고 다음 파생 artifact를 연결한다.
   - `results/paper/<dataset>/<run_id>/search_space_v2/`
   - `results/paper/survface/<run_id>/faithfulness_v1/`
   - `results/paper/common/<model>/<selection>/`
4. 최종 report notebook은 모델명, dataset 목록, model UID, run ID를 외부 Python runner에서 주입받을 수 있다. 직접 노트북을 열어 기존 기본값과 dropdown으로 실행하는 경로도 유지한다.
5. ArcFace/AdaFace/MagFace 3-model faithfulness artifact가 없으면 해당 표만 제외하고 공통 보고서는 계속 만든다. 하나의 선택 모델 실행이 다른 두 모델의 실험을 암묵적으로 시작하지 않는다.
6. source notebook의 execution count와 output은 저장하지 않는다. 실행된 report notebook은 메모리에서만 유지하고 compact CSV·PNG·manifest만 명시적 설정에 따라 기록한다.

## 05:03 KST — SurvFace 3,000-ID matched calibration 전환

- 작성일: 2026-08-03 KST
- 상태: **구현됨, protocol 단위 검증됨, 새 full 결과 미산출**
- 작업 브랜치: `step6`
- 이전 결정과의 관계:
  - `architect/20260802.md`의 SurvFace origin FPIR incident P0 판정을 유지한다.
  - 기존 200-ID/단일 enrollment calibration을 논문 주 protocol에서 폐기한다.
  - 2026-08-03 04:24의 통합 runner 결정은 유지하되, SurvFace 파생 search-space의 우선 경로를 `search_space_v3_matched_calibration`으로 올린다.

### 변경 배경

기존 origin threshold는 training-derived calibration gallery 200명과 identity당 1장 enrollment에서 산정된 반면, 공식 test는 3,000-ID multi-image mean gallery였다. MagFace 완료 run에서 target FPIR 0.10, threshold 0.686036에 대해 test origin FPIR 0.506662가 관찰됐고, matched-sweep 진단은 gallery/template 체계 불일치가 주원인임을 보였다. 따라서 calibration과 test의 watch-list 크기와 template 집계 규칙을 맞추지 않은 threshold-dependent 결과는 최종 결과로 사용할 수 없다.

### 결정 내용

1. SurvFace 공식 `training_set`의 5,319 identities만 calibration source로 사용한다.
2. seed 42의 stable SHA-256 순서로 3,000 identities를 한 번 선택한다.
3. 선택 identity별 이미지를 stable 순서로 정렬하고 `floor(n/2)`를 gallery source, 나머지를 registered probe로 둔다.
4. 선택되지 않은 2,319 identities의 모든 이미지를 non-mated probe로 둔다.
5. gallery template은 calibration과 official test 모두 identity별 embedding 평균 후 L2 정규화한다.
6. 각 non-mated probe와 전체 gallery template 사이의 최대 impostor cosine을 구하고, 이 분포만으로 target FPIR threshold를 선택한다. Mated score나 DIR은 threshold 선택에 사용하지 않는다.
7. PCA/PQ fit에는 calibration watch-list의 gallery enrollment 이미지만 사용하며 registered/non-mated와 official test는 제외한다.
8. frozen-origin과 compressed별 recalibration을 계속 분리한다. PQ reconstruction cosine과 ADC도 별도 결과로 유지한다.
9. 기존 완료 run과 결과는 수정하지 않는다. 새 evaluator 결과는 `results/paper/survface/<run_id>/search_space_v3_matched_calibration/`에 파생한다.
10. 구형 compressor fit이 존재하는 완료 run을 새 정책의 fit으로 조용히 재사용하지 않고 새 run을 요구한다.

### 검증된 실제 분할

`data/interim/survface/training_manifest.csv`에서 seed 42로 다음 수량을 확인했다.

| 역할 | identity 수 | 이미지/probe 수 |
|---|---:|---:|
| training source | 5,319 | 220,888 |
| calibration gallery source | 3,000 | 60,892 |
| calibration registered probe | 3,000 | 62,041 |
| calibration non-mated probe | 2,319 | 97,955 |
| official test gallery | 3,000 | 60,294 |
| official test registered probe | 3,000 | 60,423 |
| official test unknown probe | 121,736 identities | 121,736 |

이는 gallery identity 수와 half-gallery/mean-template 원칙을 calibration과 test에 맞춘다. 단, training과 test의 촬영 분포 차이까지 제거하는 것은 아니므로 새 test FPIR은 실제 실행으로 확인해야 한다.

### 데이터·모듈 흐름

```text
training_manifest (5,319 IDs)
  -> stable identity selection (seed 42)
  -> selected 3,000 IDs
       -> floor(n/2) images -> mean + L2 -> calibration gallery templates
       -> remaining images -> registered calibration probes
  -> remaining 2,319 IDs/all images -> non-mated probes
  -> probe별 max impostor cosine
  -> non-mated-only threshold @ target FPIR
  -> threshold freeze

official test manifest
  -> official 3,000-ID mean + L2 gallery templates
  -> registered + unknown probes
  -> frozen threshold DIR/FPIR
  -> compressed별 recalibrated threshold DIR/FPIR (별도 정책)
```

- 기존 `search_space_v2`와 v3를 혼합하지 않는다. report는 검증된 v3가 있을 때만 v3를 우선하고, 없으면 구형 결과임을 명시한다.

## 05:37 KST — multi-search-mode saliency streaming grain 수정

### 장애와 원인

공통 batch notebook은 모델/checkpoint/CUDA 단계와 Step 4 phase 00–04를 정상 완료했다. phase 05 `saliency_compression_join`에서 `retrieval_sensitivity rows are not unique` 오류가 발생했다.

Step 2 retrieval 결과는 같은 compression profile과 threshold policy 아래에서 PCA direct/reconstruction 또는 PQ reconstruction/ADC처럼 여러 `search_mode`를 갖는다. In-memory join은 이미 `search_mode`를 grain에 포함했지만 streaming join은 이를 누락하여 서로 다른 검색 공간을 중복 row로 오판했다.

실패 CSV 75,740행을 직접 검사한 결과 기존 키로는 64,920행이 duplicate group에 포함됐으나 `search_mode`를 추가하면 duplicate는 0행이었다.

### 결정과 구현

1. streaming retrieval join의 uniqueness key와 association projection group에 `search_mode`를 포함한다.
2. search mode가 없는 legacy artifact는 기존 optional-column 동작을 유지한다.
3. 서로 다른 search mode를 합치지 않는 streaming regression test를 추가한다.
4. 이 정확한 phase 05 실패는 source fix 후에도 기존 phase 00–04를 불변으로 유지하고 frozen config로 phase 05 A002부터 재개할 수 있는 명시적 correction으로 기록한다.
5. 다른 실패 메시지, 다른 config 변경 또는 phase 00–04 미완료 run에는 correction을 허용하지 않는다.

### 영향받는 코드와 artifact

- `research/evaluation/saliency_streaming.py`
- `research/experiments/pipeline_runner.py`
- `tests/research/test_saliency_streaming.py`

### 두 번째 오류의 판정

이전 phase 05 A001 오류는 수정 후 A002에서 해결됐다. phase 06까지 완료되어 `COMPLETED`와 `run_manifest.status=completed`가 존재하며 LFW `search_space_v2`의 PCA/PQ family manifest도 검증됐다.

두 번째 `preflight 실패: {'git_policy_satisfied': False}`는 연구 계산 실패가 아니다. 첫 dataset의 정상 완료 과정에서 다음 runtime artifact가 생성·갱신되어 다음 dataset의 source-code clean gate에 포함된 orchestration 오류다.

- tracked `runs/.../run_manifest.json`, `logs/events.jsonl`
- untracked `runs/.../COMPLETED`, figure 및 phase artifact
- `results/paper/lfw/.../search_space_v2`

### 결정

1. canonical `runs/`와 `results/`는 source-code provenance와 artifact provenance를 분리한다.
2. 해당 root의 tracked 변경과 untracked 생성물은 source dirty 판정에서 제외하되 별도의 ignored artifact path 목록에 기록한다.
3. notebook source, config, Python 코드 등 artifact root 밖의 변경은 계속 fail-closed로 차단한다.
4. source diff hash는 artifact diff를 제외한 실제 source path만으로 계산한다.
