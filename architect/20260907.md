# 2026-09-07 Architecture 변경 기록

## FIQA TPIR20 정답 점수 계약 v2 및 구형 산출물의 비파괴 전환

- 작성일: 2026-09-07 (KST)
- 상태: 구현됨·검증됨. 단위/회귀, 실제 S/L 입력의 임시 artifact round-trip, 기본 노트북 top-to-bottom 검증 완료. 정식 결과 디렉터리의 v2 산출물 생성은 미실행.
- 대상: step11, 수정 전 HEAD `6998ec3f0f5c26f21387b3ca7518cb0a5c781fe8`.
- 이전 결정: `architect/20260902.md`의 calibration-only threshold fitting, identity 분할, immutable run, saliency gate를 유지한다. `architect/20260903.md`의 ADC 최소 frame에서 정답 점수/순위를 누락했던 계약을 보완하고, v1 결과의 무조건 재사용은 폐기한다.
- 감사 근거: `novelty/17.md`의 TPIR20 정의 불일치. 기존 보고서의 수치 해석이 아니라 본 문서의 v2 코드 계약이 수정 후 기준이다.

### 변경 배경

기존 FIQA 평가는 `top1_score >= threshold AND top_k_correct`를 TPIR로 집계했다. 잘못된 identity의 Top-1 점수만 threshold를 넘고 정답 점수는 미달인 경우가 성공으로 계산될 수 있었다. FPIR는 non-mated 최고 점수로 계산해야 하지만 TPIR@K는 정답 점수 자체로 판정해야 한다.

### 결정 내용

1. FPIR 및 threshold fitting의 `score`는 기존과 동일하게 compressed Top-1 maximum이다. 보정 알고리즘과 threshold 선택 규칙을 바꾸지 않는다.
2. TPIR@K는 `is_mated AND true_identity_rank <= top_k AND true_identity_score >= applied_threshold`로 계산한다. 정답이 검색되지 않았거나 non-mated이면 정답 rank/score의 NaN 쌍을 허용하며 성공으로 세지 않는다.
3. `validate_identification_scores()`로 정답 rank/score 누락, Inf, 잘못된 rank, Top-K correctness 불일치, non-mated 정답 정보, 최대 점수보다 큰 정답 점수, 잘못된 boolean을 거부한다. Top-1 점수로 정답 점수를 추정하는 fallback은 없다.
4. 새 ADC replay는 identity가 처음 등장하는 rank와 해당 ADC 점수를 보존한다. 중복 identity가 있을 때 첫 일치 위치를 사용하고, gallery에는 있지만 Top-K에 없는 identity는 mated rank miss로 유지한다.
5. condition/comparison artifact schema를 2로 올리고 `metric_contract=genuine-score-topk-v2`를 UID 입력과 manifest에 기록한다. summary 및 paired 비교에도 계약을 기록한다. 기존 v1 comparison/condition은 일반 loader와 비교 진입점에서 거부한다.
6. 별도 `upgrade_condition_score_artifact()`만 명시적으로 선택한 v1 condition을 읽을 수 있다. v1 parquet 해시·run/freeze hash·test core hash를 검증한 뒤, cached calibration maxima는 그대로 재사용하고 test ledger에서 정답 점수/순위를 복원한다. 기존 test 열 전체가 ledger와 정확히 일치해야 한다. calibration의 정답 점수는 보정에 필요 없으므로 만들거나 추정하지 않는다.
7. 전환 함수는 메모리 객체만 반환한다. 저장은 별도 writer 호출이며 기본 덮어쓰기를 허용하지 않는다. 새 test score frame과 기존 calibration score frame을 결합한 v2에는 전환 출처와 calibration genuine-score 미포함 상태를 명시한다.
8. FIQA 노트북 C는 v2가 없고 명시적 RUN/WRITE가 켜졌을 때 검증된 v1 전환을 우선한다. v1이 없다면 기존 frozen-codec ADC replay 경로를 사용한다. 두 경로 모두 기존 완료 run·FIQA score 파일을 수정하지 않는다.
9. D의 결과 경로에는 metric version과 partition seed를 포함한다. 재사용 시 source manifest canonical hash, condition/FIQA UID, score space, target FPIR 목록, quality/shrinkage/minimum 설정, safety fraction/seed를 대조한다. S/L에 동일 seed와 설정을 사용한다.
10. 기존 query-level paired CI 계산법은 유지한다. `resampling_unit=query`, `threshold_uncertainty_included=False`, `multiple_comparison_adjustment=none`을 명시해 고정 threshold의 탐색적 CI를 더 강한 통계적 확증으로 오해하지 않게 한다.
11. calibration saliency coverage 및 faithfulness gate는 유지한다. v2 condition이 없는 기본 실행에서는 readiness를 대기/차단 상태로 두며 보정을 활성화하지 않는다.

### 데이터·모듈 흐름

```text
명시적 v1 condition + 선택한 completed run
  -> parquet/run/freeze/core SHA 검증
  -> cached calibration maxima 그대로 재사용
  -> test core genuine score/rank 복원 + 기존 모든 test 열 정확 일치 확인
  -> v2 condition (메모리; 쓰기는 별도)
  -> 기존 FIQA S/L score와 해시 검증 후 결합
  -> 동일 seed의 calibration-only Global/FIQA threshold
  -> non-mated maximum 기반 FPIR / genuine-score 기반 TPIR20
  -> v2 summary, paired CI, threshold, manifest
```

### 검증 내용

- 관련 pytest 79개 통과(conditional/FIQA/notebook/compression/gallery-size/CR-FIQA/faithfulness/Git artifact visibility), 변경 Python 파일 Ruff 검사 통과.
- Top-1만 threshold를 넘는 오인 성공을 배제하고, 정답 점수가 threshold와 같은 경우 및 rank=20 경계를 올바르게 처리한다.
- 정답 점수만 낮춰도 threshold와 FPIR는 유지되고 TPIR count와 paired count만 변경되는 것을 검증한다.
- v1 일반 loader 거부, v1→v2 전환 후 원본 해시 불변, cached test maximum 변조 시 거부를 검증한다.
- 노트북의 이전 seed·shrinkage 설정·source hash가 현재 설정과 다르면 재사용을 거부한다.
- 실제 ArcFace/SurvFace run `20260902-R001-61915edf`에서 calibration 160,408행, test 182,159행의 전환을 검증했다. test에서 정답 점수가 존재하는 9,745행을 복원했다. 이 수는 TPIR 성공 수가 아니라 정답이 저장된 Top-K에 존재하는 행 수다.
- 실제 CR-FIQA S/L 두 종류를 동일 partition seed 8972로 검증했다. 각 5개 target FPIR의 `global_empirical` TPIR20 count가 기존 `apply_retrieval_thresholds()`와 정확히 일치했다. canonical adapter의 반환 스키마에만 필요한 nested Top-K 목록은 진단용 null 열로 보충했으며 점수·rank·label은 변경하지 않았다.
- FIQA-L의 모든 기존 최종 threshold와 새 threshold가 정확히 같았다. 따라서 수정이 threshold relaxation으로 인한 수치 변화가 아님을 확인했다.
- 실제 입력 기반 v2 condition/comparison write-load round-trip은 OS 임시 디렉터리에서 수행하고 검증 후 임시 산출물만 정리했다. 정식 results 디렉터리는 변경하지 않았다.
- 노트북은 기본 설정으로 처음부터 끝까지 실행 완료했다. 저장된 notebook은 output-free이며 실행/쓰기 플래그는 False다.

### 사용자가 결과를 재생성하는 범위

1. FIQA 노트북 커널을 재시작하고 처음부터 실행한다. FIQA inference 관련 RUN/WRITE는 False로 두어 기존 score를 읽는다.
2. `RUN_SCORE_REPLAY=True`, `WRITE_SCORE_ARTIFACT=True`로 C를 실행한다. v1이 있으면 검색 재실행 없이 검증/전환한다.
3. `RUN_THRESHOLD_CALIBRATION=True`, `WRITE_CALIBRATION_ARTIFACT=True`로 D를 실행한다. `OVERWRITE_OUTPUTS=False`를 유지한다.
4. S/L 모두 동일한 `PARTITION_SEED`(현재 기본 8972) 및 보정 설정으로 실행한다. 다른 seed의 기존 결과와 단순 S/L 우열 비교를 하지 않는다.
5. 새 경로:
   - condition: 기존 profile/search-mode 디렉터리 아래 `genuine-score-topk-v2/`
   - comparison: 기존 profile/search-mode 디렉터리 아래 `genuine-score-topk-v2/partition-8972/`

얼굴 정렬·embedding 추출·FIQA inference·Grad-CAM·PQ fitting·ADC search는 호환되는 v1과 ledger가 존재하는 이번 전환에 필요하지 않다. 새 실험 cohort나 codec을 선택했거나 원본 파일이 누락/변조된 경우에는 전환을 강행하지 않고 중단한다.
